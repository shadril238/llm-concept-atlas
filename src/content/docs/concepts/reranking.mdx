## Definition and intuition

Reranking jointly scores a query and each shortlisted candidate, then changes their order. It spends extra computation on a small candidate set and cannot recover a document that the first-stage retriever never supplied.

Read this lesson as a sequence: identify the input, follow the transformation, inspect the result, and explain a failure. The worked example and recorded lab below make those boundaries visible.

## How it works

### Joint scoring differs from reusable embeddings

A bi-encoder creates separate reusable vectors. A cross-encoder processes the query and passage together, allowing token interactions specific to that pair. L12 uses an actual pinned MS MARCO MiniLM pair scorer, with a declared input cap and raw scalar logits. These logits order candidates; they are not assumed to be calibrated probabilities or restricted to the book example’s provider score scale.

### Keep the candidate ceiling visible

The reranker receives the top six dense candidate chunks. It reorders those exact IDs. Because overlaps can consume candidate slots, six chunks may represent fewer than six documents. The explorer shows candidate values and collapses documents before metric calculation. If an important source is absent from the shortlist, changing only the reranker cannot add it.

### Compare the right interventions

L12 holds the corpus, queries, judgments, encoder, and chunk policy fixed for dense versus reranked comparison. The separate word-window experiment changes chunking and is labeled accordingly. Individual improved ranks and the small held-out MAP describe this configured system. They do not establish that every reranker improves every domain or that scores from BM25, cosine, and pair logits can be averaged without a declared fusion rule.

## Worked example

For a maintenance-extension question, several candidates mention rooms or telephone numbers. A useful reranker should promote the document matching the requested team, not any document containing a plausible extension. Inspect the shortlist before interpreting its reordered results. A high-quality pair scorer cannot fix a missing team-contact source outside its candidate set.

## Implement it

From the repository root, run `python3 scripts/run-examples.py --id e6-reranking --offline` after installing the foundation environment. This standard-library example calculates the stated mechanism or replays hash-linked actual model evidence from the published snapshot. It does not perform a fresh neural-model inference. The complete local/CI implementation and execution contract are linked immediately below.

{/* example:e6-reranking:start */}

```python
import json
from pathlib import Path
data = json.loads(Path('src/data/retrieval-results.json').read_text())
for method in ['dense','reranked']:
    row = next(r for r in data['retrieval']['rows'] if r['id']=='eval-hop' and r['method']==method)
    print(method,[(h['id'],round(h['score'],3)) for h in row['hits'][:3]])
print('Pair scores are raw logits; only six dense candidate chunks are reranked.')
```

## When to use it

Use reranking when the first stage can cheaply obtain a reasonably complete shortlist and higher relevance near the top is worth extra pair evaluations. Measure candidate recall and final ranking quality separately.

## Limits and common mistakes

Pair scoring adds work for every candidate. Truncating long pairs can hide evidence, and a good logit does not validate a generated claim. This lab reports one CPU configuration and no independent speed or calibrated-confidence claim.

<summary>Can reranking recover a source outside the six supplied chunks?</summary>

<details>
<summary>Why not interpret a raw logit of 4 as a 400% probability?</summary>

A logit is an unbounded scoring value. Ranking and calibrated probabilities require different contracts.
