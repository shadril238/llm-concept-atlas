## Definition and intuition

Few-shot examples are a small set of demonstrations placed in a prompt to clarify a desired pattern.

Chapter 6 treats a prompt as a task specification. A prompt can guide output, but it does not change model weights or guarantee that an answer is correct.

## Before you start

Read [In-context learning](/llm-concept-atlas/concepts/in-context-learning/) first. You should be able to explain what information its output carries. Then return here and ask what extra problem **few-shot examples** solves. This sequence matters because a plausible output can hide a missing prerequisite or a weak input representation.

## Theory: how it works

1. **Prepare:** Choose diverse, correctly labeled examples that cover common boundaries
2. **Transform:** Keep formatting and label spelling consistent
3. **Inspect:** Test on held-out cases and remove misleading demonstrations.

### The important distinction

Include examples that cover the decision boundary, not just easy positive cases. A balanced prompt can show both valid and invalid outputs, but mislabeled examples are especially damaging because the model may imitate them. Measure several prompt variants on the same held-out set before settling on one.

## Worked example

A prompt shows one refund request and one delivery complaint before a new ticket. Adding a borderline case may clarify whether “late refund” belongs to billing or shipping. Walk through the three stages above with that input: identify what is prepared, what changes, and which observation would show success. Then change one condition in the example. If the conclusion changes, the method is sensitive to that choice; if it does not, ask whether the example actually tests the mechanism.

## Implement it

**Setup:** Python 3; no packages or API key are needed. Save the following as `example.py` and run `python3 example.py`. It is a small deterministic illustration of the relevant calculation or data flow. It does not download a trained model.

```python
instruction = "Return one label: positive or negative."
example = "Text: I loved it. Label: positive"
query = "Text: The ending was dull. Label:"
prompt = "\n".join([instruction, example, query])
print(prompt)
```

**Expected output:**

```text
Return one label: positive or negative.
Text: I loved it. Label: positive
Text: The ending was dull. Label:
```

**What the code shows:** The final string contains the instruction, demonstration, and new query in that order. Inspect the rendered string before sending it to a real generator. The [official chapter 6 notebook](https://github.com/HandsOnLLM/Hands-On-Large-Language-Models/tree/main/chapter06) develops the corresponding model-based implementation.

## When to use it

Use them when instructions alone leave ambiguity or output format needs demonstration. Choose it when the input and output in your application match those assumptions. Compare the simplest useful baseline first, then measure whether the additional complexity improves the metric that matters to readers or users. Record the model, data version, and decision threshold when applicable so results can be reproduced.

## Limits and common mistakes

- More examples consume context and can bias the model toward their narrow wording.
- **Failure to look for:** All examples come from one product line, and the model performs poorly on other products.

A teaching demo usually holds data and model behavior fixed so one mechanism is visible. Real systems face noisy inputs, changing distributions, and edge cases. Test examples that should fail as well as examples that should succeed, and inspect the intermediate stage that causes the error.
