## Definition and intuition

Query routing selects an appropriate source or retrieval path before searching. Its source labels, decision rule, invalid-output behavior, and cross-source questions determine whether it preserves the required evidence.

Read this lesson as a sequence: identify the input, follow the transformation, inspect the result, and explain a failure. The worked example and recorded lab below make those boundaries visible.

## How it works

### Declare the available sources

The fixture separates library, rooms, and operations collections. A routing prompt supplies these names and design-only examples. The actual model output is parsed against that finite set. This is a small source-selection mechanism, not a claim that a label word establishes reliable domain classification.

### Invalid choices and fallbacks are behavior

L13 records whether the generated route is valid. Invalid text explicitly falls back to searching all collections. A successful answer after fallback is not evidence that routing worked. The selected collection and actual returned IDs appear in the trace, so readers can distinguish a genuine restricted search from baseline behavior.

### Some questions span sources

Room capacity may belong in rooms, but the maintenance extension requires an operations contact after a room relationship. A single-source router can remove necessary evidence. Multi-source routing or a bounded follow-up controller may be more appropriate, but its extra work and mistakes need separate evaluation. The same design-selected answerability threshold is reused and is not a calibrated route-specific decision boundary.

## Worked example

The question “What extension reaches the team maintaining Wren?” crosses a room guide and a maintenance-contact source. Routing to rooms alone might retain the team name but lose the number. Routing to operations alone might return several numbers without the room relationship. Inspect the actual route and support coverage before accepting its final draft.

## When to use it

Use routing when collections have meaningful boundaries, distinct permissions or schemas, or specialized retrieval methods. Include cross-source and out-of-domain questions in validation rather than testing only obvious single-source requests.

## Limits and common mistakes

A wrong route can hide all useful evidence. A fallback can obscure poor classifier behavior unless it is reported. The atlas sources are public fictional fixtures; it does not implement authorization rules or infer that a routing prompt enforces access control.

## Check your understanding

<details>
<summary>Does a correct answer after an invalid-route fallback prove routing success?</summary>

No. It may have succeeded through all-collection baseline search. The route-valid flag and executed filter must be inspected.

</details>

<details>
<summary>When can a single-source route be structurally insufficient?</summary>

When the required relationship or evidence spans collections, such as room ownership and a separate team contact.

</details>
