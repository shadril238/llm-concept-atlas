## Definition and intuition

Model access is the operational route by which software uses a model: a hosted interface/API, a downloaded local artifact, or a deployment you control. Access, licensing, and openness describe different properties.

A student has a laptop and wants to reproduce a generation example without entering an API key. A team with confidential documents has a different set of requirements. Both need to know where computation and data actually go.

## How it works

A model hub stores artifacts and metadata; an inference library loads and executes a supported architecture; a workflow framework connects components such as retrieval and generation. These roles can coexist, but installing a framework does not download a trained model or provide compute by itself.

Downloadable weights provide local access subject to their license. They do not necessarily include the training corpus, preprocessing, training code, or enough resources to reproduce training. “Open weights” and fully open development are therefore not synonyms.

Hosted access can reduce local hardware requirements, while introducing provider-specific authentication, availability, versioning, data handling, and usage accounting. Local access gives direct artifact control but makes installation, memory, updates, and service operation your responsibility. A browser interface and an API can expose the same remote model through different contracts.

### The important distinction

A local model can exceed RAM even if its download is small: weights, activations, temporary tensors, and cache all consume memory.

### Access decision table

| Need | Starting route | What to verify |
| --- | --- | --- |
| Reproduce a small lesson offline | Pinned CPU artifact + local inference | Cache contents, environment, model/tokenizer pair |
| No local compute for a larger workload | Hosted API or managed runtime | Service version, data path, usage limits, task results |
| Customize and control deployment | Downloadable weights | Model license, memory, architecture support, operations |
| Reproduce training research | Open training resources plus compute | Data access, code, configuration, budget, evaluation |

These are operational tradeoffs, not rankings of current providers. Product capabilities and terms change; use the provider's current primary documentation when implementing a hosted route.

Run the small mechanism from the repository root with `python3 scripts/run-examples.py --id foundation-model-access`. Its values are illustrative; it isolates the stated operation rather than pretending to load a trained model.

weights = 14_000_000

## When to use it

Choose through a table of task quality, supported hardware, model/data license, data path, reproducibility, and operational effort. The default atlas route is local and account-free. Hosted API work is optional; this phase does not provision credentials or make paid requests.

## Limits and common mistakes

A local model can exceed RAM even if its download is small: weights, activations, temporary tensors, and cache all consume memory. A model file’s license can differ from the repository code license. A pinned name without a revision can still resolve to changed artifacts.
