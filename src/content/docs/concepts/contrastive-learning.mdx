## Definition and intuition

Contrastive learning trains representations by rewarding closeness for positives and separation from negatives.

Chapter 10 trains representations by choosing which examples should be close or far apart. The construction of positive and negative pairs is part of the learning objective.

## Before you start

Read [Text Embedding](/llm-concept-atlas/concepts/text-embedding/) first. You should be able to explain what information its output carries. Then return here and ask what extra problem **contrastive learning** solves. This sequence matters because a plausible output can hide a missing prerequisite or a weak input representation.

## Theory: how it works

1. **Prepare:** Define what counts as a positive pair for the application
2. **Transform:** Encode a batch and compare similarities across pairs
3. **Inspect:** Optimize a loss that ranks positives above negatives and evaluate retrieval.

### The important distinction

For an anchor, the loss often compares one positive score with several negative scores through a temperature-scaled softmax. The resulting gradient reshapes the encoder so similar examples occupy nearby regions. Hard negatives sharpen the task boundary, but mislabeled hard negatives can do disproportionate damage.

## Worked example

A question and its answering passage are a positive pair. A passage on the same broad topic but without the answer is a hard negative that teaches a finer distinction. Walk through the three stages above with that input: identify what is prepared, what changes, and which observation would show success. Then change one condition in the example. If the conclusion changes, the method is sensitive to that choice; if it does not, ask whether the example actually tests the mechanism.

## Implement it

**Setup:** Python 3; no packages or API key are needed. Save the following as `example.py` and run `python3 example.py`. It is a small deterministic illustration of the relevant calculation or data flow. It does not download a trained model.

```python
from math import exp, log
positive_similarity = 0.8
negative_similarities = [0.2, 0.4]
all_scores = [positive_similarity, *negative_similarities]
loss = -log(exp(all_scores[0]) / sum(exp(x) for x in all_scores))
print(round(loss, 3))
```

**Expected output:**

```text
0.797
```

**What the code shows:** The positive score competes with two negative scores inside a softmax. The negative logarithm is smaller when the positive takes more of the probability mass. The [official chapter 10 notebook](https://github.com/HandsOnLLM/Hands-On-Large-Language-Models/tree/main/chapter10) develops the corresponding model-based implementation.

## Limits and common mistakes

- Pair quality and batch composition strongly affect learned geometry.
- **Failure to look for:** An unlabeled true match is treated as a negative and pushed away during training.

A teaching demo usually holds data and model behavior fixed so one mechanism is visible. Real systems face noisy inputs, changing distributions, and edge cases. Test examples that should fail as well as examples that should succeed, and inspect the intermediate stage that causes the error.
