## Definition and intuition

Contrastive learning shapes a representation using relationships between examples: which inputs should be compatible, and which alternatives should be distinguished. The relationship must match the intended task; same topic, same intent and same sentiment are different definitions of similarity.

Follow the input, objective, update, and evaluation as separate steps. The worked example and experiment below connect the explanation to an inspectable implementation.

## How it works

### The supervision lives in the relationship

A sentence encoder does not discover your product’s definition of relevance from a vector shape. In L15, two requests are positive when they ask for the same community service. “Reserve a room” and “cancel a room” are lexically close but have different intents. A sentiment dataset would create different pairs. State this policy before generating examples, and keep validation/test sentences outside pair construction.

### A competition creates a gradient

For one MNR anchor, candidate similarities s_j become logits s_j/T. Cross entropy is −log(exp(s_positive/T)/sum_j exp(s_j/T)). Its logit derivative is predicted probability minus the one-hot target. Increasing the positive logit lowers loss; increasing an unrelated alternative raises it. If an alternative is another valid positive, the same gradient teaches a false distinction. Lower temperature concentrates that competition.

### Verify the learned geometry

The actual library losses update a tiny pretrained BERT encoder rather than moving invented dots. Validation selects checkpoints, and held-out retrieval measures whether the learned relation transfers to unseen phrases. Two-dimensional projections illustrate changes but omit most of the 128-dimensional representation. Full-dimensional cosine scores drive the reported task metrics.

## Worked example

With positive similarity 0.8, alternative 0.4, and scale 5, logits are [4,2]. The target probability is about 0.881 and loss about 0.127. If the alternative expresses the same intent, this apparently clean target is wrong: optimization still pushes it away. Inspect the actual six-intent batch and the independent library arithmetic check before judging a falling curve.

```python
import sys
sys.path.insert(0, 'examples/foundations/src')
from atlas_foundations.e7.contracts import cross_entropy
scores = [0.8, 0.4]
scale = 5
logits = [scale * score for score in scores]
loss = cross_entropy(logits, 0)
from math import exp
probability = exp(-loss)
print('target probability:', round(probability, 4))
print('row loss:', round(loss, 4))
print('logit gradients:', [round(probability - 1, 4), round(1 - probability, 4)])
```

## When to use it

Use it for retrieval, sentence similarity, class-conditioned embeddings and recommendation when you can define trustworthy relationships. Evaluate on the downstream relation rather than assuming semantic similarity is universal.

## Limits and common mistakes

Pair leakage, false negatives and repeated templates can make the task deceptively easy. A larger batch adds useful alternatives only when they are valid negatives. Our original small corpus is a controlled teaching experiment, with recurring intent categories and unknown pretrained overlap, not a broad benchmark.

Author execution checks tensor/mask contracts, actual parameter updates, split provenance and artifact reload. It does not constitute independent lesson acceptance. Keep training quality, task quality, runtime and generalization claims separate.
