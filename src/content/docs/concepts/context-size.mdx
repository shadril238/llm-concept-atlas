## Definition and intuition

Context size is the maximum token span a model can condition on during a request or generation step.

Chapter 3 traces a transformer forward pass. Distinguish the computation performed for a fixed input from the repeated loop used to generate new tokens.

## Before you start

Read [Transformer](/llm-concept-atlas/concepts/transformer/) first. You should be able to explain what information its output carries. Then return here and ask what extra problem **context size** solves. This sequence matters because a plausible output can hide a missing prerequisite or a weak input representation.

## Theory: how it works

1. **Prepare:** Tokenize the prompt and any retrieved passages
2. **Transform:** Reserve room for generated tokens and check the model's limit
3. **Inspect:** Choose, summarize, or truncate material before inference.

### The important distinction

Context is measured after tokenization, and the generated continuation must fit alongside the prompt. A retrieval system should budget for instructions, the question, citations, and output tokens before selecting passages. A long-context model may accept a large prompt while still failing to use a critical middle passage reliably.

## Worked example

A 4,000-token request cannot fit into a 2,000-token context. Trimming the beginning might remove the instruction, while trimming the end might remove the evidence needed to answer. Walk through the three stages above with that input: identify what is prepared, what changes, and which observation would show success. Then change one condition in the example. If the conclusion changes, the method is sensitive to that choice; if it does not, ask whether the example actually tests the mechanism.

## Implement it

**Setup:** Python 3; no packages or API key are needed. Save the following as `example.py` and run `python3 example.py`. It is a small deterministic illustration of the relevant calculation or data flow. It does not download a trained model.

```python
tokens = ["The", "cat", "slept"]
position = 1
visible = tokens[:position + 1]
print("query token:", tokens[position], "visible context:", visible)
```

**Expected output:**

```text
query token: cat visible context: ['The', 'cat']
```

**What the code shows:** The slice keeps only tokens through the selected position. It illustrates a causal visibility rule or a context budget, not a complete transformer computation. The [official chapter 3 notebook](https://github.com/HandsOnLLM/Hands-On-Large-Language-Models/tree/main/chapter03) develops the corresponding model-based implementation.

## When to use it

Plan retrieval and conversation memory around token budgets, especially for long documents. Choose it when the input and output in your application match those assumptions. Compare the simplest useful baseline first, then measure whether the additional complexity improves the metric that matters to readers or users. Record the model, data version, and decision threshold when applicable so results can be reproduced.

## Limits and common mistakes

- A larger window does not guarantee equal use of every position or correct reasoning over all content.
- **Failure to look for:** An answer cites a passage that was actually truncated from the model input.

A teaching demo usually holds data and model behavior fixed so one mechanism is visible. Real systems face noisy inputs, changing distributions, and edge cases. Test examples that should fail as well as examples that should succeed, and inspect the intermediate stage that causes the error.
