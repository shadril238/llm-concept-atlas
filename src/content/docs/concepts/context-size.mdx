## Definition and intuition

Context size is the supported token budget for a model invocation or sequence-processing regime. It counts encoded positions, including task/template content, rather than visible words, and does not by itself establish reliable use of every position.

A document assistant must fit instructions, a question, retrieved passages, and room for its answer. Trimming only the document to the advertised maximum can leave no space for the rest of the request.

## How it works

Tokenize the final model-ready input with the paired tokenizer. For a decoder, distinguish input length from the maximum newly generated tokens. The effective supported total depends on the model and inference API contract; do not assume every service parameter has identical semantics.

Longer prefixes require more activation and cache memory. Dense attention also compares many query/key pairs during prefill. A model accepting an input length is a weaker claim than accurate retrieval or reasoning over the entire input.

Truncation is an application policy. Removing the beginning can delete an instruction; removing the end can cut an answer source or entity. Sliding windows and document chunking preserve different information and need explicit source-offset/evaluation handling.

### The important distinction

A longer supported context does not mean perfect memory.

## Worked example

With a 128-position teaching limit, 90 encoded passage tokens, 15 instruction/question tokens, and 2 markers leave 21 positions for output under a total-budget contract. A 30-token answer request would exceed that budget. These are invented counts; the real tokenizer determines the actual values.

## When to use it

Choose a context policy through token measurements, memory limits, source coverage, and task evaluation. Use retrieval or summarization when the full corpus does not fit, while checking whether relevant evidence was lost. For independent documents, see sequence packing and its boundary masks.

## Limits and common mistakes

A longer supported context does not mean perfect memory. A KV cache accelerates repeated prefixes but still grows with retained positions. Tokenizer differences can change the budget even when word counts match.
