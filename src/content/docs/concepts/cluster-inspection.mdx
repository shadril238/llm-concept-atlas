## Definition and intuition

Cluster inspection connects fitted groups back to source documents, representative examples, borderline cases, and visual summaries. It tests whether a convenient geometric grouping has a useful human interpretation.

A few representative titles can make a group look cleaner than it is. Inspection should deliberately include what the group excludes, what it wrongly absorbs, and which documents sit at the boundary between plausible interpretations.

## How it works

### Trace an individual row

The explorer links each source ID to its title, complete fictional summary, five-dimensional fitted coordinates, two-dimensional display point, baseline topic, changed-setting topic, and membership strength. Stable joins make this trace auditable. A representative-document list is a useful starting point, not a replacement for reading the rest of a group.

### Three views, three questions

Term bars show which words score highly under a representation convention. A similarity heatmap compares fitted topic vectors with cosine; it is not an accuracy matrix. The hierarchy uses average linkage on cosine distances between non-outlier baseline topic embeddings, with explicit leaf IDs and merge distances. It summarizes relationships and does not reassign documents. The two-dimensional map answers where an approximate layout placed the points, not whether a paper proves a claim.

### Inspect the failure evidence

In this recorded corpus, a topic called Summarization also contains original unrelated summaries, including garden irrigation or ceramic glazes. A high-diversity representation can surface words such as soil or temperatures. That may reveal contamination rather than improve the group. The noise group contains a cross-task bridge document; its rejection reflects this density configuration, not a judgment that cross-disciplinary work is invalid.

## Worked example

Suppose a topic’s three representatives all discuss summarization, while one of its seventeen members studies irrigation sensors. “Summarization” describes its majority, but calling every document a summarization study would be false. The code illustrates coverage inspection on invented tags; L08 computes assignments and representatives from actual embeddings and a fitted model.

## Implement it

This small mechanism uses Python’s standard library and illustrative values; it does not claim to run a pretrained model. Run `python3 scripts/run-examples.py --id discovery-cluster-inspection`. The connected workflow below supplies the actual model, data, and evaluation.

{/* example:discovery-cluster-inspection:start */}

```python
inspected = {
    "summary-1": "summarization",
    "summary-2": "summarization",
    "garden": "irrigation",
}
proposed_label = "summarization"
unsupported = [doc for doc, theme in inspected.items() if theme != proposed_label]
print("inspect minority documents:", unsupported)
assert unsupported == ["garden"]
```

## When to use it

Use cluster inspection before publishing a research collection browser, assigning human topic names, or creating training labels from clusters. Save examples of weak group members and compare the effect of one changed component at a time.

## Limits and common mistakes

Representative extraction and topic names can hide minority documents. A visually compact group may still be semantically mixed. Agreement between two parameter settings is evidence about partition stability, not a guarantee of usefulness or factual correctness.
