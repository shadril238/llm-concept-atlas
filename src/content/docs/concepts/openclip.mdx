## Definition and intuition

OpenCLIP is an open implementation and family of CLIP-style image-text encoders trained with contrastive objectives.

Chapter 9 connects images and language. A shared vector space supports matching, while a generation model needs an additional path from visual features to text tokens.

## Before you start

Read [CLIP](/llm-concept-atlas/concepts/clip/) first. You should be able to explain what information its output carries. Then return here and ask what extra problem **OpenCLIP** solves. This sequence matters because a plausible output can hide a missing prerequisite or a weak input representation.

## Theory: how it works

1. **Prepare:** Choose a documented model and its matching preprocessing transforms
2. **Transform:** Encode images and text into compatible normalized vectors
3. **Inspect:** Compare retrieval or zero-shot scores on the target data.

### The important distinction

OpenCLIP exposes multiple checkpoints with different data sources and architectures. Always use the matching tokenizer, image preprocessing, and model weights together. If vectors come from different checkpoints, they are not guaranteed to share coordinates even when their dimensions match.

## Worked example

Two OpenCLIP checkpoints can give different rankings for the same photo and labels. Preprocessing the photo with the wrong resize or normalization can also alter scores. Walk through the three stages above with that input: identify what is prepared, what changes, and which observation would show success. Then change one condition in the example. ## Implement it

**Setup:** Python 3; no packages or API key are needed. Save the following as `example.py` and run `python3 example.py`. It is a small deterministic illustration of the relevant calculation or data flow. It does not download a trained model.

```python
from math import sqrt
image = (0.8, 0.6)
captions = {"a dog": (0.7, 0.7), "a car": (-0.6, 0.8)}
score = lambda a,b: sum(x*y for x,y in zip(a,b)) / (sqrt(sum(x*x for x in a))*sqrt(sum(y*y for y in b)))
print(max(captions, key=lambda text: score(image, captions[text])))
```

**Expected output:**

```text
a dog
```

**What the code shows:** The toy image vector is compared with caption vectors using cosine similarity. The highest score wins among the offered candidates; no image pixels are processed. The [official chapter 9 notebook](https://github.com/HandsOnLLM/Hands-On-Large-Language-Models/tree/main/chapter09) develops the corresponding model-based implementation.

## Limits and common mistakes

- Checkpoints differ in data, licenses, preprocessing, and evaluation behavior.
- **Failure to look for:** Text vectors from one checkpoint are compared with image vectors from another, producing meaningless scores.

A teaching demo usually holds data and model behavior fixed so one mechanism is visible. Real systems face noisy inputs, changing distributions, and edge cases. Test examples that should fail as well as examples that should succeed, and inspect the intermediate stage that causes the error.
