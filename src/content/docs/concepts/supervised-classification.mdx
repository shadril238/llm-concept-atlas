## Definition and intuition

Supervised classification fits a decision rule using labeled training examples, chooses settings on validation data, and estimates performance on held-out cases. Evaluation must preserve the meaning of the labels and the denominator.

A score is meaningful only if you know which data influenced the model or its settings. A train/test split is not sufficient when you repeatedly inspect test results to choose a prompt, threshold, or regularization value. L07 records those roles separately and makes the final case list identical across methods.

## How it works

### What is actually fitted

The TF-IDF vocabulary/IDF and logistic head use the 200 training sentences. The embedding head uses frozen encoder outputs and those same training labels. C is chosen from [0.1,1,10] by validation macro-F1; ties prefer smaller C. No test result enters that choice. The test and challenge rows remain separate reports. Canonical exact text duplicates are removed before the split; absent reviewer IDs prevent a stronger reviewer-level independence claim.

### Evaluation and confusion matrices

The atlas matrix uses actual labels as rows and predictions as columns, with an explicit invalid column. For a class, precision = TP/(TP+FP), recall = TP/(TP+FN), and F1 = 2TP/(2TP+FP+FN). An invalid prediction is a false negative for its true class and an accuracy error. Macro-F1 averages the two class F1 values equally. Weighted-F1 weights by class support, so it does not generally give equal influence to minority classes. They can coincide on balanced data.

### Review thresholds and uncertainty

A confidence threshold routes low-score cases for review. Report coverage, the fraction accepted, alongside accuracy on accepted cases. If no cases are accepted, accepted accuracy is undefined rather than 100%. L07 selects an embedding-head threshold on validation only, maximizing coverage subject to at least 90% validation accuracy. Forty validation examples are too few to guarantee that constraint in deployment. The slider explores recorded test behavior and is not a license to tune on it.

## Worked example

For gold [0,0,1,1,1] and predictions [0,1,1,-1,1], actual rows are [1,1,0] and [0,2,1]. Accuracy is 3/5. Negative F1 is 2/3; positive F1 is 4/6; macro-F1 is 2/3. The invalid case lowers positive recall even though it is not assigned to a wrong valid class. Counting it out of the denominator would overstate quality.

## Implement it

This small mechanism uses Python’s standard library and illustrative values; it does not claim to run a pretrained model. Run `python3 scripts/run-examples.py --id discovery-supervised-classification`. The connected workflow below supplies the actual model, data, and evaluation.

{/* example:discovery-supervised-classification:start */}

```python
gold = [0, 0, 1, 1, 1]
predicted = [0, 1, 1, -1, 1]
confusion = [[0, 0, 0], [0, 0, 0]]
for actual, prediction in zip(gold, predicted):
    confusion[actual][prediction if prediction >= 0 else 2] += 1
print("actual rows; negative, positive, invalid columns:", confusion)
print("accuracy:", sum(a == p for a, p in zip(gold, predicted)) / len(gold))
```

## When to use it

Use supervised classification when label definitions are stable enough to annotate representative examples. Inspect per-class performance and concrete false positives/negatives before accepting an aggregate score. Save the fitted artifact and evaluate reload behavior before wiring an inference script into a workflow.

## Limits and common mistakes

A small balanced sample hides some class imbalance and rare-error issues. The book examples are educational; its reported weighted average must not be generalized into the claim that weighted-F1 always treats classes equally. Pretrained-model data contamination and domain drift require separate investigation.
