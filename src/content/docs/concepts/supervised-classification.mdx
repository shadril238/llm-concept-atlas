## Definition and intuition

Supervised classification learns a mapping from input texts to labels using labeled examples.

Chapter 4 compares classification with specialized encoders, reusable embeddings, and generators. Label definitions, labeled data, and evaluation examples determine which approach fits.

## Before you start

Read [Task-specific models](/llm-concept-atlas/concepts/task-specific-models/) first. You should be able to explain what information its output carries. Then return here and ask what extra problem **supervised classification** solves. This sequence matters because a plausible output can hide a missing prerequisite or a weak input representation.

## Theory: how it works

1. **Prepare:** Define a consistent annotation guide and split data before training
2. **Transform:** Fit a classifier by minimizing prediction error on training examples
3. **Inspect:** Evaluate on unseen cases with per-class metrics and error review.

### The important distinction

The label guide is part of the model specification. If annotators disagree about whether a message is billing or shipping, more optimization cannot resolve the ambiguity. Use disjoint train, validation, and test examples, and review a confusion matrix rather than relying on one accuracy number.

## Worked example

A dataset of 800 messages labeled refund or delivery can train a classifier. A held-out set reveals whether the model learned patterns beyond the examples it saw. Walk through the three stages above with that input: identify what is prepared, what changes, and which observation would show success. Then change one condition in the example. If the conclusion changes, the method is sensitive to that choice; if it does not, ask whether the example actually tests the mechanism.

## Implement it

**Setup:** Python 3; no packages or API key are needed. Save the following as `example.py` and run `python3 example.py`. It is a small deterministic illustration of the relevant calculation or data flow. It does not download a trained model.

```python
examples = ["a wonderful film", "a dull film"]
labels = ["positive", "negative"]
def classify(text):
    return "positive" if "wonderful" in text else "negative"
print([(text, classify(text)) for text in examples])
```

**Expected output:**

```text
[('a wonderful film', 'positive'), ('a dull film', 'negative')]
```

**What the code shows:** The function uses one word as a simple classification baseline. Change the rule or input text and compare the predicted label with the intended label. ## When to use it

Use it when a stable label taxonomy and representative annotated examples are available. Choose it when the input and output in your application match those assumptions. Compare the simplest useful baseline first, then measure whether the additional complexity improves the metric that matters to readers or users. Record the model, data version, and decision threshold when applicable so results can be reproduced.

## Limits and common mistakes

- Label leakage, class imbalance, and inconsistent annotation can make reported accuracy misleading.
- **Failure to look for:** The same customer message appears in train and test, inflating the score without improving generalization.

A teaching demo usually holds data and model behavior fixed so one mechanism is visible. Real systems face noisy inputs, changing distributions, and edge cases. Test examples that should fail as well as examples that should succeed, and inspect the intermediate stage that causes the error.
