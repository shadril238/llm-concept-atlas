## Definition and intuition

CLIP learns image and text representations from paired examples by making matching pairs more compatible than other pairs in a batch. Its two encoders support cross-modal retrieval; CLIP itself is not a text-answer generator.

## How it works

### A batch is a matching problem

For N paired images and captions, normalized image and text vectors produce an N×N cosine matrix. A learned positive logit scale multiplies those similarities. The diagonal entries correspond to the known pairings. Image-to-text cross entropy asks which caption matches each image; text-to-image cross entropy asks which image matches each caption. The symmetric objective averages both directions.

### What the negatives assume

Other items in the batch serve as negatives, even though some may be semantically related or near duplicates. That assumption affects training and explains why a valid description of more than one image can complicate the loss. L14 computes this objective from frozen real embeddings and checks it against PyTorch. Moving a loss slider recalculates arithmetic; it does not update the pretrained encoders.

### Inference and score interpretation

The actual OpenCLIP checkpoint uses an image class-token representation and a text end-of-text representation, projected into a shared space. Larger cosine indicates greater compatibility for that input pair, not a calibrated probability. Softmax produces relative scores among selected descriptions, and its result can change simply because another candidate was added or removed.

## Worked example

## Implement it

From the repository root, run `python3 scripts/run-examples.py --id e6-clip --offline` after installing the foundation environment. This standard-library example calculates the stated mechanism or replays hash-linked actual model evidence from the published snapshot. It does not perform a fresh neural-model inference. The complete local/CI implementation and execution contract are linked immediately below.

{/* example:e6-clip:start */}

```python
import json
from pathlib import Path
data = json.loads(Path('src/data/retrieval-results.json').read_text())
import sys
sys.path.insert(0, 'examples/foundations/src')
from atlas_foundations.e6.vision import contrastive_loss
v = data['vision']
logits = [[cosine*v['logit_scale'] for cosine in row[:3]] for row in v['cosines']]
loss = contrastive_loss(logits)
assert abs(loss['loss']-v['contrastive']['loss'])<1e-10
print({key:round(loss[key],6) for key in ['image_to_text','text_to_image','loss']})
print('No weights were updated.')
```

## When to use it

Use CLIP-style encoders for cross-modal search and candidate-description matching when text labels are available but a task-specific classification head is unnecessary. Evaluate prompt wording, domain coverage, and ambiguous descriptions.

## Limits and common mistakes

CLIP does not directly produce long grounded answers or guarantee fine-grained counting. A candidate-set probability is not object certainty. The corpus is tiny, familiar, and potentially present in pretraining, so no independent vision benchmark or training-improvement claim is made.

## Check your understanding

<details>
<summary>Why use both row and column cross entropy?</summary>

Each direction tests matching from a different modality and has its own normalization. The symmetric average trains paired compatibility in both directions.

</details>

<details>
<summary>Does changing the displayed logit scale retrain the encoder?</summary>

No. The browser recomputes loss from fixed recorded similarities. Training would require gradients, optimizer updates, and a new evaluation.
