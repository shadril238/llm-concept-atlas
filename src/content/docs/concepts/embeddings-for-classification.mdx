## Definition and intuition

Embedding classification separates a frozen text-to-vector encoder from a decision rule fitted or defined in vector space. The vector alone is not a class prediction.

The same sentence vector can support retrieval, clustering, or classification. Classification begins only when you introduce a rule linking that vector to a label. L07 makes three such rules explicit, so a cosine calculation is not mistaken for a trained classifier.

## How it works

### Frozen features and learned decisions

The pinned MiniLM encoder produces mask-aware mean-pooled, L2-normalized 384D vectors. A binary logistic head computes z = x·w + b, then sigmoid(z) for the positive class. Training changes w and b while the encoder stays frozen. The model’s feature geometry is reused, but the label boundary is learned from the 200 training examples.

### Class-average prototypes

For each class, average only its training vectors and normalize the mean. Predict the class whose mean has the largest cosine with the query. This uses class labels and is supervised even though no iterative optimizer fits a head. A mean can hide multiple subgroups, and equal treatment of the two means does not automatically model class prior probabilities.

### Descriptions are a third method

Encode a human-written description for each label and compare those vectors with the document. That rule uses label semantics rather than local labeled examples. It is zero-shot with respect to the local task examples, but the encoder was pretrained. Its cosine values are similarities; a score of 0.7 is not a 70% correctness claim.

## Worked example

With unit query [0.6,0.8], prototypes [1,0] and [0,1] give cosine scores 0.6 and 0.8, so the second class wins. A linear head with w=[2,-1] and b=0 instead gives z=0.4 and positive probability about 0.599. Both rules can use the same vector while producing different margins and responding differently to training data.

## Implement it

This small mechanism uses Python’s standard library and illustrative values; it does not claim to run a pretrained model. Run `python3 scripts/run-examples.py --id discovery-embeddings-for-classification`. The connected workflow below supplies the actual model, data, and evaluation.

{/* example:discovery-embeddings-for-classification:start */}

```python
from math import exp

query = [0.6, 0.8]
prototypes = [[1.0, 0.0], [0.0, 1.0]]
scores = [sum(a * b for a, b in zip(query, p)) for p in prototypes]
z = sum(a * b for a, b in zip(query, [2.0, -1.0]))
print("prototype scores:", scores)
print("linear-head positive probability:", round(1 / (1 + exp(-z)), 3))
```

## When to use it

Use fixed embeddings when you have a modest labeled set, can cache reusable features, and want a small trainable head. Compare prototypes as a simple supervised baseline. Retain IDs, label maps, encoder revision, pooling, and truncation settings when saving a head.

## Limits and common mistakes

An incompatible encoder or pooling change invalidates a saved head even if vector dimensions match. L07 verifies a portable JSON head by recomputing probabilities after reload; it does not claim that frozen vectors solve every domain or class imbalance problem.
