## Definition and intuition

A chain composes transformations so each stage receives a defined output from the previous stage. Model calls, parsers, and deterministic functions can all be stages, with explicit contracts and visible intermediate state.

Framework composition is useful when it clarifies dataflow. A short pipeline expression should not hide which fields are generated, validated, calculated, or copied. The plain-Python equivalent remains available as a reference.

## How it works

### Modern LangChain composition

The pinned workflow uses RunnableLambda, RunnablePassthrough.assign, ChatPromptTemplate, and StrOutputParser from langchain_core. It avoids removed or deprecated book-era chain imports. A Runnable is a composable invocation interface; it is not inherently an autonomous agent. The adapter ultimately calls the same native local runtime.

### Actual stage boundaries

The first model extracts an order. A deterministic stage validates it and computes a total using fixed item prices. A second model receives the actual intermediate object and calculated total. The resulting artifact contains both calls and independent checks for original extraction, supplied-total copying, and end-to-end answer quality.

### Failure propagation

A downstream stage can be internally consistent with an incorrect upstream value. Preserve the original task and intermediate provenance when grading. If a schema check fails, a declared error outcome is preferable to silently replacing missing fields. Adding retries, fallback models, or parallel branches changes the workflow and requires separate trace and work accounting.

## Worked example

Three requested pens at price two should total six. If extraction chooses eight, multiplication yields sixteen. A later model may correctly copy sixteen; that successful copy cannot repair the original wrong quantity. The real recorded chain makes the separate pass/fail checks visible rather than collapsing them into one success label.

## Implement it

Run this small standard-library mechanism with Python 3. It illustrates the stated contract or calculation. The connected L09–L11 source below performs the actual local-model workflow; this short snippet is not a substitute for those model calls.

{/* example:e5-chains:start */}

```python
def compute(order):
    prices = {"pen": 2, "book": 8}
    return {**order, "total": prices[order["item"]] * order["quantity"]}


first = {"item": "pen", "quantity": 8}
second_input = compute(first)
print(second_input)
assert second_input["total"] == 16
```

{/* example:e5-chains:end */}

Expected mechanism output:

```text
{'item': 'pen', 'quantity': 8, 'total': 16}
```

## When to use it

Use chains for workflows with meaningful intermediate artifacts and deterministic checks. Compare the plain implementation first so framework overhead serves readability or reuse instead of obscuring a simple function call.

## Limits and common mistakes

Composition does not guarantee quality or termination of arbitrary user stages. More calls add work and possible errors. This two-call chain is small and local; its observed failure is retained, not presented as production readiness.
