## Definition and intuition

A token embedding is the learned vector selected from an embedding table by a token ID. It is the model’s numeric starting representation for that token occurrence before later contextual processing.

Your tokenizer returns [7, 12, 7], but matrix multiplication needs vectors rather than vocabulary addresses. An embedding lookup turns those three IDs into three rows of fixed width.

## How it works

For an embedding table E with shape [V, d] and input IDs with shape [batch, T], lookup produces [batch, T, d]. The same ID selects the same row before position/context processing, regardless of its surrounding words.

The table values are learned with the model’s objective; they are not handwritten dictionary definitions. Gradient updates modify rows involved in training and may also update an output table if weights are tied. Input/output weight tying is an architecture choice, not a requirement of embeddings.

Position information and transformer blocks turn initial rows into contextual states. Some models add absolute position vectors; others encode positions through operations such as RoPE on Q/K. Do not describe every model as adding the same type of position embedding at the input.

### The important distinction

Changing ID mappings while retaining weights changes meaning silently.

## Worked example

A table with four rows and width two receives IDs [2, 0, 2]. The result has three rows: E[2], E[0], E[2]. The first and third rows initially match. L03 verifies this on an actual pretrained bank row and then shows later hidden states differ between contexts.

## Implement it

Run the small mechanism from the repository root with `python3 scripts/run-examples.py --id foundation-token-embedding`. Its values are illustrative; it isolates the stated operation rather than pretending to load a trained model.

{/* example:foundation-token-embedding:start */}

```python
table = [[0.1, 0.9], [0.5, 0.2], [0.8, 0.3], [0.0, 0.0]]
ids = [2, 0, 2]
vectors = [table[index] for index in ids]
print(vectors)
assert vectors[0] == vectors[2]
```

## When to use it

Use embedding lookup when categorical IDs need learned numeric features. The same principle applies to song IDs in a recommender. Distinguish this table from a pretrained sentence encoder whose output already incorporates context and pooling.

## Limits and common mistakes

Changing ID mappings while retaining weights changes meaning silently. A random new embedding row is not trained knowledge. A 2D drawing of vectors usually omits many dimensions; its geometry should not be treated as the original model space.
