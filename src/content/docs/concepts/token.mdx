## Definition and intuition

A **token** is a unit in the sequence that a particular tokenizer maps to an integer ID. It might be a whole word, a word fragment, punctuation, a byte-like piece, or a special marker. The model’s context length is measured in these units.

A token is therefore an interface between readable text and the model’s numeric vocabulary. It is not the same thing as a linguistic word. The exact boundary comes from the tokenizer paired with the model.

## Before you start

No prior model knowledge is required. Start with the example and follow linked terms as you need them.

## How it works

A tokenizer chooses a sequence of pieces that covers an input according to its rules and vocabulary. It maps each piece to an ID; special IDs may mark sequence boundaries or padding. The model looks up an embedding vector for each ID. During generation, the model predicts an ID and the tokenizer turns the resulting ID sequence back into text.

The number of tokens matters because attention operates over positions and a model accepts only a finite context. Long or unfamiliar strings often use more pieces than familiar ones. Count with the actual model tokenizer when planning a prompt or document chunk.

## Worked example

The text `unhappiness!` might become `un`, `happiness`, `!` in one invented tokenizer and `unhappy`, `ness`, `!` in another. Both sequences represent the same visible text but have different IDs and potentially different lengths.

## Implement it

**Setup:** Python 3; no packages or API key needed. Save this as `example.py` and run `python3 example.py`. This is a small teaching model, not a pretrained neural network.

```python
# Invented vocabulary: a mechanics example, not a trained tokenizer
vocab = {'un': 12, 'happiness': 48, '!': 7}
pieces = ['un', 'happiness', '!']
print([vocab[piece] for piece in pieces])
```

**Expected behavior:** `[12, 48, 7]`

A dictionary lookup maps each known piece to an ID. Real tokenizers also decide *which* pieces to use. The [tokenization lesson](/llm-concept-atlas/concepts/tokenization/) contains a real tokenizer example.

## When to use it

- Count tokens before sending long prompts or retrieved passages.
- Inspect pieces when a model handles code, names, or unfamiliar languages poorly.

## Limits and common mistakes

- One token is not one word, and visible character count is not a reliable token count.
- IDs have meaning only with their matching vocabulary and model.
