## Definition and intuition

Self-consistency samples several candidate solutions, extracts their final answers, and aggregates agreement. Agreement can be useful evidence, but correlated wrong answers and invalid outputs can defeat the vote.

Five calls are five opportunities to repeat the same mistake. Before voting, declare how an answer is extracted, how invalids count, and when the system abstains. Otherwise a convincing aggregate can hide fragile parsing.

## How it works

### Generate, extract, aggregate

L10 records five real temperature-0.7 calls with seeds 101 through 105 per case. One path requests calculations and an Answer line; another requests a direct integer with a native 0–100 grammar. They are separately labeled mechanism probes because both the instruction and decoding change. The second is sampled answer voting, not evidence that the model generated independent reasoning chains.

### A precise voting policy

The atlas returns a winner only when one valid answer has a uniquely highest count. Ties and an empty valid set abstain. Invalid samples remain in the total sample count. A separate strict-majority flag requires the winner count to exceed half of all samples, including invalids. A unique plurality can exist without a strict majority.

### Agreement and correctness

The reference answer is used only after aggregation to grade the result. It is never used to select which answer wins. Different seeds do not guarantee independent errors; the same prompt, checkpoint, and learned tendencies can produce highly correlated mistakes. Report the original sample texts, extracted values, vote counts, model calls, and token work alongside aggregate accuracy.

## Worked example

With answers [15, 15, 14, invalid, invalid], fifteen wins a unique plurality with two of five votes. It is not a strict majority. With [15, 14, invalid], the valid votes tie and the system abstains. Removing invalids from the denominator would overstate confidence in a fragile output contract.

## Implement it

Run this small standard-library mechanism with Python 3. It illustrates the stated contract or calculation. The connected L09–L11 source below performs the actual local-model workflow; this short snippet is not a substitute for those model calls.

{/* example:e5-self-consistency:start */}

```python
from collections import Counter

samples = [15, 15, 14, None, None]
counts = Counter(x for x in samples if x is not None)
best = max(counts.values(), default=0)
winners = [x for x, n in counts.items() if n == best]
winner = winners[0] if len(winners) == 1 else None
print("winner:", winner, "strict majority:", best > len(samples) / 2)
print("invalid:", samples.count(None))
```

{/* example:e5-self-consistency:end */}

Expected mechanism output:

```text
winner: 15 strict majority: False
invalid: 2
```

## When to use it

Use sampled aggregation on tasks with a well-defined normalization and checkable answer. Compare the extra calls with a single-call baseline and an independent verifier; agreement should not replace evidence.

## Limits and common mistakes

The free-format probe has many unextractable outputs on this tiny model. The integer grammar improves parseability without establishing truth. Sampling costs additional work, and a confident majority can be wrong.
