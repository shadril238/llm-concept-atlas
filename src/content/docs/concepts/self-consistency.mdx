## Definition and intuition

Self-consistency samples multiple reasoning paths or answers and aggregates them instead of trusting one completion.

Chapter 6 treats a prompt as a task specification. A prompt can guide output, but it does not change model weights or guarantee that an answer is correct.

## Before you start

Read [Chain prompting](/llm-concept-atlas/concepts/chain-prompting/) first. You should be able to explain what information its output carries. Then return here and ask what extra problem **Self-consistency** solves. This sequence matters because a plausible output can hide a missing prerequisite or a weak input representation.

## Theory: how it works

1. **Prepare:** Generate several diverse candidate responses under controlled settings
2. **Transform:** Normalize or extract comparable final answers
3. **Inspect:** Vote or score them and inspect disagreements.

### The important distinction

Repeated samples are useful only if they explore genuinely different paths. If sampling is nearly deterministic, voting adds cost without independent evidence; if all samples share a bad premise, agreement is misleading. Aggregate comparable final answers and inspect variance rather than averaging incompatible prose.

## Worked example

Five solutions to a word problem produce four answers of 12 and one answer of 13. Majority agreement is a signal to inspect, not proof that 12 is correct. Walk through the three stages above with that input: identify what is prepared, what changes, and which observation would show success. Then change one condition in the example. If the conclusion changes, the method is sensitive to that choice; if it does not, ask whether the example actually tests the mechanism.

## Implement it

**Setup:** Python 3; no packages or API key are needed. Save the following as `example.py` and run `python3 example.py`. It is a small deterministic illustration of the relevant calculation or data flow. It does not download a trained model.

```python
references = ["cat", "dog", "bird"]
predictions = ["cat", "dog", "car"]
accuracy = sum(a == b for a,b in zip(references,predictions)) / len(references)
print(round(accuracy, 3))
```

**Expected output:**

```text
0.667
```

**What the code shows:** The code compares predictions with references and reports exact-match accuracy. Generative tasks often need additional criteria because two valid answers can use different words. ## When to use it

Use it when sampling is affordable and independent paths might reduce occasional errors. Choose it when the input and output in your application match those assumptions. Compare the simplest useful baseline first, then measure whether the additional complexity improves the metric that matters to readers or users. Record the model, data version, and decision threshold when applicable so results can be reproduced.

## Limits and common mistakes

- Correlated mistakes can dominate the vote; more samples cost time and money.
- **Failure to look for:** All samples rely on the same false premise, so agreement creates false confidence.

A teaching demo usually holds data and model behavior fixed so one mechanism is visible. Real systems face noisy inputs, changing distributions, and edge cases. Test examples that should fail as well as examples that should succeed, and inspect the intermediate stage that causes the error.
