## Definition and intuition

Generative classification asks a language model to produce a textual label, then validates and maps that response into a fixed decision schema. Task correctness and output-format validity must be evaluated separately.

A generator can answer with a correct label, an explanation, an ambiguous response, or unrelated text. A classifier application needs a precise rule for each case. Formatting instructions reduce uncertainty but do not turn every response into a valid decision.

## How it works

### T5 classification

T5 is an encoder-decoder family: the encoder reads the available prompt bidirectionally; the decoder generates target tokens autoregressively while attending to encoder states. Original T5 pretraining reconstructs corrupted text spans using sentinel tokens, and FLAN instruction tuning adds many instructed tasks. Depth depends on the checkpoint; not every T5 has twelve encoder and decoder layers. L07 runs the actual pinned FLAN-T5-small model on the same 80 test sentences as every other method, with a fixed prompt, greedy decoding, a 256-token input cap, and at most eight new tokens.

### A strict output boundary

The parser strips surrounding whitespace, case-folds, and accepts only the complete strings negative or positive. It returns -1 for “positive because…”, a refusal, an empty response, or an unrecognized label. Invalids count as errors in accuracy and as false negatives for the true class, and their rate is reported. In this recorded local run all test outputs happened to be valid; that observation is not a proof that future inputs will always obey the format.

### Optional hosted classification

Keep hosted calls outside the static website and the required local lab. Predeclare the same test IDs, label schema, prompt version, model identifier, maximum output budget, and a bounded call count; use no more than one initial request per test row and log any retries separately. Validate a structured enum response and still handle refusal, timeout, and transport errors. Record measured latency, token usage, date, and cost only when actually observed. The separate optional notebook here imports externally collected JSON results and never makes an API call. Missing outputs and provider errors remain invalid cases, so an interrupted run cannot look better by dropping hard examples.

## Worked example

For raw outputs [“ negative ”, “POSITIVE”, “not negative”, “positive because it is funny”], the declared parser yields [0,1,-1,-1]. The phrase “not negative” may sound favorable, but accepting it would be an undocumented semantic parser. A book-style rule that maps anything except “negative” to positive would misclassify every malformed response as a valid positive label.

## Implement it

This small mechanism uses Python’s standard library and illustrative values; it does not claim to run a pretrained model. Run `python3 scripts/run-examples.py --id discovery-generative-classification`. The connected workflow below supplies the actual model, data, and evaluation.

{/* example:discovery-generative-classification:start */}

```python
outputs = [" negative ", "POSITIVE", "not negative", "positive because it is funny"]
label_ids = {"negative": 0, "positive": 1}
parsed = [label_ids.get(raw.strip().casefold(), -1) for raw in outputs]
print(parsed)
assert parsed == [0, 1, -1, -1]
```

## When to use it

Use a generator when the task requires flexible instructions or a schema that is difficult to support with an existing head, and when measured task quality and operational costs justify it. For a fixed binary decision, compare a direct classifier and a simple baseline first. The optional importer preserves comparability without requiring a paid account to learn the chapter.

## Limits and common mistakes

Token likelihood is not task confidence. A valid label can be wrong, and a fluent explanation can rationalize an error. Hosted model revisions and decoding behavior can change; pin identifiers where possible and record dates. No paid API result or hosted performance claim is included in this E4 release.
