## Definition and intuition

A document embedding maps a text into a fixed-width vector under a specific encoder, pooling, normalization, and truncation contract. It is a feature representation, not a discovered topic or factual summary.

Topic discovery needs one comparable representation for each document. Keeping the document ID attached at every stage is as important as computing the vector: a beautiful map is misleading if its labels have been joined to the wrong rows.

## How it works

### From token states to document features

The E4 encoder returns [batch,tokens,384] contextual states. Multiply each position by its attention mask, sum over tokens, and divide by the number of unmasked positions. L2-normalize the pooled vector for cosine comparisons. Padding must not dilute a shorter document’s mean. This pooling follows the chosen checkpoint contract; arbitrary pooling changes produce a different representation.

### Retain the input contract

L08 preserves an ordered 45-row corpus of original fictional research summaries. The same ID order follows embeddings [45,384], clustering coordinates [45,5], assignments [45], and the independent display coordinates [45,2]. Titles are retained for inspection; hidden theme labels are never supplied to fitting. The encoder token budget is 256, so longer texts may lose evidence even though the original text stays visible.

### Corpus provenance and the book

The book uses a large arXiv computation-and-language corpus. A real research collection needs paper IDs, title/abstract fields, source revision or retrieval date, licensing decisions, and reproducible sampling. The atlas uses an original small corpus to make every row inspectable and avoid presenting unverified paper findings. It is an adaptation, not a reproduction of the book’s full-corpus benchmark.

## Worked example

For token states [[2,0],[0,2],[100,100]] with mask [1,1,0], masked mean pooling is [1,1]. Including padding would instead produce [34,34], changing scale and potentially direction with other values. The normalized correct vector is approximately [0.707,0.707]. A mask affects which states are pooled, not just how a diagram is drawn.

## Implement it

This small mechanism uses Python’s standard library and illustrative values; it does not claim to run a pretrained model. Run `python3 scripts/run-examples.py --id discovery-document-embeddings`. The connected workflow below supplies the actual model, data, and evaluation.

{/* example:discovery-document-embeddings:start */}

```python
from math import sqrt

states = [[2.0, 0.0], [0.0, 2.0], [100.0, 100.0]]
mask = [1, 1, 0]
mean = [sum(row[j] * m for row, m in zip(states, mask)) / sum(mask) for j in range(2)]
norm = sqrt(sum(v * v for v in mean))
print("masked mean:", mean, "unit vector:", [round(v / norm, 3) for v in mean])
```

## When to use it

Use document vectors for semantic retrieval, a separate classifier, or the input stage of clustering. Cache them with text/encoder/preprocessing hashes so a source edit or pooling change does not silently reuse incompatible features.

## Limits and common mistakes

One vector can hide multiple topics, numerical details, or contradictory claims. Similarity is not factual agreement. A short curated corpus makes broad themes obvious; it does not demonstrate performance on all research literature.

## Check your understanding

<details><summary>Why retain IDs rather than relying only on array position?</summary><p>Batching, filtering, sorting, and joins can reorder rows. Stable IDs let you check that an assignment, plot point, and representative text refer to the same source document.</p></details>

<details><summary>Can a document vector prove that a paper supports a generated topic claim?</summary><p>No. It represents learned features. Read the paper evidence and the label scope separately; vector similarity does not establish factual entailment.</p></details>
