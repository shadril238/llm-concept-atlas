## Definition and intuition

LoRA learns an additive low-rank update to a frozen weight matrix. For column input x, W has shape d_out×d_in, A has shape r×d_in, B has shape d_out×r, and the adapted projection is Wx + (alpha/r)BAx. The factorization restricts the update, not the rank of the original W.

## Theory: how it works

### Low rank and initialization

The product BA has rank at most r. A bottleneck can represent some useful task changes with many fewer values than an unrestricted matrix, but the useful rank depends on the task and targeted modules. Ordinary LoRA scaling is alpha/r; other variants can choose a different rule. L21 uses ordinary rank 4/alpha 8, so scaling is 2. Increasing alpha does not increase capacity or parameter count in the same way as increasing rank.

In the selected PEFT initialization, A is random and B is zero. The initial update is zero, so the adapted policy initially matches the base in evaluation mode. B can receive a first-step gradient while A's first-step gradient may be zero because it is multiplied by B. After B changes, A can learn too. Zero A and zero B together would produce a dead bilinear initialization.

Targets are named modules, not vague “attention weights.” Here `query_key_value` is one fused projection with three output groups. Six fused 384×128 matrices produce 12,288 trainable values at rank 4. This does not adapt the attention output projection, MLP, embeddings or vocabulary head. Dropout is explicitly zero for these controlled CPU runs; nonzero adapter dropout changes the training path and must be disabled for equivalence checks.

### Adapter merging

For supported floating-point linear layers, merge computes `W_merged = W + (alpha/r)BA`. It removes the separate adapter branch, so deployment can use an ordinary model, but merging sacrifices convenient task switching unless originals are retained. Save the tokenizer and exact base identity with the artifact. Directly changing a quantized integer payload is not this floating-point algebra.

Float32 summation order can differ between a separate adapter path and the merged projection. L21 records the actual maximum logit difference and uses an explicit scale-relative tolerance, then separately repeats the algebra in float64. The author run's float32 maximum was about 0.00788 on logits with global magnitude 31.95; float64 differed by about 1.3e-11. This is bounded numerical agreement, not bitwise identity. A fresh reload of the saved merged model is checked too.

### The important distinction

Read the mechanism and the actual workflow together. A small calculation checks arithmetic; the connected training record checks optimization and artifacts; heldout task results check a separate quality claim.

## Worked example

Let W be the 2×2 identity, A=`[0.1,0.2]`, B=`[0.3,-0.1]` as a column and alpha/r=2. BA is `[[0.03,0.06],[-0.01,-0.02]]`, so the merged matrix is `[[1.06,0.12],[-0.02,0.96]]`. Multiply the same x through both paths and compare. Changing orientation would compute a different shape or the wrong update.

## Implement it

### A complete arithmetic trace

This standalone Python 3 calculation uses only the standard library. It does not download or train a model. The [complete generation labs](/llm-concept-atlas/labs/generation-adaptation/) provide the pinned environments, actual training entrypoints, staged notebooks, raw results and artifact checks.

{/* example:e8-lora:start */}

```python
w = [[1.0, 0.0], [0.0, 1.0]]
a, b, scale, x = [0.1, 0.2], [0.3, -0.1], 2.0, [2.0, -1.0]
merged = [[w[i][j] + scale * b[i] * a[j] for j in range(2)] for i in range(2)]
separate = [
    sum(w[i][j] * x[j] for j in range(2))
    + scale * b[i] * sum(a[j] * x[j] for j in range(2))
    for i in range(2)
]
combined = [sum(merged[i][j] * x[j] for j in range(2)) for i in range(2)]
print("merged:", merged)
assert all(abs(a - b) < 1e-12 for a, b in zip(separate, combined))
print("same linear function:", combined)
```

## When to use it

Use LoRA for compact domain/style/task adaptation where low-rank targets offer a useful quality/resource tradeoff. It cannot guarantee factual correctness or preserve every original capability. An adapter that lowers completion loss may still generate repeated, irrelevant or truncated prose.

## Limits and common mistakes

The evaluated instruction subset has 32 training,8 validation and 8 test source contexts. Pretraining overlap is unknown. Repeated views of these test outputs are not a new independent benchmark. Preserve failed and length-limited answers, exact base/tokenizer identity and data provenance when transferring the workflow. The book's larger TinyLlama/CUDA settings require their own supported hardware execution; the small profiles do not certify them.

## Check your understanding

<details>
<summary>Why can B learn on the first step when A is random and B is zero?</summary>

The derivative with respect to B contains A and input x. The derivative with respect to A contains the initially zero B. Both-zero initialization would block both gradients.

</details>

<details>
<summary>What must be compared after merging besides file size?</summary>

Use the same tokenizer, inputs and evaluation mode; compare logits under a stated precision/tolerance, task outputs, exact base identity and fresh saved-model reload.

</details>
