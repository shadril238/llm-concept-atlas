## Definition and intuition

An **encoder-only model** builds context-aware representations of an input sequence. In a bidirectional encoder such as BERT, a token can use information from positions on both sides. The output is useful for understanding or labeling text, rather than directly continuing a prompt token by token.

“Bank” in “river bank” and “bank account” begins as the same written word, but the surrounding words help the encoder produce different contextual states.

## Before you start

Read [representation model](/llm-concept-atlas/concepts/representation-model/) first; return here when the key terms feel familiar.

## How it works

Token IDs enter an embedding layer with position information. Repeated encoder blocks apply self-attention across the allowed input positions and a feed-forward transformation. The final hidden states contain contextual information. A task head can read a designated pooled position or token states to classify a sequence or label tokens.

BERT-style pretraining hides some tokens and asks the model to recover them using context. For a real task, a classifier head usually needs task training; raw encoder states are not automatically sentiment labels.

## Worked example

Input: “The bank near the river flooded.” For the `bank` position, `river` and `flooded` are available context. In “The bank approved the loan,” `loan` pushes toward the financial sense. This does not mean every attention weight directly names the model’s interpretation.

## Implement it

**Setup:** Python 3; no packages or API key needed. Save this as `example.py` and run `python3 example.py`. This is a small teaching model, not a pretrained neural network.

```python
# A tiny context rule, not a neural encoder
sentences = ['The bank flooded by the river', 'The bank approved a loan']
for sentence in sentences:
    words = sentence.lower().split()
    sense = 'river edge' if 'river' in words else 'financial institution'
    print(sense)
```

**Expected behavior:** `river edge` followed by `financial institution`.

This explicit rule shows why context changes an interpretation. A trained encoder learns its context-dependent features from data rather than using this `if` statement. For a real classifier, follow the [classification use case](/llm-concept-atlas/use-cases/text-classification/).

## When to use it

- Use encoder-style models for classification, entity labeling, and representation tasks.
- Use a decoder-style model when direct left-to-right generation is the goal.

## Limits and common mistakes

- “Bidirectional” describes available context in the encoder, not perfect language understanding.
- An encoder model can be adapted into a generator in other architectures, but the basic encoder-only setup is not an autoregressive text generator.
