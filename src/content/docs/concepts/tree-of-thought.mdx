## Definition and intuition

Tree-of-thought is an explicit search workflow over candidate intermediate states. It needs branching, state evaluation, a frontier policy, and a stopping rule; a list of ideas in one answer is not an executed search tree.

A search tree makes alternatives concrete. Each node records a state; each edge records a legal action. The evaluator decides which states deserve more work or already satisfy the task. That control flow is visible and independently testable.

## How it works

### A bounded, exact problem

L10 combines four small integers using addition, subtraction, multiplication, and division to make 24. Every input must be used exactly once. States contain exact rational values and their expression provenance. The solver generates legal pairwise combinations, excludes division by zero, and memoizes duplicate value states. A bounded AST interpreter checks the final expression and leaf multiset without evaluating arbitrary Python.

### Frontier and stopping

Complete breadth-first search, beam widths one and four, and a sixteen-node budget are compared on identical puzzles. Beam variants rank all generated candidates using a declared distance heuristic before retaining the beam. Beam exhaustion means the retained path failed; node-budget exhaustion means work stopped early. Only an exhaustive frontier exhaustion establishes no solution under these operators and duplicate-state convention.

### Where the model enters

A separate actual model ranks one of up to eight pre-generated legal next candidates, with at most three calls. A native index grammar prevents out-of-range selections. The exact solver still constructs operations and checks success. This restricted model-guided search is not a demonstration that the model independently invents, evaluates, and proves arithmetic plans. The displayed first hundred nodes plus solution ancestors are an explicitly labeled subset; full traces are saved locally.

## Worked example

The inputs 3, 3, 8, 8 have the fractional solution 8/(3-8/3)=24. A heuristic that prefers values immediately near 24 can discard the fractional route. Compare the complete run with beam-one and inspect where the frontier becomes narrow. A failed beam is a limitation of that search policy, not proof that the puzzle is impossible.

## When to use it

Use explicit search when intermediate states and success can be represented and evaluated, such as constrained puzzles or bounded planning. Define work budgets and compare a transparent baseline before adding a model ranker.

## Limits and common mistakes

Branching can grow quickly. Heuristics and duplicate-state conventions influence which paths survive. A Game-24 solver is a controlled illustration, not evidence of general language reasoning or a universal planning agent.
