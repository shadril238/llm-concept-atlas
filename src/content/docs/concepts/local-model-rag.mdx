## Definition and intuition

Local-model RAG runs document encoding, retrieval, context assembly, and generation in a declared local runtime. Local execution controls where computation occurs; it does not automatically improve source coverage, model quality, or grounding.

Read this lesson as a sequence: identify the input, follow the transformation, inspect the result, and explain a failure. The worked example and recorded lab below make those boundaries visible.

## How it works

### The runnable local contract

The default L12/L13 environment pins the encoder, cross-encoder, generator, tokenizers, package versions, and original fixture hashes. Public safetensors are downloaded once and checked; remote custom model code is not executed. The generator is FLAN-T5-small in CPU float32, an explicit accessible adaptation of the book’s larger local example, not a claim of equivalent quality.

### Inspect model I/O

The encoder rejects over-cap inputs and records its pooling/index conventions. The generator rejects prompts beyond its native input cap. Context packing adds only whole source passages with IDs and separately records omissions. Every generated answer and planner output remains unedited. Finite-label source choices use actual likelihood scoring over a shared domain and account for scored tokens separately from generated tokens.

### Save the usable artifact

L12 saves vectors together with ordered chunk IDs, encoder provenance, metric, and pooling metadata. A reload check verifies neighbor IDs. Saved result JSON connects raw generation to source versions and prompt settings. Reproducing a pipeline requires this joint contract; copying only a model filename or a vector matrix loses essential context.

## Worked example

After the first public downloads, the registered commands run with offline caches and no provider key. If a snapshot is incomplete, execution fails rather than substituting another checkpoint. The local run can still return the wrong team extension even with relevant passages present; that is a model/grounding failure, not evidence that locality guarantees correctness.

## When to use it

Use local execution when the operating environment, deployment control, reproducibility, or input handling requires it. Evaluate the actual selected model on representative tasks and account for downloads, memory, context limits, and generated work.

## Limits and common mistakes

The supplied fixture is fictional and the small model frequently fails. No hosted provider or CUDA backend is silently substituted. Locality is an operating choice; the phase does not claim a broad privacy certification or production-quality answers.
