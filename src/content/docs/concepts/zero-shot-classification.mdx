## Definition and intuition

Zero-shot classification applies a model to labels for which no task-specific labeled examples were supplied.

Chapter 4 compares classification with specialized encoders, reusable embeddings, and generators. Label definitions, labeled data, and evaluation examples determine which approach fits.

## Before you start

Read [Representation Model](/llm-concept-atlas/concepts/representation-model/) first. You should be able to explain what information its output carries. Then return here and ask what extra problem **zero-shot classification** solves. This sequence matters because a plausible output can hide a missing prerequisite or a weak input representation.

## Theory: how it works

1. **Prepare:** Write clear descriptions for candidate labels
2. **Transform:** Score the text against each label using a general model
3. **Inspect:** Calibrate or inspect predictions on a small validation sample.

### The important distinction

One common implementation compares the input with candidate label descriptions through an entailment or embedding model. Score differences can be sensitive to how labels are phrased and whether candidates are evaluated together. Validate on a small labeled set even when the method needs no task-specific training.

## Worked example

A team asks whether a note is about shipping, billing, or account access without training three new classes. Descriptive labels help the model compare candidates. Walk through the three stages above with that input: identify what is prepared, what changes, and which observation would show success. Then change one condition in the example. If the conclusion changes, the method is sensitive to that choice; if it does not, ask whether the example actually tests the mechanism.

## Implement it

**Setup:** Python 3; no packages or API key are needed. Save the following as `example.py` and run `python3 example.py`. It is a small deterministic illustration of the relevant calculation or data flow. It does not download a trained model.

```python
labels = {"sports": {"goal", "team"}, "food": {"meal", "recipe"}}
text = "the team scored a goal"
words = set(text.split())
scores = {label: len(words & cues) for label, cues in labels.items()}
print(max(scores, key=scores.get), scores)
```

**Expected output:**

```text
sports {'sports': 2, 'food': 0}
```

**What the code shows:** Each label has a short description represented here by cue words. The code counts overlap and chooses the highest score; a real zero-shot model uses learned representations. The [official chapter 4 notebook](https://github.com/HandsOnLLM/Hands-On-Large-Language-Models/tree/main/chapter04) develops the corresponding model-based implementation.

## When to use it

Use it for exploratory labeling or rapidly changing label sets, then validate before high-stakes use. Choose it when the input and output in your application match those assumptions. Compare the simplest useful baseline first, then measure whether the additional complexity improves the metric that matters to readers or users. Record the model, data version, and decision threshold when applicable so results can be reproduced.

## Limits and common mistakes

- Wording of labels can change scores; zero-shot does not mean zero evaluation.
- **Failure to look for:** A vague label “other” wins because the specific labels were poorly described.

A teaching demo usually holds data and model behavior fixed so one mechanism is visible. Real systems face noisy inputs, changing distributions, and edge cases. Test examples that should fail as well as examples that should succeed, and inspect the intermediate stage that causes the error.
