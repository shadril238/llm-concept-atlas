## Definition and intuition

In-context learning uses examples in a prompt to guide a model on a task without changing its weights.

Chapter 6 treats a prompt as a task specification. A prompt can guide output, but it does not change model weights or guarantee that an answer is correct.

## Before you start

Read [Instruction prompting](/llm-concept-atlas/concepts/instruction-prompting/) first. You should be able to explain what information its output carries. Then return here and ask what extra problem **in-context learning** solves. This sequence matters because a plausible output can hide a missing prerequisite or a weak input representation.

## Theory: how it works

1. **Prepare:** Select demonstrations that show the desired input-output mapping
2. **Transform:** Place them in a consistent format before the new query
3. **Inspect:** Measure whether the model applies the pattern to new cases.

### The important distinction

The model's weights stay fixed while examples influence the next-token prediction in the current context. Example order, formatting, and similarity to the test case can change performance. Distinguish this from supervised fine-tuning, where gradient updates persist after the examples are removed.

## Worked example

Two examples map short reviews to positive and negative. The model then labels a third review by following the shown format, although no gradient update occurred. Walk through the three stages above with that input: identify what is prepared, what changes, and which observation would show success. Then change one condition in the example. If the conclusion changes, the method is sensitive to that choice; if it does not, ask whether the example actually tests the mechanism.

## Implement it

**Setup:** Python 3; no packages or API key are needed. Save the following as `example.py` and run `python3 example.py`. It is a small deterministic illustration of the relevant calculation or data flow. It does not download a trained model.

```python
instruction = "Return one label: positive or negative."
example = "Text: I loved it. Label: positive"
query = "Text: The ending was dull. Label:"
prompt = "\n".join([instruction, example, query])
print(prompt)
```

**Expected output:**

```text
Return one label: positive or negative.
Text: I loved it. Label: positive
Text: The ending was dull. Label:
```

**What the code shows:** The final string contains the instruction, demonstration, and new query in that order. Inspect the rendered string before sending it to a real generator. The [official chapter 6 notebook](https://github.com/HandsOnLLM/Hands-On-Large-Language-Models/tree/main/chapter06) develops the corresponding model-based implementation.

## When to use it

Use it when a few examples clarify a task faster than fine-tuning. Choose it when the input and output in your application match those assumptions. Compare the simplest useful baseline first, then measure whether the additional complexity improves the metric that matters to readers or users. Record the model, data version, and decision threshold when applicable so results can be reproduced.

## Limits and common mistakes

- Performance depends on example choice, order, and context capacity.
- **Failure to look for:** Examples contain a shortcut word that the model imitates instead of learning the intended rule.

A teaching demo usually holds data and model behavior fixed so one mechanism is visible. Real systems face noisy inputs, changing distributions, and edge cases. Test examples that should fail as well as examples that should succeed, and inspect the intermediate stage that causes the error.
