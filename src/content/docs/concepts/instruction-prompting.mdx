## Definition and intuition

Instruction prompting states the requested behavior directly in natural language.

Chapter 6 treats a prompt as a task specification. A prompt can guide output, but it does not change model weights or guarantee that an answer is correct.

## Before you start

Read [Prompt structure](/llm-concept-atlas/concepts/prompt-structure/) first. You should be able to explain what information its output carries. Then return here and ask what extra problem **instruction prompting** solves. This sequence matters because a plausible output can hide a missing prerequisite or a weak input representation.

## Theory: how it works

1. **Prepare:** Describe the role and task in concrete terms
2. **Transform:** Provide the input and necessary constraints
3. **Inspect:** Check the output against the instruction and examples.

### The important distinction

An instruction can state constraints such as length, tone, or permitted labels. Make success observable: “return one of these labels” is easier to verify than “be helpful.” If a prompt demands facts not available in context or model knowledge, the appropriate behavior may be uncertainty rather than confident completion.

## Worked example

“Return only a JSON object with a `label` field” is clearer than “analyze this”. The model may still add prose, so the parser must validate the shape. Walk through the three stages above with that input: identify what is prepared, what changes, and which observation would show success. Then change one condition in the example. If the conclusion changes, the method is sensitive to that choice; if it does not, ask whether the example actually tests the mechanism.

## Implement it

**Setup:** Python 3; no packages or API key are needed. Save the following as `example.py` and run `python3 example.py`. It is a small deterministic illustration of the relevant calculation or data flow. It does not download a trained model.

```python
instruction = "Return one label: positive or negative."
example = "Text: I loved it. Label: positive"
query = "Text: The ending was dull. Label:"
prompt = "\n".join([instruction, example, query])
print(prompt)
```

**Expected output:**

```text
Return one label: positive or negative.
Text: I loved it. Label: positive
Text: The ending was dull. Label:
```

**What the code shows:** The final string contains the instruction, demonstration, and new query in that order. Inspect the rendered string before sending it to a real generator. The [official chapter 6 notebook](https://github.com/HandsOnLLM/Hands-On-Large-Language-Models/tree/main/chapter06) develops the corresponding model-based implementation.

## When to use it

Use it for straightforward tasks where the model already has relevant capabilities. Choose it when the input and output in your application match those assumptions. Compare the simplest useful baseline first, then measure whether the additional complexity improves the metric that matters to readers or users. Record the model, data version, and decision threshold when applicable so results can be reproduced.

## Limits and common mistakes

- Instructions are not weight updates and can conflict with context, ambiguity, or model behavior.
- **Failure to look for:** An instruction says “cite evidence” but no evidence is provided, so the model invents citations.

A teaching demo usually holds data and model behavior fixed so one mechanism is visible. Real systems face noisy inputs, changing distributions, and edge cases. Test examples that should fail as well as examples that should succeed, and inspect the intermediate stage that causes the error.
