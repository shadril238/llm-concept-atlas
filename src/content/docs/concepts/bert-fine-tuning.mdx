## Definition and intuition

BERT fine-tuning adapts a pretrained bidirectional encoder and a task head using labeled data. For sequence classification, one prediction is made for each review; this differs from masked-token prediction and token-level NER.

Follow the input, objective, update, and evaluation as separate steps. The worked example and experiment below connect the explanation to an inspectable implementation.

## How it works

### Follow text into the supervised batch

The tokenizer creates integer IDs, attention masks and padding under a declared cap. A BERT encoder produces contextual states; a pooler/classification head maps the sequence to class logits. Cross entropy compares logits with the review label. L18 uses the same licensed UCI review splits as E4 and an explicitly smaller pretrained tiny BERT backbone.

### Train the intended parameters

The loop uses AdamW, finite loss checks, gradient clipping and validation checkpoint selection. Full adaptation, embeddings-plus-first-layer freezing, and head-only training expose different trainable counts. A frozen weight must remain bitwise equal; absence from an optimizer is not the only evidence. The head-only route also fixes encoder dropout behavior explicitly.

### Evaluate after selection

Three fixed seeds each choose eight training examples per class, with identical selected IDs across methods within a seed. The first maximum validation macro-F1 checkpoint is saved, reloaded and evaluated on the same eighty test reviews. Per-class metrics, confusion matrices and individual wrong predictions are retained. A pretrained sentence-encoder classifier is a separate architectural comparison.

## Worked example

Compare a misclassified review under full and partial freezing for the same selection seed. The partially frozen model may save trainable parameters without reliably increasing test quality. The displayed loss and validation curves explain which checkpoint was selected; the final optimizer step is not automatically deployed.

import json
from pathlib import Path
data = json.loads(Path('src/data/training-results.json').read_text())['classification']
for row in data['runs']:
    if row['method'] == 'bert-full':
        print('seed:', row['seed'], 'train reviews:', len(row['train_ids']))
        print('selected step:', row['selected_step'], 'test macro-F1:', round(row['test']['macro_f1'], 4))

## When to use it

Use it for labeled text classification when a pretrained encoder can adapt to the task and a compact supervised predictor is suitable. Keep lexical and frozen-embedding baselines.

## Limits and common mistakes

Small labeled samples cause high selection variability. Macro-F1, accuracy and per-class recall can disagree. Our three fixed selections are descriptive evidence and do not establish a universal best freezing policy.

Author execution checks tensor/mask contracts, actual parameter updates, split provenance and artifact reload. It does not constitute independent lesson acceptance. Keep training quality, task quality, runtime and generalization claims separate.
