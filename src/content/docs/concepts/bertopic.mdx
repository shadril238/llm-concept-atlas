## Definition and intuition

BERTopic is a modular topic-modeling framework that can fit document embeddings, dimensionality reduction, clustering, and interpretable group representations. Its replaceable stages make controlled comparisons possible.

The main implementation in this lesson is a real fitted pipeline. Preassigned groups appear only in the separate c-TF-IDF arithmetic exercise. L08 preserves every document ID and intermediate shape so you can tell which stage computed an output.

## How it works

### One pipeline, distinct contracts

A frozen encoder turns 45 original summaries into [45,384] vectors. UMAP fits [45,5] clustering coordinates. HDBSCAN fits groups and possible −1 noise. CountVectorizer builds aggregated class counts after English stop-word removal, and ClassTfidfTransformer assigns topic-term weights. BERTopic connects these components and retains topic IDs, terms, counts, and representative texts.

### Replace only the stage you mean to study

KeyBERTInspired and two MMR settings update descriptions of the same fitted assignments. The code asserts assignment equality after each update. A separate density comparison changes only min_samples while retaining the exact five-dimensional points. Refitting several components at once would confound the interpretation. The record uses real library components, not a dictionary of manually supplied semantic groups.

### Research abstract corpus

The book’s corpus contains arXiv computation-and-language abstracts. The atlas adaptation uses 45 original fictional research-style summaries with stable IDs and inspectable provenance. They are not real paper findings or citations. A larger imported collection needs source licensing, paper IDs, title/abstract fields, sampling rules, and version hashes before it can support claims about research trends.

### Saving is also a model contract

L08 saves topic data and c-TF-IDF using safetensors and reloads with the same explicitly supplied pinned embedding backend. It checks assignments, term lists, and stored weights. That lightweight format does not retain fitted UMAP/HDBSCAN estimators. Its new-document transform uses cosine to saved topic embeddings, so it is not the original density assignment rule. The record checks that inference calculation and reports its agreement with original training assignments instead of assuming equivalence.

## Worked example

The baseline run produces three topics and one noise document. The less conservative density setting absorbs the bridge document into a group; ARI is about 0.970 under the declared convention. Keyword reranking and MMR can change terms such as translation/translations without moving a document. Those are two different kinds of change, and the explorer exposes both.

## Implement it

This is the actual fitted pipeline function extracted from the verified L08 source. Its inputs are the ordered document list, the corresponding real encoder vectors, and the pinned embedding backend built in the complete lab. Run the complete source with `python3 scripts/run-examples.py --id modular-bertopic --offline` after the first download; the standalone function is not a replacement for input preparation.

{/* example:bertopic-pipeline:start */}

```python
def fit_pipeline(documents, embeddings, backend):
    """Documents -> real UMAP -> real HDBSCAN -> class-based TF-IDF."""
    from bertopic import BERTopic
    from bertopic.vectorizers import ClassTfidfTransformer
    from hdbscan import HDBSCAN
    from sklearn.feature_extraction.text import CountVectorizer
    from umap import UMAP

    reducer = UMAP(
        n_neighbors=8,
        n_components=5,
        min_dist=0.0,
        metric="cosine",
        random_state=42,
        n_jobs=1,
    )
    clusterer = HDBSCAN(
        min_cluster_size=5,
        min_samples=8,
        metric="euclidean",
        cluster_selection_method="eom",
        prediction_data=True,
    )
    vectorizer = CountVectorizer(stop_words="english", ngram_range=(1, 1))
    model = BERTopic(
        embedding_model=backend,
        umap_model=reducer,
        hdbscan_model=clusterer,
        vectorizer_model=vectorizer,
        ctfidf_model=ClassTfidfTransformer(),
        top_n_words=5,
        calculate_probabilities=False,
    )
    assignments, strengths = model.fit_transform(documents, embeddings)
    return model, assignments, strengths
```

## When to use it

Use BERTopic when you need a modular, inspectable organization of a text collection and can evaluate its usefulness with readers. Start with traceable inputs, sensible components, and document inspection before adding generated labels. Read the complete runnable L08 source alongside the extracted pipeline function below.

## Limits and common mistakes

The curated themes make this small example easier than an open research corpus. Representative documents can hide unrelated members; density noise does not mean an invalid paper. Lightweight reload has a different inference rule, and a generated name is never evidence that a cluster is stable or correct.
