## Definition and intuition

Quantization represents values using a finite code set plus reconstruction metadata. In model adaptation it changes the effective frozen base and its storage; in inference it can also change arithmetic and kernel choices. Fewer stored bits do not imply unchanged outputs or a uniformly smaller training process.

## Theory: how it works

### Scales, codes and reconstruction

A simple symmetric uniform quantizer divides a value by a scale, rounds to an integer and clamps to an allowed interval. Reconstruction multiplies the code by the scale. The error depends on scale, rounding, clipping and the distribution of values. A very large outlier can leave too little resolution for ordinary values; blockwise schemes allow local scales, at a metadata cost.

NF4 is a nonuniform four-bit codebook, not the signed integer grid in the small arithmetic below. Different formats—GGUF inference quantization, bitsandbytes NF4, GPTQ or AWQ—have different calibration, storage and runtime contracts. An E5 GGUF inference result does not verify Transformers adapter-training kernels. L21 uses a separate explicit quantized environment for this reason.

Weights can be packed as four-bit codes while multiplication uses float32 or bfloat16 intermediates. Normalization and output heads may stay in floating point. Backend-specific conversion decides which modules are supported; inspect actual types and dtypes instead of trusting a configuration name. Fine-tuning quantized base weights directly is a different problem from freezing them and training floating adapters.

### The important distinction

Model file bytes, allocated tensor memory, device peak, process RSS, throughput and task quality measure different things. A smaller file may use slower dequantization kernels. A device can run out of memory because activations or temporary buffers grow with sequence length even when weight storage fits. The browser shows a deliberately incomplete tensor accounting exercise; execution records separately retain observed process peaks and their measurement method.

Quantization also affects deployment comparisons. Reloading identical quantized weights plus an adapter should be checked. Dequantized merge equivalence concerns the quantized approximation, whereas merging into the original high-precision base changes the starting weights. Requantizing a merged artifact can alter outputs again. Preserve identities and evaluate every artifact you intend to serve.

## Worked example

For the values 0.12,0.47 and1.00, choose a symmetric signed four-bit demonstration grid with codes−7…7 and scale 1/7. Values round to codes1,3,7 and reconstruct to approximately0.143,0.429,1.000. The first two values change despite staying in range. With one global outlier7.0, the scale becomes1 and both0.12 and0.47 round to zero.

This counterexample explains why code precision alone is insufficient: the scale and grouping matter. It does not reproduce NF4's codebook, GPU kernels or the memory savings in the original QLoRA experiments. Use the actual Linux profile to inspect real quantizer state and raw heldout behavior.

## Implement it

This standalone Python 3 calculation uses only the standard library. It does not download or train a model. The [complete generation labs](/llm-concept-atlas/labs/generation-adaptation/) provide the pinned environments, actual training entrypoints, staged notebooks, raw results and artifact checks.

{/* example:e8-quantization:start */}

```python
values = [0.12, 0.47, 1.0]


def quantize(values, scale):
    codes = [max(-7, min(7, round(x / scale))) for x in values]
    restored = [q * scale for q in codes]
    return codes, [round(x, 3) for x in restored]


print("local range:", quantize(values, 1 / 7))
print("outlier-scaled range:", quantize(values, 1.0))
print("Uniform signed grid demonstration; not the NF4 codebook.")
```

## When to use it

Quantization is useful for reducing deployment storage or enabling an otherwise memory-constrained adapter experiment. Choose it after identifying the bottleneck, and retain a high-precision baseline. Accuracy-sensitive extraction or arithmetic can fail even when ordinary prose appears fluent; evaluate the actual application outputs.

<details>
<summary>If all model weights use four-bit codes, is the training peak exactly parameter_count/2 bytes?</summary>

No. Metadata, floating modules, adapters, gradients, optimizer state, activations and temporary allocations add to the payload. Often not all weights are quantized either.

</details>

<details>
<summary>Can an inference-only quantized result certify QLoRA?</summary>

No. QLoRA requires genuine adapter optimization through a frozen quantized base, with verified backend, gradients, frozen state and reusable artifacts.
