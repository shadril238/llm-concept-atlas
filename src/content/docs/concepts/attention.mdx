## Definition and intuition

Attention constructs an output by scoring a query against keys, normalizing permitted scores, and combining the corresponding values. It is a learned information-routing computation, not a literal measurement of human attention.

At one position, a model needs information from several other positions, with different weights. A uniform average cannot adapt to the current query, while attention can change the mixture based on content and visibility.

## How it works

For row-vector matrices Q, K, V, scaled dot-product attention computes scores QKᵀ/√d_k, adds an appropriate mask, applies a row-wise softmax, then multiplies by V. With Q [Tq,d_k], K [Tk,d_k], and V [Tk,d_v], the result has shape [Tq,d_v].

Masking removes disallowed positions before normalization. Using a score of negative infinity makes its softmax weight zero. A causal mask disallows future positions; padding and document-boundary masks serve different purposes. Every row must retain at least one valid key.

Softmax is numerically stable when the row maximum is subtracted before exponentiation. Scaling by √d_k controls score magnitude as head width grows. Output coordinates are weighted values, not weighted token IDs or a copy of the largest-scoring key.

### The important distinction

A large weight does not prove a word caused a final answer.

## Worked example

For scores [2,1] and values [10,0], weights are about [0.731,0.269] and the weighted result is 7.311. If the second key is masked, the first weight becomes one and the result becomes 10. This isolates normalization; L05 additionally computes projections and checks the complete tensor operation.

## Implement it

Run the small mechanism from the repository root with `python3 scripts/run-examples.py --id foundation-attention`. Its values are illustrative; it isolates the stated operation rather than pretending to load a trained model.

{/* example:foundation-attention:start */}

```python
from math import exp

scores, values = [2.0, 1.0], [10.0, 0.0]
p = [exp(s - max(scores)) for s in scores]
p = [x / sum(p) for x in p]
print("weights:", [round(x, 3) for x in p])
print("output:", round(sum(w * v for w, v in zip(p, values)), 3))
```

## When to use it

Use attention when outputs should combine variable input positions under a query. Self-attention shares the source sequence; cross-attention draws queries and memory from different streams. Inspect both the value mixture and masking before interpreting a heatmap.

## Limits and common mistakes

A large weight does not prove a word caused a final answer. Other heads, residual paths, MLPs, and later layers also contribute. Applying softmax before masking and then zeroing values without renormalizing gives a different computation.

## Check your understanding

<details><summary>Why does masking one of two keys change the other key’s normalized weight?</summary><p>The softmax denominator sums only permitted exponentiated scores. Removing one contributor changes that denominator. Setting a value vector to zero after softmax would not produce the same renormalized distribution.</p></details>

<details><summary>One of two keys is masked. Is zeroing its value after softmax sufficient?</summary><p>No. Recompute normalization over allowed scores. Otherwise the removed key still consumes probability mass, shrinking the remaining output incorrectly.</p></details>
