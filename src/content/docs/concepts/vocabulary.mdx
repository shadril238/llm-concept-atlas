## Definition and intuition

A tokenizer’s **vocabulary** is the inventory of token pieces and their assigned IDs. It defines which pieces can be emitted and which embedding row each ID points to in a paired model. Think of it as a numbered parts catalog, not a dictionary of complete words.

Special tokens, such as start or separator markers, are usually entries too. A vocabulary can contain common words, word fragments, punctuation, and byte-level pieces.

## Before you start

Read [tokenization](/llm-concept-atlas/concepts/tokenization/) first; return here when the key terms feel familiar.

## How it works

A tokenizer is often trained on a text collection to choose useful pieces. Frequent sequences may receive compact entries; rarer strings can be assembled from smaller pieces. At inference time, the vocabulary is fixed for a given tokenizer. The tokenizer segments incoming text and returns the corresponding IDs. The model’s embedding matrix has a row for each allowed ID.

A model and tokenizer are therefore a matched pair. Replacing only the vocabulary can change what a given ID means while leaving the model’s learned embedding row unchanged. Even if both systems use integer IDs, the mapping is not interchangeable.

## Worked example

Suppose ID `42` means `cat` in vocabulary A, but `##ing` in vocabulary B. The same embedding row is loaded for ID `42`. Using B with a model trained on A would feed the wrong learned signal for that row.

## Implement it

**Setup:** Python 3; no packages or API key needed. Save this as `example.py` and run `python3 example.py`. This is a small teaching model, not a pretrained neural network.

```python
vocabulary = {'cat': 42, '##s': 17, '[SEP]': 2}
ids = [vocabulary[p] for p in ['cat', '##s', '[SEP]']]
reverse = {number: piece for piece, number in vocabulary.items()}
print(ids, [reverse[number] for number in ids])
```

**Expected behavior:** The IDs `[42, 17, 2]`, followed by the three original pieces.

The forward map encodes pieces; the reverse map helps inspect IDs. A production tokenizer also applies segmentation, normalization, and decoding rules—this dictionary alone is insufficient.

## When to use it

- Keep tokenizer artifacts with model weights when deploying.
- Inspect vocabulary and special-token IDs when debugging surprising input lengths or decoding.

## Limits and common mistakes

- A large vocabulary does not automatically mean better quality; it trades sequence length against embedding size and coverage.
- A vocabulary entry can be a fragment, not a semantic concept.
