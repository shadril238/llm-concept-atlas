## Definition and intuition

**Retrieval-augmented generation (RAG)** combines a retriever with a text generator. The retriever finds source passages relevant to a question; the system puts selected passages into the generator’s context; the generator writes an answer using that evidence. The source material can change without retraining the generator.

Think of a librarian handing a writer a small packet of documents. The packet improves the writer’s access to facts, but the writer can still misread it, omit a caveat, or invent a claim.

## Before you start

Read [semantic search](/llm-concept-atlas/concepts/semantic-search/) first; return here when the key terms feel familiar.

## How it works

A practical RAG pipeline has distinct stages: ingest and chunk documents; embed and index them; retrieve candidates for a question; optionally rerank and choose passages; assemble a prompt with source IDs; generate an answer; verify that claims are supported by cited passages. If retrieval misses the right passage, generation cannot recover it from the supplied context. If the relevant passage is found but truncated, context selection fails.

Evaluation should separate retrieval quality from grounded answer quality. Check whether relevant evidence appears in the top k, whether the answer addresses the question, and whether each claim is supported. A refusal such as “I cannot answer from these passages” is better than unsupported confidence when evidence is absent.

## Worked example

Question: “When does the library close on Saturday?” Retriever returns a library-hours passage saying “Saturday: 5 p.m.” and an unrelated café menu. A grounded answer is “5 p.m. [Library hours].” If the hours passage is removed, the system should withhold the answer rather than guess.

## Implement it

**Setup:** Python 3; no packages or API key needed. Save this as `example.py` and run `python3 example.py`. This is a small teaching model, not a pretrained neural network.

```python
question = 'When does the library close on Saturday?'
passages = {'hours': 'The library closes at 5 p.m. on Saturday.',
            'cafe': 'The café serves coffee and tea.'}
selected = ['hours']
answer = passages['hours'] + ' [hours]' if 'hours' in selected else 'No supported answer.'
print(answer)
```

**Expected behavior:** `The library closes at 5 p.m. on Saturday. [hours]`

This is the evidence-selection boundary, not a live LLM. The code makes source dependence visible. Follow the [RAG use case](/llm-concept-atlas/use-cases/rag-question-answering/) for a real embedding retriever and prompt assembly. Try removing the source in the lab above.

## When to use it

- Use RAG for answers that must reflect a changing document collection and show sources.
- Use direct classification or search when the user needs only a label or document list.

## Limits and common mistakes

- Retrieved context does not force a model to obey it. Verify citations and support.
- RAG quality depends on document freshness, chunking, retrieval, context limits, and generation together.
