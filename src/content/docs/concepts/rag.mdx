## Definition and intuition

Retrieval-augmented generation supplies retrieved external evidence to a language model before it drafts an answer. Ingestion, ranking, context packing, generation, and support checking are separate stages with separate failure modes.

Read this lesson as a sequence: identify the input, follow the transformation, inspect the result, and explain a failure. The worked example and recorded lab below make those boundaries visible.

## How it works

### A concrete source-to-answer path

L12 indexes original source-preserving passages. L13 retrieves actual candidates, removes duplicate documents, packs whole passages with IDs into a native-token budget, and invokes a pinned local generator. The original question and the actual selected text appear in the saved prompt. Reference answers and support IDs are evaluation inputs, never hidden additions to the model context.

### Evidence is data

Imported documents can contain instructions, outdated rules, or unrelated but similar text. The generator is instructed to treat evidence as untrusted data. This wording is not an isolation guarantee. The fixture includes an explicitly untrusted imported note for inspection; the workflow has no shell, private-file, or write tools. A downstream support check must still distinguish a policy fact from a command quoted inside a source.

### Advanced retrieval

The connected workflow compares a baseline with generated rewriting, complementary queries, dependent follow-up queries, source routing, and a bounded source-selection controller. Their actual search strings, observations, and work are visible. They are purpose-built mechanism probes, including inspected prototypes, not an untouched generative-generalization benchmark. A more elaborate workflow can retrieve worse evidence or propagate an earlier mistake.

## Worked example

The Saturday-hours baseline produces the correct 17:30 draft without a citation. An absent swimming-pool question still retrieves nearby opening-time passages and can produce an unsupported time. An application threshold may withhold a draft, but a hidden hallucination is not a grounded model answer. Inspect raw text, selected evidence, and the final display decision independently.

## Implement it

From the repository root, run `python3 scripts/run-examples.py --id e6-rag --offline` after installing the foundation environment. This standard-library example calculates the stated mechanism or replays hash-linked actual model evidence from the published snapshot. It does not perform a fresh neural-model inference. The complete local/CI implementation and execution contract are linked immediately below.

{/* example:e6-rag:start */}

```python
import json
from pathlib import Path
data = json.loads(Path('src/data/retrieval-results.json').read_text())
row = next(r for r in data['grounded']['rows'] if r['id']=='eval-hours' and r['variant']=='baseline')
for source in row['context']:
    assert source['text'] in row['answer_call']['prompt']
print('actual context IDs:',[s['id'] for s in row['context']])
print('raw draft:',row['answer_call']['raw'])
print('model citations:',row['model_citations'])
print('application display:',row['display_answer'])
```

## When to use it

Use RAG when answers need a maintained document collection and inspectable sources. Search results alone may be sufficient for navigation; generation is useful when the task requires synthesis or a direct answer backed by evidence.

## Limits and common mistakes

Retrieval does not force faithfulness, and citation markers do not establish entailment. A source can be relevant yet insufficient. The local model is small and unreliable; the lab preserves failures instead of repairing answers with reference values or claiming production readiness.
