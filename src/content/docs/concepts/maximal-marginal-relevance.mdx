## Definition and intuition

Maximal marginal relevance (MMR) greedily selects relevant candidates while penalizing redundancy with already selected items. It is a selection rule that can diversify topic keywords or retrieved passages.

A topic described by translation, translations, and translated may repeat the same idea. MMR tries to reserve space for additional useful information. More variety is a tradeoff, not an automatic quality improvement.

## How it works

### State the parameter convention

Using BERTopic’s diversity d, choose the most relevant first candidate. For each later candidate i, score (1−d) × similarity(i,topic) − d × max similarity(i,j) over already selected j. Choose the highest score and repeat. Some papers or libraries call the relevance coefficient lambda; then lambda=1−d. Check which direction a control uses before interpreting it.

### A concrete selection step

Suppose translation has relevance 0.90 and is selected first. Translations has relevance 0.88 and similarity 0.98 to translation; evaluation has relevance 0.65 and similarity 0.20. At d=0.3 their scores are 0.322 and 0.395, so evaluation is preferred despite lower relevance. This illustrates penalizing redundancy. At d=0 later choices use relevance only; at d=1 later choices ignore relevance and can become unhelpfully different.

### Selection is not a new partition

The live arithmetic example uses invented fixed similarities so every choice can be checked. L08 separately runs the actual BERTopic MaximalMarginalRelevance module at 0.2 and 0.8. Document assignments remain unchanged. Selected terms keep their c-TF-IDF weights, so the displayed ranked list is not necessarily the chronological greedy selection trace. This distinction matters when comparing numerical scores.

## Worked example

In the recorded topic experiment, high diversity can reveal words such as soil or temperatures inside a group whose majority concerns summarization. That is a useful warning about mixed membership, not proof that the diverse description is superior. Read the underlying unrelated documents before deciding whether to rename or recluster the group.

## Implement it

This small mechanism uses Python’s standard library and illustrative values; it does not claim to run a pretrained model. Run `python3 scripts/run-examples.py --id discovery-maximal-marginal-relevance`. The connected workflow below supplies the actual model, data, and evaluation.

{/* example:discovery-maximal-marginal-relevance:start */}

```python
relevance = {"translations": 0.88, "evaluation": 0.65}
similarity_to_selected_translation = {"translations": 0.98, "evaluation": 0.20}
diversity = 0.3
scores = {
    term: (1 - diversity) * value - diversity * similarity_to_selected_translation[term]
    for term, value in relevance.items()
}
print({term: round(value, 3) for term, value in scores.items()})
assert max(scores, key=scores.get) == "evaluation"
```

## When to use it

Use MMR when a small displayed set would otherwise contain near duplicates. Choose the candidate pool and similarity model deliberately, tune the tradeoff using validation or human inspection, and retain relevant evidence even when a diverse alternative looks more novel.

## Limits and common mistakes

MMR is greedy and does not guarantee a globally optimal or factual selection. It depends on candidate quality and embedding similarities. Diverse keywords cannot repair incorrect cluster membership or establish that a generated topic name is supported.
