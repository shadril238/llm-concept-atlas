## Definition and intuition

Summarized memory compresses earlier conversation into a shorter note that is passed to later requests.

Chapter 7 combines model calls with templates, memory, and tools. Trace the inputs and outputs of each step so an error can be located rather than hidden inside a chain.

## Before you start

Read [Conversation memory](/llm-concept-atlas/concepts/conversation-memory/) first. You should be able to explain what information its output carries. Then return here and ask what extra problem **summarized memory** solves. This sequence matters because a plausible output can hide a missing prerequisite or a weak input representation.

## Theory: how it works

1. **Prepare:** Extract durable facts and unresolved goals from old messages
2. **Transform:** Write a compact summary with provenance and update rules
3. **Inspect:** Include the summary and recent turns in new prompts.

### The important distinction

A summary is a derived record that can drift from the source messages. Keep a distinction between confirmed facts, user preferences, and unresolved questions. Recompute or correct the summary when new turns contradict it instead of appending every new statement indefinitely.

## Worked example

A long support conversation becomes “User needs invoice for order 123; refund pending.” The summary saves tokens but must be updated if the refund resolves. Walk through the three stages above with that input: identify what is prepared, what changes, and which observation would show success. Then change one condition in the example. If the conclusion changes, the method is sensitive to that choice; if it does not, ask whether the example actually tests the mechanism.

## Implement it

**Setup:** Python 3; no packages or API key are needed. Save the following as `example.py` and run `python3 example.py`. It is a small deterministic illustration of the relevant calculation or data flow. It does not download a trained model.

```python
history = [("user", "My name is Sam"), ("assistant", "Hello Sam")]
history.append(("user", "What is my name?"))
print("\n".join(f"{role}: {text}" for role, text in history[-3:]))
```

**Expected output:**

```text
user: My name is Sam
assistant: Hello Sam
user: What is my name?
```

**What the code shows:** The slice keeps the last three messages and formats them for a future request. Earlier messages are absent unless the application explicitly stores and reinserts them. The [official chapter 7 notebook](https://github.com/HandsOnLLM/Hands-On-Large-Language-Models/tree/main/chapter07) develops the corresponding model-based implementation.

## Limits and common mistakes

- Summaries can omit nuance or preserve mistakes and must be checked against source messages.
- **Failure to look for:** An incorrect summary says the user agreed to a refund and later steps rely on that claim.

A teaching demo usually holds data and model behavior fixed so one mechanism is visible. Real systems face noisy inputs, changing distributions, and edge cases. Test examples that should fail as well as examples that should succeed, and inspect the intermediate stage that causes the error.
