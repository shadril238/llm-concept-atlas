## Definition and intuition

Masked language modeling (MLM) trains an encoder to predict selected original tokens from a corrupted token sequence. Continued pretraining applies that objective to a permitted domain corpus before evaluating a downstream task.

Follow the input, objective, update, and evaluation as separate steps. The worked example and experiment below connect the explanation to an inspectable implementation.

## How it works

### Separate selection, replacement and targets

The actual collator selects eligible tokens with probability 15%. Among selected positions its nominal replacement policy is 80% [MASK], 10% random vocabulary token and 10% unchanged. All selected positions still target the original token. Other positions, special tokens and padding receive label −100. An unchanged observed ID does not reveal whether it came from the unchanged branch or a coincidental random draw.

### Adapt with a real held-out protocol

Only the two hundred training review texts enter MLM updates; task labels and test/challenge text do not. Fixed validation masks provide a stable token-weighted loss for checkpoint selection. A separate two-step smoke run checks execution; a sixty-step run provides the evaluated adaptation. Dynamic masks vary training supervision, while fixed validation masks avoid comparing different corruption draws at each checkpoint.

### Control the downstream initialization

An MLM checkpoint omits BERT’s sequence pooler. Loading it naively for classification would initialize a new pooler and confound the comparison. The lab first creates identical base classifiers, preserves their original pooler/head, and transfers only adapted embeddings/encoder weights. Equal initial pooler/head hashes are asserted before matched downstream training and test evaluation.

## Worked example

A selected token left unchanged is not an ignored token: the label remains its original ID and contributes to loss. Toggle eligible positions in the teaching mask to see the distinction. Then compare the actual pretrained versus MLM-adapted downstream classifier. A plausible fill-mask completion alone would not establish a useful classifier gain.

{/* example:e7-masked-language-modeling:start */}

```python
import json
from pathlib import Path
data = json.loads(Path('src/data/training-results.json').read_text())['mlm']
trace = data['mask_trace']
for row in trace:
    if row['special_or_padding']:
        assert row['label'] == -100
    if row['label'] != -100:
        assert row['label'] == row['original_id']
print('selected actual targets:', sum(r['label'] != -100 for r in trace))
print('same initial downstream head/pooler:', data['downstream'][0]['head_pooler_initial_sha256'] == data['downstream'][1]['head_pooler_initial_sha256'])
print('two-step smoke / evaluated steps:', data['smoke']['steps'], data['evaluated']['steps'])
```

## When to use it

Use continued pretraining when permitted target-domain language differs from the starting encoder’s distribution. Choose checkpoints on a declared validation objective and test the downstream benefit.

## Limits and common mistakes

No selected tokens makes a mean token loss undefined, so the trainer checks for targets. WordPiece token masking and whole-word masking differ. A short original checkpoint may have unknown pretraining overlap with review data; no contamination-free benchmark or universal benefit is claimed.

Author execution checks tensor/mask contracts, actual parameter updates, split provenance and artifact reload. It does not constitute independent lesson acceptance. Keep training quality, task quality, runtime and generalization claims separate.
