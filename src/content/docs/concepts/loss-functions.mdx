## Definition and intuition

**Loss functions**: A loss function turns prediction or ranking errors into a scalar signal used to update model parameters.

Chapter 10 trains representations by choosing which examples should be close or far apart. The construction of positive and negative pairs is part of the learning objective.

## Before you start

Read [Contrastive learning](/llm-concept-atlas/concepts/contrastive-learning/) first. You should be able to explain what information its output carries. Then return here and ask what extra problem **loss functions** solves. This sequence matters because a plausible output can hide a missing prerequisite or a weak input representation.

## Theory: how it works

1. **Prepare:** Choose a loss whose target matches the intended behavior
2. **Transform:** Compute loss from model outputs and labeled examples
3. **Inspect:** Differentiate it to update trainable weights and monitor held-out quality.

### The important distinction

A classification loss compares predicted class probabilities with labels; a contrastive loss compares relative similarities among examples. The gradient tells the optimizer how to change weights, but the chosen objective determines what improvement means. A smaller number is only valuable if the objective matches the application.

## Worked example

A contrastive loss decreases when a positive sentence pair outranks negatives. A classification loss instead rewards the right class label, so the two objectives can shape different representations. Walk through the three stages above with that input: identify what is prepared, what changes, and which observation would show success. Then change one condition in the example. If the conclusion changes, the method is sensitive to that choice; if it does not, ask whether the example actually tests the mechanism.

## Implement it

**Setup:** Python 3; no packages or API key are needed. Save the following as `example.py` and run `python3 example.py`. It is a small deterministic illustration of the relevant calculation or data flow. It does not download a trained model.

```python
from math import exp, log
positive_similarity = 0.8
negative_similarities = [0.2, 0.4]
all_scores = [positive_similarity, *negative_similarities]
loss = -log(exp(all_scores[0]) / sum(exp(x) for x in all_scores))
print(round(loss, 3))
```

**Expected output:**

```text
0.797
```

**What the code shows:** The positive score competes with two negative scores inside a softmax. The negative logarithm is smaller when the positive takes more of the probability mass. The [official chapter 10 notebook](https://github.com/HandsOnLLM/Hands-On-Large-Language-Models/tree/main/chapter10) develops the corresponding model-based implementation.

## Limits and common mistakes

- Low training loss can coexist with overfitting or a mismatch to the real goal.
- **Failure to look for:** The model optimizes easy pair separation but fails on hard near-miss search results.

A teaching demo usually holds data and model behavior fixed so one mechanism is visible. Real systems face noisy inputs, changing distributions, and edge cases. Test examples that should fail as well as examples that should succeed, and inspect the intermediate stage that causes the error.
