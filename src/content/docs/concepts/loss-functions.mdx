## Definition and intuition

A loss function turns model outputs and a supervision contract into a scalar objective for optimization. For sentence embeddings, pair classification, cosine regression and multiple-negatives ranking use different labels and expose different inference behavior.

Follow the input, objective, update, and evaluation as separate steps. The worked example and experiment below connect the explanation to an inspectable implementation.

## How it works

### Softmax pair classification

The SBERT-style classifier consumes [u,v,|u−v|], learns class logits, and minimizes cross entropy against a discrete relation label. The book uses three NLI classes. L15 explicitly adapts this to two author-defined service relations, same-intent versus different-intent; it is not a relabeled NLI benchmark. The classifier has its own trainable weights, and the optimizer includes them as well as the shared encoder.

### Cosine similarity regression

The pinned CosineSimilarityLoss computes mean squared error between cosine similarity and a numerical target: mean_i(cos(u_i,v_i)−y_i)^2. It is not simply 1−cos for every pair. A target of zero asks for orthogonality under this score, not maximum negative cosine. Our binary targets reflect the defined service relation; continuous human STS ratings require their own annotation scale.

### Multiple negatives ranking

MNR uses a matrix of anchor/candidate similarities, multiplies by a declared scale, and applies row-wise cross entropy with diagonal targets. In the pinned 5.1.2 configuration, scale is 20 and the loss is directional anchor→candidate; it is not automatically the symmetric CLIP objective. Batch composition determines the denominator and the negative assumptions. Validation retrieval MRR selects its saved checkpoint.

## Worked example

If cosine is 0.8 and target 1, regression squared error is 0.04. If target is 0, the same score yields 0.64. With alternative similarity 0.4 and scale 5, one-row ranking loss is about 0.127. The same positive score therefore produces different losses because the contracts differ. L15 checks the actual library outputs against independent arithmetic and verifies parameter changes.

```python
import sys
sys.path.insert(0, 'examples/foundations/src')
from atlas_foundations.e7.contracts import cross_entropy, mnr_loss
score = 0.8
print('regression toward one:', round((score - 1) ** 2, 4))
print('regression toward zero:', round(score ** 2, 4))
print('pair classification CE:', round(cross_entropy([2.0, 1.0], 0), 4))
matrix = [[0.8, 0.4], [0.3, 0.9]]
print('directional MNR mean:', round(mnr_loss(matrix, scale=5)['loss'], 4))
print('Different labels and denominators define different objectives.')
```

## When to use it

Choose a loss after specifying your data format and deployed scorer. Use regression for graded similarity targets, ranking for trustworthy positive retrieval pairs, and a pair classifier when relation classes are the task.

## Limits and common mistakes

Loss magnitudes across objectives are not a leaderboard. A lower number does not establish better retrieval, and false negatives make a ranking target wrong even when its tensor shape is valid.

Author execution checks tensor/mask contracts, actual parameter updates, split provenance and artifact reload. It does not constitute independent lesson acceptance. Keep training quality, task quality, runtime and generalization claims separate.
