## Definition and intuition

QLoRA combines a low-bit frozen base model with LoRA adapters so fine-tuning uses less memory.

Chapter 12 distinguishes pretraining, instruction tuning, and preference optimization. Efficient adapters change a subset of parameters; evaluation still decides whether behavior improved.

## Before you start

Read [LoRA](/llm-concept-atlas/concepts/lora/) first. You should be able to explain what information its output carries. Then return here and ask what extra problem **QLoRA** solves. This sequence matters because a plausible output can hide a missing prerequisite or a weak input representation.

## Theory: how it works

1. **Prepare:** Quantize the base weights with a supported low-bit format
2. **Transform:** Attach and train LoRA adapters while keeping the base frozen
3. **Inspect:** Evaluate quality, memory, and inference compatibility.

### The important distinction

QLoRA commonly keeps a quantized base frozen while gradients flow into higher-precision LoRA adapters. Low-bit storage reduces base-weight memory, but activations and optimizer state still consume resources. Compatibility of quantization kernels, adapter merge, and deployment format must be tested on the target hardware.

## Worked example

A base model that cannot fit for full fine-tuning may fit in 4-bit form while the small adapter remains trainable. The hardware and kernels must support the chosen setup. ## Implement it

**Setup:** Python 3; no packages or API key are needed. Save the following as `example.py` and run `python3 example.py`. It is a small deterministic illustration of the relevant calculation or data flow. It does not download a trained model.

```python
base = [[1.0, 0.0], [0.0, 1.0]]
a = [[0.1], [0.2]]
b = [[0.3, -0.1]]
adapted = [[round(base[i][j] + a[i][0]*b[0][j], 3) for j in range(2)] for i in range(2)]
print(adapted)
```

**Expected output:**

```text
[[1.03, -0.01], [0.06, 0.98]]
```

**What the code shows:** The nested list comprehension adds a rank-one outer product to a frozen 2-by-2 matrix. For wider matrices, the small inner rank is what saves trainable parameters. The [official chapter 12 notebook](https://github.com/HandsOnLLM/Hands-On-Large-Language-Models/tree/main/chapter12) develops the corresponding model-based implementation.

## When to use it

Use it to fine-tune larger models on constrained hardware when quality remains acceptable. Choose it when the input and output in your application match those assumptions. Compare the simplest useful baseline first, then measure whether the additional complexity improves the metric that matters to readers or users. ## Limits and common mistakes

- Quantization and adapter settings add complexity, and speed gains are not guaranteed.
- **Failure to look for:** Training fits in memory but inference fails because the deployment stack cannot load the same quantized format.

A teaching demo usually holds data and model behavior fixed so one mechanism is visible. Real systems face noisy inputs, changing distributions, and edge cases. Test examples that should fail as well as examples that should succeed, and inspect the intermediate stage that causes the error.
