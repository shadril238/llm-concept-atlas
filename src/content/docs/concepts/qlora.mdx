## Definition and intuition

QLoRA trains high-precision low-rank adapters through a frozen quantized base model. The original method combines four-bit NormalFloat (NF4), double quantization and paged optimizers to reduce memory. A four-bit inference file without adapter optimization is not a QLoRA training run.

## Theory: how it works

### NF4 and blockwise quantization

Four bits index sixteen representable values. NF4 uses a nonuniform codebook motivated by normally distributed weights, with more resolution near common values. Blocks have their own scaling metadata so one outlier does not force one global range across the whole model. During multiplication, kernels reconstruct an approximation at the chosen compute precision; integer storage and arithmetic dtype are different contracts.

Not every tensor becomes four-bit. Embeddings, normalization, output heads, quantization constants, padding/alignment and temporary workspaces add memory. Trainable adapters need their own weights, gradients and optimizer state. Base weights remain frozen: gradients flow through the effective quantized linear operation into adapter parameters, rather than performing ordinary full-gradient updates to four-bit codes.

### QLoRA memory

Double quantization compresses some block-scale metadata with another quantizer; it is not “quantize the same weights twice until they are two-bit.” Paged optimizers use managed memory to handle some memory spikes. They are not activation checkpointing, and they do not make unlimited context lengths fit. Exact backend support, precision, batch size and sequence length need real verification.

The optional E8 entrypoint uses bitsandbytes 0.48.2 on supported Linux CPU, NF4 with nested quantization, float32 compute and float32 adapters. It inspects actual Linear4bit quantization state, verifies frozen bytes and nonzero updates, selects among trained checkpoints using validation completion loss, and saves/reloads the adapter. It uses ordinary torch AdamW, so it does not certify paged CUDA optimization or the book's TinyLlama/UltraChat scale. macOS/MPS is explicitly rejected by that entrypoint. A supported GPU run remains an open E8 completion requirement.

### Merging a quantized adaptation

An adapter trained against an NF4 approximation has learned around that effective base. Dequantizing reconstructs those approximations in floating point; it does not restore the original checkpoint values. The optional profile dequantizes a fresh quantized base before attaching the trained adapter and merging, then compares logits and reloads the saved floating model. Attaching the same adapter to the original unquantized base is a different function. Requantizing a merged model adds another approximation and needs new evaluation.

### The important distinction

Read the mechanism and the actual workflow together. A small calculation checks arithmetic; the connected training record checks optimization and artifacts; heldout task results check a separate quality claim.

## When to use it

Use quantized adapter training when frozen-base storage is a bottleneck and the selected backend supports the needed kernels and gradients. Start with a reproducible small profile, keep reference outputs and quantify quality changes. Avoid applying CUDA installation recipes to MPS or promising a model fits from parameter bits alone.

## Limits and common mistakes

The evaluated instruction subset has32 training,8 validation and8 test source contexts. Pretraining overlap is unknown. Repeated views of these test outputs are not a new independent benchmark. Preserve failed and length-limited answers, exact base/tokenizer identity and data provenance when transferring the workflow. The book's larger TinyLlama/CUDA settings require their own supported hardware execution; the small profiles do not certify them.

<details>
<summary>Does dequantization recover the original pretrained weight exactly?</summary>

No. It reconstructs the quantized approximation at a higher storage precision. Lost information is not recovered merely by changing dtype.

</details>
