## Definition and intuition

Multimodal chat combines image inputs with conversation messages so a model can generate successive visual answers. The application must serialize the conversation and supply image tensors each time; the model does not automatically retain an image or verified facts between stateless calls.

Read this lesson as a sequence: identify the input, follow the transformation, inspect the result, and explain a failure. The worked example and recorded lab below make those boundaries visible.

## How it works

### Actual generated history

The chat lab uses a pinned 256M instruction model and its own processor/template. The first turn receives the photograph and a description request. The application appends the actual generated answer before forming the second question about an exact drink price. It never replaces that answer with a hand-authored ideal conversation. Continuation-only decoding removes the prompt token prefix before displaying generated text.

### Input views and history can change the answer

Image splitting/tiling is a processor setting, not a text instruction. Its actual setting and resulting tensor shapes are inspected. If preprocessing changes the first response, that changed generated history can also influence later turns. Such a mediated conversation comparison should not be described as a single direct-effect test on the final answer.

### Visual support remains necessary

A photograph of a cup can support visible-object descriptions, but an exact price requires visible price evidence or an external source. An apparently helpful numeric answer can be invented. Inspect the original photo, processor view, previous generated messages, final question, and actual continuation before deciding whether the model answered from evidence.

## Worked example

The final question explicitly asks for an unknown response if the price is not shown. Compare what the actual model says with the photograph. A correct abstention on one input view does not guarantee all configurations will abstain; an invented price on another view is a useful failure to preserve, not a reason to silently replace the answer.

## When to use it

Use multimodal conversation when follow-up questions need both visual input and prior task context. Keep actual generated history, image identifiers, preprocessing settings, and token budgets so errors can be attributed.

## Limits and common mistakes

This small local model is an explicitly separate adaptation, not the genuine BLIP-2 backend. It can hallucinate, overinterpret, or truncate responses. Conversation memory belongs to the application, and a fluent second-turn answer does not establish verified visual understanding.

No. Recognizing a category does not supply the missing price evidence. A confident amount would still be unsupported.
