## Definition and intuition

**Pretraining and SFT**: Pretraining learns broad text patterns, while supervised fine-tuning teaches a model to follow example input-output tasks.

Chapter 12 distinguishes pretraining, instruction tuning, and preference optimization. Efficient adapters change a subset of parameters; evaluation still decides whether behavior improved.

## Before you start

Read [Decoder-Only Model](/llm-concept-atlas/concepts/decoder-only/) first. You should be able to explain what information its output carries. Then return here and ask what extra problem **pretraining and sft** solves. This sequence matters because a plausible output can hide a missing prerequisite or a weak input representation.

## Theory: how it works

1. **Prepare:** Train a base model on broad token prediction
2. **Transform:** Assemble instruction-response examples for supervised fine-tuning
3. **Inspect:** Evaluate the adapted behavior separately from base language modeling.

### The important distinction

The pretraining objective typically predicts tokens over broad text, while SFT uses curated prompt-response pairs to teach interaction patterns. SFT changes weights persistently, unlike few-shot prompting. It can improve instruction following but does not verify facts contained in the generated response.

## Worked example

A base model may continue “Write an email” as more web text. After SFT on instructions and responses, it more often drafts the requested email, although correctness still needs checking. Walk through the three stages above with that input: identify what is prepared, what changes, and which observation would show success. Then change one condition in the example. ## Implement it

**Setup:** Python 3; no packages or API key are needed. Save the following as `example.py` and run `python3 example.py`. It is a small deterministic illustration of the relevant calculation or data flow. It does not download a trained model.

```python
weight = 0.2
for target in [1.0, 1.0, 0.0]:
    prediction = weight
    weight -= 0.1 * 2 * (prediction - target)
print(round(weight, 3))
```

**Expected output:**

```text
0.39
```

**What the code shows:** The toy loop measures a squared-error gradient for one scalar weight and applies a small update. Actual pretraining uses many parameters, batches, and a token-level objective. The [official chapter 12 notebook](https://github.com/HandsOnLLM/Hands-On-Large-Language-Models/tree/main/chapter12) develops the corresponding model-based implementation.

## When to use it

Use SFT when a capable base model needs a specific interaction format or task behavior. Choose it when the input and output in your application match those assumptions. Compare the simplest useful baseline first, then measure whether the additional complexity improves the metric that matters to readers or users. Record the model, data version, and decision threshold when applicable so results can be reproduced.

## Limits and common mistakes

- SFT can teach style or shortcuts without improving factual knowledge.
- **Failure to look for:** A model produces polished answers after SFT but invents details outside its evidence.

A teaching demo usually holds data and model behavior fixed so one mechanism is visible. Real systems face noisy inputs, changing distributions, and edge cases. Test examples that should fail as well as examples that should succeed, and inspect the intermediate stage that causes the error.
