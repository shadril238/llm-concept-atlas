## Definition and intuition

Recommendation embeddings represent items or users through learned vectors so that a scoring rule can rank candidates. In a playlist example, co-occurring song IDs supply the training signal rather than lyrics or audio.

A listener has heard three songs in a session. You need to rank a new song without returning one already observed. A popularity list is a useful baseline, while learned co-occurrence vectors may capture narrower patterns.

## How it works

Treat songs as vocabulary items and playlists as sequences. Center/context pairs are drawn from training playlists only. A skip-gram negative-sampling model learns input and context tables; the demo ranks candidates with cosine to a pooled vector of observed songs.

Split whole sessions before fitting. In validation/test, hide the last song, form the query from the preceding songs, and exclude already observed items from candidates. Fit popularity counts on training sessions only. A public item catalog can define IDs without exposing held-out interactions.

Recall@3 asks whether the hidden target appears in the first three results. Reciprocal rank is 1 divided by the target rank; mean reciprocal rank averages it over queries. These metrics are meaningful only with a declared candidate pool, target policy, and eligibility denominator.

## Worked example

If the target ranks second, that query contributes 1 to Recall@3 and 0.5 to MRR. If it ranks fourth, it contributes 0 to Recall@3 and 0.25 to MRR. Returning an already observed song would violate this exercise’s recommendation contract even if the cosine were high.

## Implement it

Run the small mechanism from the repository root with `python3 scripts/run-examples.py --id foundation-recommendation-embeddings`. Its values are illustrative; it isolates the stated operation rather than pretending to load a trained model.

{/* example:foundation-recommendation-embeddings:start */}

```python
observed = {"song-a", "song-b"}
catalog = ["song-a", "song-b", "song-c", "song-d"]
candidates = [song for song in catalog if song not in observed]
rank = 2
print(
    "eligible:", candidates, "recall@3:", int(rank <= 3), "reciprocal rank:", 1 / rank
)
```

## When to use it

Use co-occurrence embeddings when interaction patterns are available and a collaborative signal is appropriate. Compare against popularity, inspect rare-item coverage, and add metadata/content features or a transparent fallback for cold starts. Do not infer causal preference from co-occurrence alone.

## Limits and common mistakes

Our fictional themes make a deliberately easy controlled task. A perfect plot would not establish real listening quality. New songs have no learned interaction vector; a random allocated row must not be presented as a meaningful recommendation. Popularity bias and repeated exposure can dominate observed interactions.
