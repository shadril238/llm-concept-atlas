## Definition and intuition

Recommendation embeddings put users and items in a shared space so likely preferences can be estimated by proximity.

Chapter 2 follows text into tokens and vectors. The shape and training objective of a representation determine which comparisons are meaningful.

## Before you start

Read [Text Embedding](/llm-concept-atlas/concepts/text-embedding/) first. You should be able to explain what information its output carries. Then return here and ask what extra problem **recommendation embeddings** solves. This sequence matters because a plausible output can hide a missing prerequisite or a weak input representation.

## Theory: how it works

1. **Prepare:** Gather interaction signals such as plays or clicks
2. **Transform:** Learn user and item vectors from observed and sampled interactions
3. **Inspect:** Rank candidate items and evaluate on held-out behavior.

### The important distinction

A dot product between a user vector and an item vector can serve as a preference score, but observed interactions are not random samples. Exposure bias means an unclicked item might simply never have been shown. Evaluate with held-out interactions and account for popularity before interpreting a vector as personal taste.

## Worked example

A listener who plays two similar songs may have a vector near both songs. A newly added song with few interactions may be difficult to place reliably. Walk through the three stages above with that input: identify what is prepared, what changes, and which observation would show success. Then change one condition in the example. ## Implement it

**Setup:** Python 3; no packages or API key are needed. Save the following as `example.py` and run `python3 example.py`. It is a small deterministic illustration of the relevant calculation or data flow. It does not download a trained model.

```python
from math import sqrt
a, b = (0.8, 0.6), (0.7, 0.7)
dot = sum(x*y for x, y in zip(a, b))
cosine = dot / (sqrt(sum(x*x for x in a)) * sqrt(sum(y*y for y in b)))
print(round(cosine, 3))
```

**Expected output:**

```text
0.99
```

**What the code shows:** The code takes a dot product, divides by both vector lengths, and prints a cosine score. Change a coordinate to see how the direction changes the comparison. The [official chapter 2 notebook](https://github.com/HandsOnLLM/Hands-On-Large-Language-Models/tree/main/chapter02) develops the corresponding model-based implementation.

## When to use it

Use embeddings to rank many items when sparse interaction patterns contain a reusable signal. Choose it when the input and output in your application match those assumptions. Compare the simplest useful baseline first, then measure whether the additional complexity improves the metric that matters to readers or users. Record the model, data version, and decision threshold when applicable so results can be reproduced.

## Limits and common mistakes

- Clicks reflect exposure and position as well as preference, and cold-start items lack evidence.
- **Failure to look for:** A popular item appears universally relevant because training data mostly showed it, not because every user prefers it.

A teaching demo usually holds data and model behavior fixed so one mechanism is visible. Real systems face noisy inputs, changing distributions, and edge cases. Test examples that should fail as well as examples that should succeed, and inspect the intermediate stage that causes the error.
