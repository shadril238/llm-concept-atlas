## Definition and intuition

A Vision Transformer converts image pixels into a sequence of patch representations, adds positional information, and applies attention-based encoder blocks. Patch size and input resolution determine the visible sequence before any semantic image embedding is produced.

Read this lesson as a sequence: identify the input, follow the transformation, inspect the result, and explain a failure. The worked example and recorded lab below make those boundaries visible.

## How it works

### Pixels become learned sequence elements

For the verified OpenCLIP model, a 224×224 RGB tensor is divided into 32×32 patches. Each patch contains 3×32×32 = 3072 normalized values. A learned linear map projects each patch to 768 values. The implementation’s convolution with kernel/stride 32 performs that same operation; the lab independently unfolds actual pixels and checks the projection numerically.

### Position and pooling matter

A 7×7 grid provides 49 patches. Prepending a learned image class token gives 50 sequence elements, each with learned positional information. Attention mixes information across those positions. The final projected 512-dimensional image representation is different from a raw patch vector or an average RGB color. This checkpoint’s text encoder pools its end-of-text representation; it does not use the image class token to separate text from images.

### Architecture is checkpoint-specific

BLIP-2 uses a different vision encoder and patch configuration, so the OpenCLIP 7×7 grid must not be reused as its claimed trace. L14 records each actual model’s tensor shapes. Changing image resolution, cropping, interpolation, or patch size changes the input sequence or what pixels survive. A visually attractive preview is not proof that the displayed pixels match the processor tensor.

## When to use it

Use this trace to understand image encoders, resolution costs, cropping sensitivity, and how vision features feed retrieval or generation. Inspect the checkpoint configuration rather than assuming every ViT uses the same patch grid.

## Limits and common mistakes

A patch is not a detected object, and a learned coordinate is not a human label such as eye or price. Attention mixing and learned projections are essential. This lab performs frozen inference and a shape/projection check, not vision-model training.

## Check your understanding

<details>
<summary>Why are there 50 sequence positions rather than 49?</summary>

The 49 projected patches are joined by one learned image class token, which also receives positional information.

</details>

<details>
<summary>Can the displayed first eight projection values represent the entire patch embedding?</summary>

No. They are an inspection slice of a 768-dimensional learned representation; the full model uses every coordinate.
