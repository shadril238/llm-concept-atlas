## Definition and intuition

Language AI is the use of computational models to represent, classify, retrieve, transform, or generate language. A useful system definition names its input, output, and success criterion before naming a model.

A library receives a support message. It could route the message to a team, retrieve a policy, or draft a reply. These are three different products even though all accept text. Choosing a chat model first can hide the simpler task you actually need.

## How it works

A representation model turns an input into useful numeric features. A classifier maps features to a fixed label set. A retriever ranks existing items. A generator predicts a sequence of new tokens. A product can combine these roles, but its evaluation should retain the distinction.

The historical progression addressed different bottlenecks: count vectors represented documents without word order; learned word vectors shared information across words; recurrent encoder-decoder models handled sequences; attention exposed relevant source states; transformers made attention central and processed available positions in parallel. These developments did not make earlier methods useless.

Pretraining uses broad data and a learning objective to fit parameters. Task adaptation changes those parameters or adds task-specific components. In-context examples instead change the input while parameters remain fixed. A fluent reply can fail the user’s task, so test the system-level outcome as well as the model output.

### The important distinction

A demonstration with a hardcoded routing rule is a software baseline, not a trained model.

## Worked example

For “I cannot sign in,” routing might output ACCOUNT, retrieval might return a reset-policy document, and drafting might produce a paragraph. A routing error is a wrong class; a retrieval error is missing evidence; a drafting error might invent an unsupported reset step. Counting pleasant paragraphs would not evaluate the first two tasks.

## When to use it

Use classification for stable categories, retrieval when an existing source should be returned, and generation when a new sequence is needed. Start with a measurable baseline and the smallest adequate output. A model family is a means to that goal, not a product specification.

## Limits and common mistakes

A demonstration with a hardcoded routing rule is a software baseline, not a trained model. A generated explanation of a policy is not evidence that the policy exists. Inspect data provenance and include an absent-answer case before making a reliability claim.
