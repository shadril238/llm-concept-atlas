## Definition and intuition

**Language AI** is the design of systems that work with human language: reading it, searching it, labeling it, or producing it. The task comes first. An email spam detector needs a label; a search engine needs a ranked list; a translator needs a new sentence. All three operate on language, but their outputs and success measures differ.

Think of language AI as a toolbox rather than one model. Rules, keyword search, statistical classifiers, representation models, and generators each solve different parts of a language problem.

## Before you start

No prior model knowledge is required. Start with the example and follow linked terms as you need them.

## How it works

1. **Choose an input and output.** For classification the input is text and the output is a fixed label. For generation both input and output can be text.
2. **Represent text.** Simple systems count words; neural systems tokenize text and turn token IDs into vectors.
3. **Learn or define a decision.** A rule can be handwritten; a model learns parameters from examples.
4. **Evaluate the real task.** Accuracy, retrieval relevance, and answer quality measure different things. A fluent answer may still be wrong.

The book starts with this history because tokenization, embeddings, and transformers solve different bottlenecks in that pipeline.

## Worked example

Suppose a support team receives “I cannot sign in.” A keyword rule can route messages containing “sign in” to account support. A classifier might learn that “login failed” means the same thing even without that phrase. A generator could draft a reply, but should not be used as the sole authority for account policy.

## Implement it

**Setup:** Python 3; no packages or API key needed. Save this as `example.py` and run `python3 example.py`. This is a small teaching model, not a pretrained neural network.

```python
def route(message):
    text = message.lower()
    if 'sign in' in text or 'login' in text:
        return 'account support'
    return 'general support'

print(route('I cannot sign in'))
```

**Expected behavior:** `account support`

This is a deliberately small rule system. `lower()` normalizes case; the two phrase checks define a decision boundary. It needs no model download and exposes where a rule fails: “my password is broken” would be missed.

## When to use it

- Use a rule when the wording is stable and the consequence is easy to inspect.
- Use a trained classifier when many varied expressions map to a fixed set of labels.
- Use retrieval when the answer is in a document; use generation when you need new wording, ideally grounded in that document.

## Limits and common mistakes

- Language AI is broader than LLMs. A simple rule can be the right tool.
- Fluent output is not proof of understanding or factual correctness; evaluation must match the task.
