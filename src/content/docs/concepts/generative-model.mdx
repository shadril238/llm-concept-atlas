## Definition and intuition

A generative language model assigns probabilities to token sequences and can produce a continuation by repeatedly selecting the next token. It produces new text rather than simply returning an existing document.

You need a draft explanation rather than a fixed category. The model must produce a variable-length sequence, and the surrounding application must decide when to stop and how to check its claims.

## How it works

The tokenizer converts a prompt to IDs. The neural network processes the available prefix and the LM head produces one logit per vocabulary item. A decoding policy chooses a token; the loop appends it and repeats until a stopping condition.

A base model is trained primarily to continue text under its pretraining objective. An instruction-tuned model has undergone additional adaptation to prompts and responses. A chat template is part of a particular instruction model’s contract; attaching arbitrary role text to a base model does not transform it into an instruction-tuned assistant.

Generation controls belong to the sampling procedure: max_new_tokens bounds the continuation, greedy selection chooses a maximum, and seeded sampling introduces controlled randomness. Determinism on one software/device configuration is a reproducibility observation, not a universal cross-platform promise.

### The important distinction

Text can be grammatical but false or repetitive.

## When to use it

Use generation for drafting, transformation, or structured outputs whose correctness you can evaluate. If the user needs an exact known source, retrieval may be the primary operation. For constrained labels, compare with a classifier and validate the returned format.

## Limits and common mistakes

Text can be grammatical but false or repetitive. A short token limit can cut a word or thought. EOS is a learned special token, while a max-token cutoff is a software limit. Treat quoted documents as data; do not allow their embedded instructions to override the application’s task.

## Check your understanding

<details><summary>Why must you slice generated IDs rather than remove the prompt by string replacement?</summary><p>Token boundaries and normalization can make string matching unreliable. The generated tensor includes a known prefix length; slicing by that length identifies the actual continuation without deleting repeated words that happen to match the prompt.</p></details>

<details><summary>Your generated text stops after exactly 16 new IDs without EOS. What should you inspect?</summary><p>Inspect max_new_tokens and the generated-ID count. A software cutoff can stop a continuation mid-sentence; it does not establish that the model judged the response complete.</p></details>
