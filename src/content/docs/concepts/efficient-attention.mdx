## Definition and intuition

Efficient attention methods reduce computation, memory traffic, or stored state in different ways. Local visibility, shared key/value heads, and IO-aware exact kernels are separate design choices with separate correctness and quality implications.

A long-prefix decoder is limited by cache memory and memory movement. “Use efficient attention” is underspecified: changing which tokens are visible is not the same change as computing the same dense attention with less temporary storage.

## How it works

Multi-head attention has separate query and key/value heads. Multi-query attention shares one KV head across query heads. Grouped-query attention shares several KV heads across groups. For fixed sequence length, reducing KV-head count reduces ordinary cache storage without necessarily reducing query-head count.

Sliding/local attention restricts which positions can interact in a layer, changing the attention pattern. Stacking layers or mixing global/local layers changes how information can propagate, but does not make one local layer identical to full attention.

FlashAttention reorganizes exact attention computation around memory IO and tiling so the full score matrix need not be materialized in slow memory. It is not an approximation that simply discards low-weight tokens. Kernel availability, numerical rounding, and performance depend on hardware and configuration.

### The important distinction

A local-attention speed claim can conceal lost access to a relevant distant token.

## Worked example

For 4 layers, batch 1, 100 positions, head width 8, and 2-byte cache values, four KV heads require 51,200 bytes. Two KV heads require 25,600 and one requires 12,800, counting keys and values. This estimates cache tensors only, not model weights or all temporary memory.

### Grouped-query attention

With eight query heads and two KV heads, each KV head can serve a group of four query heads. Queries still compute distinct scores, while stored key/value state is shared within each group. The mapping and projection weights belong to the architecture; simply deleting heads from an arbitrary checkpoint is not a verified conversion.

## Implement it

Run the small mechanism from the repository root with `python3 scripts/run-examples.py --id foundation-efficient-attention`. Its values are illustrative; it isolates the stated operation rather than pretending to load a trained model.

```python
layers, positions, width, bytes_per_value = 4, 100, 8, 2
for kv_heads in [4, 2, 1]:
    size = 2 * layers * kv_heads * positions * width * bytes_per_value
    print("KV heads:", kv_heads, "cache bytes:", size)
```

## When to use it

Choose an architecture and kernel based on the declared task, device, context length, and measured costs. Check output correctness before benchmarking a cache/kernel path. The CPU cache lab measures its own float64 configuration rather than claiming a GPU FlashAttention speedup.

## Limits and common mistakes

A local-attention speed claim can conceal lost access to a relevant distant token. Fewer KV heads are not automatically a quality improvement. A faster GPU kernel result cannot be inferred from a tiny CPU timing, and a cache estimate is not total RAM usage.
