## Definition and intuition

Image captioning generates a text description conditioned on actual image pixels. It differs from choosing a matching caption embedding, and its descriptive details require visual support even when the sentence is fluent.

Read this lesson as a sequence: identify the input, follow the transformation, inspect the result, and explain a failure. The worked example and recorded lab below make those boundaries visible.

## How it works

### Generation has its own evidence boundary

A captioning model receives processed pixel tensors, uses its vision-language interface, and predicts text tokens. The source photograph, actual processor view, output cap, and unedited continuation are all part of the record. A caption that names a plausible object may reflect prior associations rather than something visible in this particular input.

### The genuine BLIP-2 path

L14 uses the actual Salesforce checkpoint for captioning/VQA in the supported heavy Linux CPU profile. Its vision, Q-Former, and language-projection outputs are recorded. Empty caption text is passed through the chosen processor contract explicitly, while text IDs remain integers and pixel values retain their declared floating type. A separate small chat backend is labeled as a different architecture.

### Inspect more than one notion of quality

Ask whether the description covers salient visible objects, invents properties, omits important details, or stops mid-sentence. A short output cap can truncate a useful description without proving a model has no further knowledge. Familiar sample photos do not make an independent benchmark, and the lab does not turn a favorable caption into a general quality claim.

## Worked example

The astronaut photograph can support a description of visible clothing and objects. It cannot establish every biographical fact, unseen event, or exact price merely from pixels. Compare the original and actual processed view before judging an omission. The recorded caption and VQA output remain unedited, including uncertain or unsupported details.

## When to use it

Use captioning to draft searchable descriptions or accessibility text with appropriate review. Tie any description to its actual input and task requirements, and retain a way to inspect the image that produced it.

## Limits and common mistakes

A caption is not a complete image interpretation, object detector, or factual database. Cropping and resizing can remove evidence. Human assessment of coverage and unsupported details remains necessary; no broad captioning accuracy or production accessibility certification is claimed.

## Check your understanding

<details>
<summary>How does caption generation differ from CLIP matching?</summary>

CLIP ranks compatibility between encoded inputs; captioning predicts a new text continuation conditioned on image features.

</details>

<details>
<summary>Why preserve an output-cap flag or setting?</summary>

It distinguishes possible truncation from a complete description and prevents treating a cut-off sentence as the model’s full intended answer.

</details>
