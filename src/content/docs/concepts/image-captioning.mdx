## Definition and intuition

Image captioning generates a short textual description from visual input.

Chapter 9 connects images and language. A shared vector space supports matching, while a generation model needs an additional path from visual features to text tokens.

## Before you start

Read [BLIP-2](/llm-concept-atlas/concepts/blip-2/) first. You should be able to explain what information its output carries. Then return here and ask what extra problem **image captioning** solves. This sequence matters because a plausible output can hide a missing prerequisite or a weak input representation.

## Theory: how it works

1. **Prepare:** Preprocess the image and extract visual features
2. **Transform:** Condition a text decoder on those features
3. **Inspect:** Evaluate whether the caption is accurate, useful, and appropriately specific.

### The important distinction

The decoder conditions on visual features and previously generated words, so each next token can carry uncertainty or inherited error. A caption should describe visible evidence at the desired level of detail. Human review is especially important when captions are used as accessibility text rather than only search metadata.

## Worked example

A photo of a brown dog on grass should produce a caption about the dog and grass, not an invented owner or location. One caption cannot capture every visible detail. Walk through the three stages above with that input: identify what is prepared, what changes, and which observation would show success. Then change one condition in the example. If the conclusion changes, the method is sensitive to that choice; if it does not, ask whether the example actually tests the mechanism.

## Implement it

**Setup:** Python 3; no packages or API key are needed. Save the following as `example.py` and run `python3 example.py`. It is a small deterministic illustration of the relevant calculation or data flow. It does not download a trained model.

```python
features = {"animal": 0.9, "road": 0.1}
if features["animal"] > features["road"]:
    print("An animal is in the picture.")
else:
    print("A road is in the picture.")
```

**Expected output:**

```text
An animal is in the picture.
```

**What the code shows:** The two hand-written feature scores choose a fixed sentence. This makes the feature-to-text decision visible, but a real captioner learns visual features and token generation. The [official chapter 9 notebook](https://github.com/HandsOnLLM/Hands-On-Large-Language-Models/tree/main/chapter09) develops the corresponding model-based implementation.

## When to use it

Use captions for accessibility drafts, image indexing, and media search with human review where needed. Choose it when the input and output in your application match those assumptions. Compare the simplest useful baseline first, then measure whether the additional complexity improves the metric that matters to readers or users. Record the model, data version, and decision threshold when applicable so results can be reproduced.

## Limits and common mistakes

- Captioners can omit small details or invent plausible context; reference metrics miss some errors.
- **Failure to look for:** The caption says “a dog in a park” although only an indoor rug is visible.

A teaching demo usually holds data and model behavior fixed so one mechanism is visible. Real systems face noisy inputs, changing distributions, and edge cases. Test examples that should fail as well as examples that should succeed, and inspect the intermediate stage that causes the error.
