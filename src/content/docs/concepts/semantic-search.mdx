## Definition and intuition

Semantic search ranks a collection using learned representations of meaning rather than relying only on shared words. Its output is a ranked set of candidate sources; it does not itself establish that a generated answer is true.

Read this lesson as a sequence: identify the input, follow the transformation, inspect the result, and explain a failure. The worked example and recorded lab below make those boundaries visible.

## How it works

### From information need to ranked evidence

Start with the question the reader needs answered. A retrieval model encodes the query and candidate passages in a compatible representation space. Similarity then orders candidates. A query about wheelchair access can match a passage about a ramp even without repeating the same words. Compatibility matters: equal vector widths from unrelated encoders do not create a shared semantic space.

### A lexical baseline remains useful

BM25 rewards query-term occurrences with inverse-document-frequency and length normalization. It is often helpful for exact identifiers, names, or rare terms. L12 compares this transparent baseline with actual masked-mean MiniLM embeddings and a pairwise reranker on the same original corpus. It does not assume learned search wins every query or that a single example proves general superiority.

### Define relevance before measuring success

The fixed corpus has 24 fictional documents and stable source IDs. Author judgments use grade two for directly useful evidence, grade one for related or partial evidence, and zero otherwise. L12 reports 16 evaluation queries, including two with no answer evidence, separately from six design queries. The stricter support-ID set for QA is different from topical relevance. A related result can improve a retrieval metric while remaining insufficient for a complete answer.

## Worked example

For “Which entrance should a wheelchair visitor use?”, the access document supplies an east-entrance ramp. A wireless-network page may also mention an entrance or lobby without answering access needs. Inspect the actual BM25 and dense lists before deciding which representation helped. Then choose an absent swimming-pool question: the index still returns neighbors even though the collection contains no pool rule.

```python
import json
from pathlib import Path
data = json.loads(Path('src/data/retrieval-results.json').read_text())
query = next(q for q in data['retrieval']['queries'] if q['id']=='eval-access')
print(query['text'])
for method in ['lexical','dense']:
    row = next(r for r in data['retrieval']['rows'] if r['id']==query['id'] and r['method']==method)
    print(method, row['document_ranking'][:3])
```

## When to use it

Use semantic retrieval to find evidence expressed with varied wording, such as a help-center article, policy clause, or research passage. Preserve source identity and compare a lexical baseline using representative queries and explicit judgments.

## Limits and common mistakes

Similarity is not a calibrated probability of relevance. The closest available vector can still be irrelevant. A small fictional corpus is a teaching experiment, not a benchmark for all document domains. Domain adaptation belongs to a separate training/evaluation workflow.

## Check your understanding

<details>
<summary>Why can an absent-answer query still return a top result?</summary>

Nearest-neighbor ranking orders the available collection; it does not prove that any item answers the query. A separate withholding or answerability policy needs evidence.

</details>

<details>
<summary>Why keep BM25 in the comparison?</summary>

Exact terms and identifiers can matter. A baseline reveals whether the learned encoder adds useful retrieval behavior on the same judged questions.

</details>
