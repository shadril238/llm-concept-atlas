## Definition and intuition

**Semantic search** ranks documents by a representation of meaning, not just exact word overlap. A query and candidate passages are embedded into vectors, then compared. This can retrieve a relevant passage even when it uses a paraphrase of the question.

It is a retrieval method, not a guarantee that the top result answers the question. A practical system must prepare documents, evaluate ranking quality, and often combine dense and keyword search.

## Before you start

Read [text embedding](/llm-concept-atlas/concepts/text-embedding/) first; return here when the key terms feel familiar.

## How it works

First divide source material into passages with usable titles and provenance. Encode each passage using an embedding model and store its vector. At query time, encode the question in a compatible way, compare it with indexed vectors, and return the top candidates. A reranker may then compare each query–passage pair more deeply before presenting results.

Cosine similarity or dot product can rank dense vectors; approximate nearest-neighbor indexes accelerate large collections. Keyword methods can outperform dense retrieval for exact IDs, names, or quoted phrases, so hybrid retrieval is often useful. Evaluate with labeled queries using recall at k or ranking metrics, not only a few satisfying examples.

## Worked example

Query: “How can I reduce my electric bill?” Passage A: “Ways to use less power at home.” Passage B: “How electricity prices are set.” Both are related, but A better satisfies the implied request for actions. A semantic retriever might surface both; a reranker can improve their order.

## Implement it

**Setup:** Python 3; no packages or API key needed. Save this as `example.py` and run `python3 example.py`. This is a small teaching model, not a pretrained neural network.

```python
from math import sqrt
query = (0.9,0.3)
docs = {'power-saving tips':(0.8,0.4), 'billing policy':(0.4,0.8)}
def cos(a,b):
    return sum(x*y for x,y in zip(a,b))/(sqrt(sum(x*x for x in a))*sqrt(sum(y*y for y in b)))
print(sorted(docs, key=lambda name: cos(query,docs[name]), reverse=True))
```

**Expected behavior:** `power-saving tips` ranks first for these invented vectors.

The vectors are illustrative, so the code tests ranking mechanics only. The [official chapter 8 notebook](https://github.com/HandsOnLLM/Hands-On-Large-Language-Models/tree/main/chapter08) uses embedding models. For a real system, encode both documents and queries with a compatible model and retain source IDs.

## When to use it

- Search knowledge bases with varied phrasing; retrieve candidate context for RAG.
- Add keyword retrieval when exact identifiers or rare names are critical.

## Limits and common mistakes

- Similarity can rank a related but unhelpful passage above the answer.
- A corpus cannot return information it never contained; document quality and chunking matter.
