## Definition and intuition

A task-specific text classifier is a pretrained representation model with a head trained to score a particular label set. Loading its tokenizer and label map correctly is part of using the model.

A sentiment model is already a learned decision function. It is not necessary to fit a new head merely to inspect its predictions, but its existing labels constrain what it can say. A positive/negative head cannot supply a reliable third “billing” label by renaming its output.

## How it works

### From states to label logits

A tokenizer produces IDs and an attention mask. The encoder builds contextual states; the checkpoint’s classification layers reduce those states to one logit per trained class. Softmax converts the logits into a distribution over that head’s classes. Architectures differ in their pooling and head details, so do not assume every model averages token states.

### Read the map rather than guessing

L07 loads the pinned SST-2 DistilBERT checkpoint in evaluation mode and reads config.id2label. It parses NEGATIVE/POSITIVE into canonical 0/1 and reorders probability columns accordingly. A different checkpoint might put positive in column 0 or include neutral. Treat an unknown mapping as a contract error instead of assuming the highest column has a universal meaning.

### Model selection

Start with the required labels and language, then inspect provenance, input length, artifact/license constraints, and representative validation cases. Compare a TF-IDF baseline before selecting a larger encoder. An encoder trained on tweets and one trained on movie sentences can have different domain behavior. The atlas uses a small CPU checkpoint as a reproducible choice, not a current best-model recommendation. A hub leaderboard cannot replace evaluation on your own input distribution.

## Worked example

Imagine model columns [POSITIVE, NEGATIVE] with probabilities [0.8,0.2], while the application expects [negative,positive]. The prediction is application ID 1, and canonical probabilities are [0.2,0.8]. Simply taking argmax and calling it the application ID would invert the result. The live comparison uses an explicitly inspected map even though this particular checkpoint happens to agree with 0/1.

## Implement it

This small mechanism uses Python’s standard library and illustrative values; it does not claim to run a pretrained model. Run `python3 scripts/run-examples.py --id discovery-task-specific-models`. The connected workflow below supplies the actual model, data, and evaluation.

{/* example:discovery-task-specific-models:start */}

```python
model_labels = {0: "POSITIVE", 1: "NEGATIVE"}
application_ids = {"negative": 0, "positive": 1}
model_scores = [0.8, 0.2]
canonical = [0.0, 0.0]
for column, label in model_labels.items():
    canonical[application_ids[label.casefold()]] = model_scores[column]
print("[negative, positive]:", canonical)
assert max(range(2), key=canonical.__getitem__) == 1
```

## When to use it

Use a task head when its trained label scheme matches the decision you need and held-out results justify it. Add an abstention/review policy for unfamiliar or uncertain cases. If you need new labels, collect evidence for a new head or evaluate a suitable zero-shot/generative method.

## Limits and common mistakes

Class scores are not an explanation and can be miscalibrated. L07 caps inputs at 256 tokens and records that truncation; a long review can lose its final judgment. Checkpoint prior training differs across methods, and possible overlap with review sources remains unknown.
