## Definition and intuition

Document chunking divides a source into bounded passages that can be encoded and retrieved while retaining enough surrounding context. Stable source IDs and exact offsets make each chunk attributable to the original text.

Read this lesson as a sequence: identify the input, follow the transformation, inspect the result, and explain a failure. The worked example and recorded lab below make those boundaries visible.

## How it works

### What a boundary can remove

A whole-document vector compresses several facts, while a single isolated sentence can lose the entity or qualification it refers to. A chunk that separates “laptops” from “three days” may damage retrieval or grounding. Overlap can preserve surrounding information, and adding the title can identify the subject. These are design choices to evaluate, not a universal optimal chunk size.

### Offsets are an evidence contract

The calculator uses end-exclusive Unicode code-point offsets, preserving text[start:end] exactly. Its sentence rule splits punctuation followed by whitespace and is explicitly not a general linguistic parser. A whitespace word is not a model token. The actual encoder checks native token counts. A production token-window implementation should use the tokenizer’s offset mapping and protect special tokens rather than assuming characters, words, and tokens are interchangeable.

### Overlap and evaluation

L12 compares two-sentence windows with one-sentence overlap against 24-word windows with six-word overlap, using the same document-level judgments. Several overlapping chunks can point to one document. Before scoring, the lab collapses repeated document IDs so duplicated evidence cannot inflate precision or AP. The chosen context packer also avoids spending its small generation budget on multiple chunks from the same document.

{/* example:e6-document-chunking:start */}

```python
import sys
sys.path.insert(0, 'examples/foundations/src')
from atlas_foundations.e6.retrieval import chunks
text = 'Laptop loans last three days. Return them to the desk. Book loans last twenty-one days.'
for part in chunks(text,size=2,overlap=1,mode='sentence'):
    assert text[part['start']:part['end']]==part['text']
    print(part['start'],part['end'],part['text'])
```

## When to use it

Use source-preserving chunks for long articles, manuals, and policy collections. Choose boundaries using the kinds of questions readers ask and measure both retrieval quality and downstream evidence sufficiency.

## Limits and common mistakes

Overlap adds storage and repeated context. Small chunks may lose qualifications; large ones may dilute a specific fact or exceed an input cap. The browser recalculates boundaries only; changing its controls does not re-encode passages or rerun the recorded benchmark.

## Check your understanding

<details>
<summary>Does overlap create additional relevant documents?</summary>

No. It creates additional passages from the same source. Document-level evaluation must collapse their IDs.

</details>

<details>
<summary>Why preserve offsets instead of only storing copied chunk text?</summary>

Offsets connect a result to its exact source span and allow attribution, coverage checks, and reconstruction after inspecting a failure.
