## Definition and intuition

Fine-tuning embeddings updates a pretrained encoder so its representations better reflect a target similarity or retrieval relation. It requires a data policy, objective, validation rule and deployable saved encoder, not merely a decreasing training loss.

Follow the input, objective, update, and evaluation as separate steps. The worked example and experiment below connect the explanation to an inspectable implementation.

## How it works

### Prepare the lifecycle

Version sentences, pair labels and source IDs. Split before pair generation, define positive/negative relationships, and inspect truncation/pooling. L15 uses 24 training sentences and task-specific gold pairs; validation and test have distinct sentences. Starting from pretrained tiny BERT means the language backbone is already learned, while this sentence-level objective is newly trained.

### Update and select deliberately

The transparent CPU loop includes the actual Sentence Transformers loss, AdamW, a declared learning rate and weight decay, gradient clipping, batch construction and validation checkpoints. First-step gradients and changed parameter tensors are inspected. The pair softmax classifier is optimized with the encoder; MNR uses one distinct intent per batch.

### Save what inference actually needs

Save tokenizer, transformer, pooling configuration and encoder weights together. A separate objective state is preserved when it contains extra training parameters. Reload the saved SentenceTransformer and compare embeddings numerically before publishing task scores. The frontend replays those verified results; it does not train when a reader changes an objective selector.

## Worked example

The fixed baseline test retrieval MRR is about 0.732 in the author run. Compare all three trained objectives on the same test queries and inspect the first misranked service. Validation selection may prefer an early step; completing more optimizer steps is not itself evidence that the final step should be deployed.

## Try the experiment

Predict an outcome before changing a control. Selectors replay actual saved training/evaluation runs; loss and mask calculators recalculate a declared teaching mechanism. They make no model or API requests in your browser.

## Implement it

From the repository root, install the foundation environment and run `python3 scripts/run-examples.py --id e7-fine-tuning-embeddings --offline`. The standard-library example below calculates a mechanism or checks the published actual evidence. Recorded-evidence replay is distinct from new optimization: the connected model lab supplies the complete source and fresh-training command.

{/* example:e7-fine-tuning-embeddings:start */}

```python
import json
from pathlib import Path
data = json.loads(Path('src/data/training-results.json').read_text())['embedding']
for row in data['conditions']:
    training = row['training']
    assert training['reload_verified'] and training['updated']
    changed = sum(group['changed_tensors'] for group in training['parameters'].values())
    print(row['kind'], 'selected step:', training['selected_step'], 'changed tensors:', changed)
    print('selection:', training['selection'])
print('Rerun embedding-training for new optimization; this replays recorded evidence.')
```

## When to use it

Use it when general-purpose vectors miss a domain’s relevance distinctions or terminology. Keep a frozen pretrained baseline and a cheap lexical baseline where appropriate.

## Limits and common mistakes

Overfitting, poor pair labels and catastrophic changes to general semantics can accompany domain gains. This lab has no out-of-domain regression suite, so it cannot establish preservation of broad general capabilities. Model scale and corpus size differ from the book’s examples.

Author execution checks tensor/mask contracts, actual parameter updates, split provenance and artifact reload. It does not constitute independent lesson acceptance. Keep training quality, task quality, runtime and generalization claims separate.
