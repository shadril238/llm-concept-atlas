## Definition and intuition

**Bag-of-words**: A bag-of-words representation counts which words occur in a document while discarding their order.

Chapter 1 separates ways to represent language from ways to generate it. Ask what information a representation keeps and what it throws away before choosing a model family.

## Before you start

Read [Language AI](/llm-concept-atlas/concepts/language-ai/) first. You should be able to explain what information its output carries. Then return here and ask what extra problem **Bag-of-words** solves. This sequence matters because a plausible output can hide a missing prerequisite or a weak input representation.

## Theory: how it works

1. **Prepare:** Choose a vocabulary and normalize the text
2. **Transform:** Count occurrences or mark whether each vocabulary word appears
3. **Inspect:** Compare count vectors with a simple classifier or similarity measure.

### The important distinction

The vector dimension equals the vocabulary size, and each coordinate stands for a particular token. Frequency counts may be replaced by binary presence or TF-IDF weighting, but none of those versions recover the order of the original sentence. That is why a bag-of-words baseline can be useful without being a full model of meaning.

## Worked example

“Dog bites person” and “Person bites dog” produce the same counts for dog, bites, and person, although their meanings differ. A spam filter can still learn from words such as “offer” and “winner”. Walk through the three stages above with that input: identify what is prepared, what changes, and which observation would show success. Then change one condition in the example. ## Implement it

**Setup:** Python 3; no packages or API key are needed. Save the following as `example.py` and run `python3 example.py`. It is a small deterministic illustration of the relevant calculation or data flow. It does not download a trained model.

```python
from collections import Counter
sentence = "red fox meets red bird".split()
counts = Counter(sentence)
print(dict(counts))
```

**Expected output:**

```text
{'red': 2, 'fox': 1, 'meets': 1, 'bird': 1}
```

**What the code shows:** The `Counter` object records a frequency for each word. Swap the word order and the dictionary stays the same, which demonstrates the lost information. The [official chapter 1 notebook](https://github.com/HandsOnLLM/Hands-On-Large-Language-Models/tree/main/chapter01) develops the corresponding model-based implementation.

## When to use it

Use it as a fast, interpretable baseline for simple text classification or search when word presence matters more than syntax. Choose it when the input and output in your application match those assumptions. Compare the simplest useful baseline first, then measure whether the additional complexity improves the metric that matters to readers or users. Record the model, data version, and decision threshold when applicable so results can be reproduced.

## Limits and common mistakes

- It cannot represent word order, negation scope, or unseen meanings without additional features.
- **Failure to look for:** A document about “not good” looks deceptively close to one about “good” if negation is ignored.

A teaching demo usually holds data and model behavior fixed so one mechanism is visible. Real systems face noisy inputs, changing distributions, and edge cases. Test examples that should fail as well as examples that should succeed, and inspect the intermediate stage that causes the error.
