## Definition and intuition

Position handling gives a transformer information about sequence order. Rotary Position Embedding (RoPE) applies position-dependent rotations to pairs of query/key coordinates, so their dot products can depend on relative offsets.

Without a position mechanism, a model can lose the distinction between different orderings of the same items. The coordinate-pair trace below makes the position-dependent rotation explicit.

## How it works

For one pair [a,b] at position m and angular frequency ω, rotation gives [a cos(mω) − b sin(mω), a sin(mω) + b cos(mω)]. Rotation preserves that pair’s Euclidean norm. Real RoPE uses several coordinate pairs with different frequencies.

Rotating both q and k makes (R_m q)·(R_n k) = q·R_(n−m) k for the same frequency convention. The inner product therefore exposes a relative-position relationship. That property does not mean a model is guaranteed to generalize to arbitrary context lengths.

Learned or sinusoidal absolute position vectors are commonly added to input states; RoPE instead operates inside attention on Q/K coordinates. Implementation conventions for pair arrangement and scaling vary. Cache positions must continue correctly as new tokens are appended.

### The important distinction

Angles require consistent units.

## Worked example

Rotate [1,0] by π/2 radians: the result is approximately [0,1]. With frequency 0.5 radians per position, position 2 yields angle 1 radian and approximately [0.5403,0.8415]. A shared position shift preserves the relative inner product of equally shifted query/key pairs.

## Implement it

Run the small mechanism from the repository root with `python3 scripts/run-examples.py --id foundation-positional-embeddings-and-rope`. Its values are illustrative; it isolates the stated operation rather than pretending to load a trained model.

{/* example:foundation-positional-embeddings-and-rope:start */}

```python
from math import cos, sin, pi

a, b, angle = 1.0, 0.0, pi / 2
rotated = [a * cos(angle) - b * sin(angle), a * sin(angle) + b * cos(angle)]
print([round(x, 6) for x in rotated])
assert abs(sum(x * x for x in rotated) - 1) < 1e-12
```

## When to use it

Use the paired-coordinate explorer to inspect angle, norm, and dot product. When adapting an architecture, verify pair ordering, frequency base, position indices, and trained context assumptions. The diagram uses one pedagogical frequency, not every dimension of a model.

## Limits and common mistakes

Angles require consistent units. Adding a scalar position to an embedding is not RoPE. Resetting positions in a cache incorrectly changes scores. A norm-preserving rotation does not preserve every pairwise score when positions differ, and RoPE alone does not validate long-context quality.
