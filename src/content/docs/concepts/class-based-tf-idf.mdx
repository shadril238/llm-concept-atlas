## Definition and intuition

Class-based TF-IDF weights terms after aggregating documents within each class or fitted topic. Its default BERTopic convention combines L1-normalized class term frequency with a corpus-wide term-frequency weight.

A word appearing often in one topic may be informative, while a common word shared by every topic may say little. Class-based weighting makes the unit of aggregation explicit: the class document, formed from documents assigned to that group.

## How it works

### Define every quantity

Let n[c,t] be the count of term t in class c after the chosen tokenization and stop-word policy. Let L[c] be the sum of counts in class c. Default TF is n[c,t]/L[c]. Let f[t] be the total token frequency of that term across all class documents, not the number of classes containing it. BERTopic 0.17.4 uses A = int(mean(L[c])). Default IDF is ln(1 + A/f[t]), and weight[c,t] = TF[c,t] × IDF[t]. BM25-inspired weighting and frequent-word options are different conventions and are disabled here.

### Work the same arithmetic as the library

For vocabulary [translation,model,speech], use counts [[3,1,0],[0,1,3]]. Each class length is four, so A=4. Total term frequencies are [3,2,3]. The model term has IDF ln(3)=1.098612 and class-0 weight (1/4)ln(3)=0.274653. Translation has IDF ln(7/3)=0.847298 and class-0 weight (3/4)ln(7/3)=0.635473. Its larger TF outweighs its smaller IDF. L08 checks this exact table against ClassTfidfTransformer to 1e-12.

### How ordinary TF-IDF differs

Ordinary document TF-IDF often uses a document-frequency factor based on how many documents contain a term, with implementation-specific smoothing. Do not substitute that formula or raw within-group counts and call it the same class-based calculation. The atlas states the version and formula because identical names can hide different conventions.

## Worked example

Increase model’s count in both class documents. Its global frequency rises, decreasing its IDF, while each class’s TF also changes. Both factors must be recalculated. The live calculator shows the effect and refuses an empty class or a vocabulary column that never occurs instead of silently dividing by zero.

## Implement it

This small mechanism uses Python’s standard library and illustrative values; it does not claim to run a pretrained model. Run `python3 scripts/run-examples.py --id discovery-class-based-tf-idf`. The connected workflow below supplies the actual model, data, and evaluation.

{/* example:discovery-class-based-tf-idf:start */}

```python
from math import log

counts = [[3, 1, 0], [0, 1, 3]]
lengths = [sum(row) for row in counts]
average = int(sum(lengths) / len(lengths))
f = [sum(row[j] for row in counts) for j in range(3)]
idf = [log(1 + average / value) for value in f]
weights = [
    [count / length * factor for count, factor in zip(row, idf)]
    for row, length in zip(counts, lengths)
]
print("A:", average, "f:", f)
print([[round(v, 6) for v in row] for row in weights])
```

## When to use it

Use c-TF-IDF to describe groups with distinctive terms after assignments have been fitted or otherwise explicitly defined. In L08, the labels come from actual HDBSCAN; this fixed two-class table is only the introductory arithmetic exercise.

## Limits and common mistakes

Weights are not probabilities of topics or factual support scores. Aggregation can hide minority themes, stop-word choices change vocabulary, and including a noise class affects global counts. A correct formula does not make poor assignments useful.

## Check your understanding

<details><summary>Does f[t] count the number of topics containing a word here?</summary><p>No. It is the total token count of the word across class documents under this pinned default convention.</p></details>

<details><summary>Why is A integer-valued in the worked calculation?</summary><p>BERTopic 0.17.4 casts the mean class token count to int. The hand calculation follows that implementation, including its truncation, rather than silently using a different formula.</p></details>
