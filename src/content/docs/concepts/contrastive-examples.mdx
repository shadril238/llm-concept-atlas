## Definition and intuition

Contrastive examples specify a relationship between an anchor and other inputs. Positive pairs express the intended match; negatives express a meaningful nonmatch. Their construction determines what the representation is rewarded for learning.

Follow the input, objective, update, and evaluation as separate steps. The worked example and experiment below connect the explanation to an inspectable implementation.

## How it works

### Explicit and in-batch negatives

An explicit negative is included as a known nonmatch. An in-batch negative comes from another example’s candidate. A hard negative is plausible under the current representation but wrong for the task, such as a room cancellation retrieved for a new room booking. Hardness is model-dependent; it is not the same as incorrect labeling.

### False negatives are supervision errors

Two requests can both be valid matches even if their sentence IDs differ. Exact duplicate removal is useful but cannot establish semantic uniqueness. L15 forms a positive batch with one pair per distinct intent, checks unique texts and uses the author relation labels to avoid latent positives becoming in-batch negatives. A production collection may need multiple-positive objectives or more careful sampling.

### Construct after splitting

Split source groups before creating pairs. Otherwise one sentence may appear in many train pairs and again in a test pair. The fixture has disjoint exact sentences and IDs across train, validation, test and silver pool. Intent categories recur by design, so this is transfer to new phrasings within the same services, not transfer to entirely unseen classes.

## Worked example

A batch has “reserve a room”→“book a meeting space” and “cancel a room”→“remove my booking.” These provide a useful near miss. Replacing the second candidate with another reservation paraphrase makes the first anchor compete with a second valid answer. The numerical loss can still decrease while the semantic target is damaged.

{/* example:e7-contrastive-examples:start */}

```python
import sys, json
from pathlib import Path
sys.path.insert(0, 'examples/foundations/src')
from atlas_foundations.e7.contracts import check_splits, check_mnr_batch
data = json.loads(Path('examples/data/fixtures/embedding-training.json').read_text())
check_splits(data)
by_id = {r['id']: r for r in data['rows']}
positives = [p for p in data['gold_pairs'] if p['split'] == 'train' and p['label'] == 1]
batch = [next(p for p in positives if by_id[p['left_id']]['intent'] == intent)
         for intent in sorted({r['intent'] for r in data['rows']})]
print('valid MNR batch:', check_mnr_batch(batch, by_id))
try:
    check_mnr_batch([batch[0], batch[0]], by_id)
except ValueError as error:
    print('rejected:', error)
```

## When to use it

Use relationship examples to train retrieval and similarity systems. Review difficult negatives with the same annotation policy used for your search product.

## Limits and common mistakes

Pair counts overstate independent information when many pairs reuse the same labels/sentences. Do not mine negatives using test queries, or let a teacher label held-out evaluation text and then call that pool training-only.

Author execution checks tensor/mask contracts, actual parameter updates, split provenance and artifact reload. It does not constitute independent lesson acceptance. Keep training quality, task quality, runtime and generalization claims separate.
