## Definition and intuition

A quantized model stores or computes some tensors at reduced numerical precision. GGUF is a model container format; the filename, tensor types, runtime configuration, and measured task behavior together describe what actually runs.

Downloading a file called GGUF does not tell you that it is eight-bit. Containers can hold different tensor encodings. Loading a small model successfully also says little about whether it can perform a specific task.

## How it works

### Artifact identity

E5 pins a public SmolLM2-135M-Instruct Q8_0 GGUF by repository revision, filename, SHA-256, and byte count. Runtime metadata reports general.file_type 7, the mostly-Q8_0 type, and the llama architecture. The source checks that type and verifies the chat renderer against the embedded template. The quantizer repository is distinguished from the original model author.

### Storage and runtime are different

Quantization primarily reduces selected weight representation sizes; metadata and other tensors can have different types. Context/KV memory and temporary compute buffers still consume memory. The lab explicitly sets a 768-token runtime context despite a larger training context, batch 256, one CPU thread, zero GPU layers, and CPU KV/operator settings. These controls are inspectable rather than inferred from the file extension.

### Modernizing the book workflow

The book-era chapter code includes a filename whose FP16 encoding does not establish the prose eight-bit claim. This adaptation uses an actually checked Q8 artifact. It uses a pinned compiled llama-cpp-python runtime, not remote custom model code. On the author’s macOS build Metal initializes even with CPU computation; CPU KV/compute buffers were checked. Managed sandboxes that deny Metal initialization need a host run, not a claim that the model is broken.

## Worked example

The pinned file is 144,811,360 bytes. That is artifact storage, not peak resident memory or total inference memory. The small local model still fails elementary arithmetic and extraction cases. Reduced storage makes the experiment accessible; the published failures prevent storage efficiency from being mistaken for adequate task quality.

## When to use it

Use quantization when storage, memory bandwidth, or deployment constraints matter. Compare representative task quality, latency, and memory on the intended hardware with explicit artifact and runtime identities.

## Limits and common mistakes

This lab does not compare precisions of the same checkpoint or attribute its recorded process-memory measurement specifically to quantization. It therefore makes no quality-loss, memory-reduction, or speedup claim for Q8 relative to FP16. Timing is local execution evidence, not a hardware leaderboard.
