## Definition and intuition

BLIP-2 connects a pretrained vision encoder to a pretrained language model through learned query representations and a projection layer. Its bridge is trained to turn image features into useful conditioning for language generation.

Read this lesson as a sequence: identify the input, follow the transformation, inspect the result, and explain a failure. The worked example and recorded lab below make those boundaries visible.

## How it works

### Frozen components and learned bridge

The original training method keeps the large image encoder and language model frozen while learning the Q-Former, query embeddings, and—in the generation stage—the projection into the language model’s embedding width. Calling the bridge the only trained component should not hide the learned projection. The vision encoder is not retrained merely because its features are used by the bridge.

### Two stages have different goals

Stage one learns useful image/text representations with image-text contrastive, image-text matching, and image-grounded text-generation objectives. Their attention masks serve different information-flow requirements. Stage two connects the learned queries to the frozen language generator and trains generation conditioning. A matching embedding dimension is an interface requirement; the training objectives create the useful relationship.

### Actual inference trace

The separate genuine Salesforce BLIP-2 lab records real vision tokens, query states, projected query shapes, processor IDs, and generated caption/VQA text. It uses an explicitly measured heavy Linux CPU profile, distinct from the small local OpenCLIP/chat labs. The smaller chat model is not reported as BLIP-2, and no successful CUDA, four-bit, or failed disk-offload configuration is claimed.

## Worked example

Follow one actual image through the vision output and the configured learned-query count, then through the projection to the OPT language embedding width. The generated caption is a continuation conditioned on those visual features. It may still introduce a detail absent from the photograph or stop at its output cap; a correct shape is an execution check, not semantic validation.

## When to use it

Use this architecture to understand how pretrained vision and language components can be connected without training both large backbones from scratch. The runnable inference illustrates the bridge; a full training replication requires its own data, losses, and hardware evidence.

## Limits and common mistakes

The genuine checkpoint is large, and the verified heavy profile has explicit platform/memory requirements. The project performs no BLIP-2 training and does not claim a tiny substitute reproduces its behavior. Generated captions and VQA answers need visual support checks.
