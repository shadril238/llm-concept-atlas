## Definition and intuition

A representation model encodes an input into numeric features intended for another task, such as comparison, classification, or clustering. Its output representation and training objective determine which comparisons are meaningful.

You want to find support messages similar in intent even when they use different words. A representation can make that comparison efficient, but only if the space was trained or validated for your notion of similarity.

## How it works

An encoder reads token IDs and produces a vector at each position. A pooling rule or task head may turn these into one vector per sentence or one label distribution. The shapes differ: [batch, tokens, hidden] is not the same output contract as [batch, embedding_width].

Static word vectors give a word one context-independent row. Contextual token states depend on surrounding input. A sentence embedding pools or otherwise aggregates information and is often trained with sentence-level pairs. Averaging arbitrary token states is a computation, not proof of strong semantic retrieval.

Cosine similarity compares directions after accounting for vector norms. A score is relative to a representation space and task; it is not automatically a calibrated probability of relevance. Compare candidates encoded with compatible model revisions and preprocessing.

### The important distinction

Embedding spaces from different models cannot generally be mixed coordinate by coordinate.

### Word, sentence, document, and image spaces

Word and token representations describe smaller units; sentence/document representations require an aggregation and task objective. An image encoder can also output a vector. Those coordinate spaces are not interchangeable merely because each output is called an embedding. Cross-modal retrieval requires a deliberately aligned image/text space and evaluation; a text-only encoder does not acquire image understanding by accepting an array of the same length.

```python
from math import sqrt

a, b = [1.0, 2.0], [2.0, 4.0]
cosine = sum(x * y for x, y in zip(a, b)) / sqrt(
    sum(x * x for x in a) * sum(x * x for x in b)
)
print("same direction:", round(cosine, 3))
```

## When to use it

Use representations for efficient repeated comparisons or as inputs to a simple supervised head. Keep a lexical baseline for exact names and codes. Evaluate positives that use different wording and negatives that share many words but mean something different.

## Limits and common mistakes

Embedding spaces from different models cannot generally be mixed coordinate by coordinate. A two-dimensional projection can distort distances. Domain change, truncation, and pooling choices can change rankings even when vector dimensions stay the same.
