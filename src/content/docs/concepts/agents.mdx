## Definition and intuition

An agent workflow uses a controller to choose actions, execute permitted tools, observe results, and decide whether to continue or finish. Its capabilities and limits come from the actual action space, validation, and stopping rules.

A tool name in a generated paragraph does not mean a tool ran. The trace must show the selected action, validated arguments, executed function, returned observation, and next decision. L11 keeps all five visible.

## How it works

### A deliberately bounded action space

The actual local model selects a finite action ID using native JSON-string grammar. IDs resolve to allowlisted calculator operations or local fixture lookups. Calculator operands come from predeclared task operands, and lookup keys come from a small fixture. After a tool observation, the model can select a final value from a common predeclared domain. The domain is not narrowed to each gold answer.

### Tools and equivalent paths

Plain Python dispatch and actual LangChain StructuredTool objects use the same finite-number, operation, and lookup contracts. Strict argument models reject booleans as numbers, unknown fields, invalid operations, division by zero, and unknown keys. RunnableLambda wraps the bounded loop without claiming a general autonomous framework agent. The model chooses actions, but it does not freely extract arbitrary operands in this lab.

### Termination and test doubles

The controller requires a tool observation before finishing and permits at most three steps. Deterministic scripted and actual FakeListLLM paths test successful completion, invalid-argument recovery, and endless tool selection ending at max_steps. Those are labeled fake-model contract tests. Separate actual GGUF cases record model-choice IDs, resolved calls, observations, and final correctness.

## Worked example

For seven plus eight, the controller exposes legal calculator operations. The model may choose subtraction or repeat a lookup instead of finishing correctly. A valid tool call is not a correct plan. The real tiny-model run gets only two of six plain/framework task cases right; all still respect the declared termination boundary.

## Implement it

Run this small standard-library mechanism with Python 3. It illustrates the stated contract or calculation. The connected L09–L11 source below performs the actual local-model workflow; this short snippet is not a substitute for those model calls.

{/* example:e5-agents:start */}

```python
allowed = {"sum": lambda: 7 + 8, "difference": lambda: 7 - 8}
choice = "sum"
observation = allowed[choice]()
trace = [{"action": choice, "observation": observation}, {"final": str(observation)}]
print(trace)
assert len(trace) <= 3
```

{/* example:e5-agents:end */}

## When to use it

Use a bounded controller when tools can add verifiable information or calculation. Start with a small allowlist, typed arguments, explicit observations, and a hard call budget before expanding the action space.

## Limits and common mistakes

This is a restricted local controller, not an unrestricted browsing, file-writing, or production agent. Native action validity does not establish good choices. Fake-model success tests mechanics and must not be reported as real model competence.
