## Definition and intuition

SetFit is a two-stage few-label classification approach: adapt a sentence encoder with class-derived positive/negative pairs, then fit a classifier on the resulting sentence representations. The classifier stage still uses the original labeled sentences.

Follow the input, objective, update, and evaluation as separate steps. The worked example and experiment below connect the explanation to an inspectable implementation.

## How it works

### Generate relationships from class labels

The actual pinned SetFit ContrastiveDataset sampler constructs same-class and different-class pairs from the selected sixteen reviews. Its sampling can repeat pairs and include self-positive pairs. A declared iteration count controls sampled rows, not a count of independent newly annotated examples. The result records sampled and distinct pair counts.

### Train the real sentence encoder

The lab uses the actual SetFitModel, a pinned pretrained MiniLM sentence encoder, the library sampler, and Sentence Transformers cosine-regression loss. A transparent twenty-four-step AdamW loop keeps training explicitly on CPU and checks the first attention-query gradient and changed weight hash. This avoids the convenience Trainer’s implicit accelerator choice on the author Mac; it is the real two-stage algorithm, not a frozen encoder mislabeled as SetFit.

### Fit and reload the classifier

SetFitModel.fit trains its sklearn logistic head on the adapted normalized embeddings of the original sixteen labeled reviews. The frozen-encoder control uses the same pretrained encoder and labels without the embedding-update stage. Saved SetFit artifacts include the body and local fitted head; reload predictions must match. Only load such serialized heads from trusted artifacts you created.

## Worked example

Changing an embedding model to emphasize sentiment can help a small classifier, but it can also overfit the sampled reviews. Compare all three fixed seeds against the frozen sentence-logistic control. The implementation retains unfavorable runs and exposes per-review errors rather than selecting the best seed for display.

import json
from pathlib import Path
data = json.loads(Path('src/data/training-results.json').read_text())['classification']
for row in data['runs']:
    if row['method'] == 'setfit':
        assert row['initial_sha256'] != row['updated_sha256']
        assert row['first_query_gradient_norm'] > 0
        print('seed:', row['seed'], 'unique labeled reviews:', len(row['train_ids']))

## When to use it

Use it for low-label text classification when a pretrained sentence encoder is suitable and class-derived similarity is meaningful. Evaluate whether pair adaptation improves over a frozen-vector classifier first.

## Limits and common mistakes

Same-class text can differ semantically while still being a valid sentiment positive under this task. That relation may harm a general semantic-search use. Small seed counts, validation annotation costs and architecture differences limit comparisons with BERT.

Author execution checks tensor/mask contracts, actual parameter updates, split provenance and artifact reload. It does not constitute independent lesson acceptance. Keep training quality, task quality, runtime and generalization claims separate.
