## Definition and intuition

Dimensionality reduction maps high-dimensional vectors to fewer dimensions while trying to retain chosen structure.

Chapter 5 explores unlabeled collections. A cluster is a geometric grouping, while a useful topic also needs an interpretable description and inspection by a person.

## Before you start

Read [Document embeddings](/llm-concept-atlas/concepts/document-embeddings/) first. You should be able to explain what information its output carries. Then return here and ask what extra problem **dimensionality reduction** solves. This sequence matters because a plausible output can hide a missing prerequisite or a weak input representation.

## Theory: how it works

1. **Prepare:** Start with embeddings and decide which structure matters
2. **Transform:** Fit a projection or nonlinear reduction on an appropriate dataset
3. **Inspect:** Compare neighborhood or variance preservation before interpreting a plot.

### The important distinction

PCA chooses directions that retain variance under a linear projection, while UMAP focuses on preserving neighborhood structure under a nonlinear map. Neither guarantees that distances in a 2D plot match the original vector space. Use the projection as an exploratory view and validate conclusions on the original embeddings.

## Worked example

A 384-dimensional document vector cannot be drawn directly. A 2D map can show broad groupings, but two points that look close may have been farther apart in the original space. Walk through the three stages above with that input: identify what is prepared, what changes, and which observation would show success. Then change one condition in the example. ## Implement it

**Setup:** Python 3; no packages or API key are needed. Save the following as `example.py` and run `python3 example.py`. It is a small deterministic illustration of the relevant calculation or data flow. It does not download a trained model.

```python
documents = {"A": (0.9, 0.1, 0.3), "B": (0.1, 0.8, 0.4)}
projection = {name: (vector[0], vector[1]) for name, vector in documents.items()}
print(projection)
```

**Expected output:**

```text
{'A': (0.9, 0.1), 'B': (0.1, 0.8)}
```

**What the code shows:** The projection keeps only the first two of three coordinates. This makes a drawable point but discards the third coordinate, showing why a plot can lose distinctions. The [official chapter 5 notebook](https://github.com/HandsOnLLM/Hands-On-Large-Language-Models/tree/main/chapter05) develops the corresponding model-based implementation.

Use it for visualization or as a preprocessing step when a clustering method benefits from lower dimension. Choose it when the input and output in your application match those assumptions. ## Limits and common mistakes

- Every projection loses information; different seeds or parameters can change the visible map.
- **Failure to look for:** A colorful 2D island is declared a real topic without checking its original-space neighbors.

A teaching demo usually holds data and model behavior fixed so one mechanism is visible. Real systems face noisy inputs, changing distributions, and edge cases. Test examples that should fail as well as examples that should succeed, and inspect the intermediate stage that causes the error.
