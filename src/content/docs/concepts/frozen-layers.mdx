## Definition and intuition

Freezing layers prevents selected parameters from receiving optimizer updates while other parameters train. It changes the optimization problem and resource use, but it does not automatically disable dropout or make all intermediate computation unnecessary.

Follow the input, objective, update, and evaluation as separate steps. The worked example and experiment below connect the explanation to an inspectable implementation.

## How it works

### Freeze by meaningful module names

The lab freezes BERT embeddings and encoder layer 0 for partial adaptation, or every BERT parameter for the head-only route. It does not rely on a magic enumeration index that changes with architecture. The optimizer includes only trainable parameters and the result records per-group parameter counts.

### Verify gradients and exact weights

Before training, frozen tensors are hashed. After selected-state loading, their hash must match exactly. First-step gradient norms and changed tensor counts show where learning occurred. A frozen early module can still participate in a forward path needed by later trainable modules; freezing is not the same as deleting it.

### Separate parameter state and module mode

requires_grad=False controls gradient accumulation for a parameter. model.eval() controls behaviors such as dropout. The head-only route explicitly keeps the encoder in evaluation mode during head training, whereas partially frozen training retains the declared model train-mode behavior. Report those choices rather than treating identical weight hashes as identical stochastic outputs.

## Worked example

In the partial route, the embedding table and first encoder layer have zero trainable parameters and zero changed tensors. The upper layer and head should show nonzero gradients and changed weights. Select the same review/seed under full and head-only conditions and inspect their distinct errors; less training work need not imply better or worse quality in every small sample.

```python
import json
from pathlib import Path
data = json.loads(Path('src/data/training-results.json').read_text())['classification']
row = next(r for r in data['runs'] if r['seed'] == 11 and r['method'] == 'bert-partial')
for name, group in row['parameters'].items():
    if group['trainable'] == 0:
        assert group['changed_tensors'] == 0
    print(name, 'trainable:', group['trainable'], 'changed tensors:', group['changed_tensors'])
print('exact frozen-weight check:', row['frozen_verified'])
```

## When to use it

Use freezing to reduce update/optimizer-state work or preserve a representation when labels are scarce. Validate the policy for the actual architecture and task.

## Limits and common mistakes

A frozen but randomly initialized classifier cannot solve the task by wishful thinking. Freezing all parameters leaves no meaningful update. Trainable counts alone do not measure peak memory, since activations and other runtime buffers also matter.

Author execution checks tensor/mask contracts, actual parameter updates, split provenance and artifact reload. It does not constitute independent lesson acceptance. Keep training quality, task quality, runtime and generalization claims separate.
