## Definition and intuition

The Q-Former is BLIP-2’s query-based bridge: a fixed set of learned query vectors attends to visual features and produces a compact image-conditioned representation for language generation. These learned queries are not the user’s written questions.

Read this lesson as a sequence: identify the input, follow the transformation, inspect the result, and explain a failure. The worked example and recorded lab below make those boundaries visible.

## How it works

### Learned queries extract rather than copy patches

The vision encoder can produce many image tokens. A smaller learned-query set interacts with them through cross-attention, while shared transformer components support the training tasks. A query does not have a guaranteed human meaning such as left eye or price. Its index is a learned representation position, not a detected-object ID.

### Representation learning before generation conditioning

Stage-one image-text contrastive learning aligns paired representations; matching distinguishes compatible pairs; image-grounded text generation encourages useful visual information for text. Different attention masks control which information can be seen. In stage two a trainable projection maps query states into the frozen language model’s input width, and the bridge is optimized for the generation objective.

### Inspect the real boundary

The genuine inference trace records query count and hidden widths from the actual model config and forward outputs. The implementation does not draw the OpenCLIP patch grid and relabel it a Q-Former. The small shape/parameter calculation uses those recorded dimensions; it is not a training run or evidence that every query faithfully preserves each image fact.

## Worked example

For the actual configured query count q and query width d, learned query storage contains q×d values. A linear projection from d to language width h uses d×h + h parameters when biased. Compute these counts from the recorded model, then inspect the [batch,q,h] output. Matching h lets the generator consume the prefix, while the learned bridge determines its usefulness.

import json

## When to use it

Use this concept to reason about compact visual conditioning, frozen backbones, and the distinction between feature count and language-input width. Inspect query and projection boundaries when diagnosing a multimodal model that loads successfully but answers poorly.

## Limits and common mistakes

The atlas runs pretrained inference only. It does not train the three stage-one objectives or stage-two bridge and then claim training success. Query count limits representation capacity but is not an interpretable count of objects, facts, or questions answered.

## Check your understanding

<details>
<summary>Are the learned query vectors the tokenized user question?</summary>

No. They are pretrained parameters used to extract image-conditioned information. User text is a separate input.

</details>

<details>
<summary>Why is the projection still needed after Q-Former?</summary>

Its output width and learned representation differ from the language model’s input embedding interface. The projection supplies the required conditioning interface.

</details>
