## Definition and intuition

A key-value cache stores previous attention keys and values during autoregressive inference so later decode steps can reuse them. It avoids rebuilding prior states while retaining attention to the available prefix.

An uncached decoder repeatedly processes the whole growing prefix for every new token. The already computed keys/values are reusable under the same causal model and positions, so rebuilding them wastes work.

## How it works

Prefill processes the prompt and creates per-layer caches. A decode step supplies only the new input token plus the past state; its query attends to previous and current keys/values. Positions and masks must describe the complete retained sequence.

For ordinary dense caches, bytes = 2 × layers × batch × KV_heads × positions × head_width × bytes_per_value. The factor two counts keys and values. GQA/MQA change KV-head count; dtype changes bytes per value. This is tensor storage, not all process memory.

Before comparing speed, compare logits for the same prefix and forced continuation. Greedy paths can diverge if numerical ties choose different tokens, making a timing comparison confound different inputs. Warm up the declared device and state whether prefill is included.

### The important distinction

A cache is not persistent factual memory and does not extend the trained context by itself.

## When to use it

Use caching for supported autoregressive inference when prefix reuse matters. Budget memory using actual cache shapes and precision. Benchmark the real sequence lengths and hardware; do not convert this tiny CPU demonstration into a general throughput claim.

## Limits and common mistakes

A cache is not persistent factual memory and does not extend the trained context by itself. Reusing a cache after changing the prefix or positions can produce wrong results. Training and inference cache requirements differ; follow the library’s supported contract.
