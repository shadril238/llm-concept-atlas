## Definition and intuition

Queries and keys determine attention compatibility scores; values supply the vectors that are mixed into the output. They are separate learned projections with different roles in the same attention computation.

A reader sees three matrices and assumes they are arbitrary names for the same vector. Tracing one small example shows why changing a key can alter weights while changing a value can alter content without changing those weights.

## How it works

For X [T,d_model], Wq and Wk map to head width d_k, while Wv maps to value width d_v. The dot product of a query and key is a scalar. After normalization across keys, the weights multiply value vectors, yielding d_v output coordinates.

In self-attention all three projections start from the same stream. In cross-attention, queries come from the target/decoder stream and keys/values from source/encoder states. Their position counts can therefore differ.

The query/key analogy is a search request and index entry, while the value is retrieved content. The analogy ends at literal semantics: the learned coordinates are not guaranteed to be readable requests, titles, or facts. A projection can encode many task-dependent features.

### The important distinction

Multiplying weights by keys instead of values can silently produce a tensor when dimensions match, while implementing the wrong operation.

## Worked example

Let q=[1,0], keys=[[1,0],[0,1]], and values=[[10,0],[0,4]]. Scores before scaling are [1,0]. With d_k=2, softmax of [0.707,0] gives roughly [0.670,0.330], so the output is approximately [6.698,1.321]. Values have two coordinates even though each compatibility score is scalar.

## Implement it

Run the small mechanism from the repository root with `python3 scripts/run-examples.py --id foundation-query-key-value`. Its values are illustrative; it isolates the stated operation rather than pretending to load a trained model.

{/* example:foundation-query-key-value:start */}

```python
from math import exp, sqrt

query, keys, values = [1.0, 0.0], [[1.0, 0.0], [0.0, 1.0]], [[10.0, 0.0], [0.0, 4.0]]
scores = [sum(a * b for a, b in zip(query, key)) / sqrt(2) for key in keys]
p = [exp(s - max(scores)) for s in scores]
p = [x / sum(p) for x in p]
print([round(sum(p[j] * values[j][d] for j in range(2)), 3) for d in range(2)])
```

## When to use it

Use shape annotations to debug a new attention layer or inspect a model. Check which stream supplies each matrix and whether head reshaping preserves the intended position dimension. The transparent lab exposes the projections before the normalized mixture.

## Limits and common mistakes

Multiplying weights by keys instead of values can silently produce a tensor when dimensions match, while implementing the wrong operation. Forgetting the scale can sharpen distributions. A cache stores prior keys and values, not all past queries for ordinary next-token decoding.

## Check your understanding

<details><summary>If you double every value vector but leave Q and K unchanged, what happens?</summary><p>The weights remain unchanged because the scores depend only on Q and K. The attention output doubles because it is a linear weighted sum of the values, before any later nonlinear processing.</p></details>

<details><summary>Change a key but leave values fixed. Can the output change?</summary><p>Yes. Key/query compatibility can change the weights, which changes the mixture of the same value vectors. This contrasts with changing values while holding scores fixed.</p></details>
