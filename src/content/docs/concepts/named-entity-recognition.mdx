## Definition and intuition

Named-entity recognition (NER) identifies typed spans such as complete person, organization or place names. A token classifier supplies local label predictions, but the task is evaluated on reconstructed whole entities with sentence boundaries preserved.

Follow the input, objective, update, and evaluation as separate steps. The worked example and experiment below connect the explanation to an inspectable implementation.

## How it works

### Define annotations before tokenization

The original fixture labels complete human names as PER, fictional organizations as ORG and places as LOC, excluding titles and punctuation. It uses flat nonoverlapping BIO tags and cannot represent nested entities. Person/organization/place names are disjoint across train, validation and test, but sentence templates overlap, limiting generalization claims. Empty-entity sentences are valid examples.

### Align actual words and subtokens

The pinned fast tokenizer supplies word IDs, pieces and special/padding positions. First-subtoken supervision gives each complete retained word one loss contribution and masks later pieces with −100. An all-subtoken alternative propagates labels and changes repeated B-X to I-X within a split word; it weights heavily split words differently. Truncation that removes words or cuts an entity rejects the training record; an inspection mask is not permission to train shortened gold spans.

### Reuse training and score complete spans

L20 reuses the E2 tiny-BERT training implementation with explicit artifact/model paths rather than copying its loop. It freezes embeddings, trains encoder/head, selects on validation entity F1, reconstructs full-sentence word predictions, and reloads the saved model. Strict metrics compare (sentence ID, type, start, exclusive end). Invalid predicted I-tags start a repaired span under an explicit policy and remain separately labeled violations.

## Worked example

Gold “Cedar Labs” is one ORG span. Predicting only “Cedar” has the right type but wrong boundary, so the whole entity is incorrect. If another person entity is correct, token accuracy can remain high while entity F1 falls. The editable alignment table contrasts real split-name pieces and masks; the saved model’s separate held-out sentences retain actual predictions, not supplied labels.

import sys

from atlas_foundations.ner_contract import entity_scores
gold = [['B-PER', 'I-PER', 'O', 'B-ORG', 'I-ORG', 'O']]
predicted = [['B-PER', 'I-PER', 'O', 'B-ORG', 'O', 'O']]
result = entity_scores(gold, predicted)
print('token accuracy:', round(sum(a == b for a, b in zip(gold[0], predicted[0])) / 6, 4))

assert result['tp'] == 1 and result['f1'] == 0.5

## When to use it

Use NER to extract structured entity spans when annotation conventions and boundaries are well defined. Preserve original offsets and evaluate domain-specific boundary/type errors before deployment.

## Limits and common mistakes

Do not pass each token as a separate one-token sentence to an entity scorer: that destroys multiword spans. Flat BIO cannot express arbitrary overlaps. The tiny controlled fixture’s high score does not establish natural-domain, medical or CoNLL-2003 performance; all-subtoken alignment is inspected but not a second trained model here.

Author execution checks tensor/mask contracts, actual parameter updates, split provenance and artifact reload. It does not constitute independent lesson acceptance. Keep training quality, task quality, runtime and generalization claims separate.
