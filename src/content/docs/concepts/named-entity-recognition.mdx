## Definition and intuition

A support system needs to turn “Ada Lovelace joined Cedar Labs in New York” into structured fields. **Named-entity recognition (NER)** identifies spans of text and assigns an entity type, such as person, organization, or location. It answers both **where is the entity?** and **what kind is it?** Sentence classification answers a different question: it gives a label to a whole input.

A useful mental model is a highlighter with typed colors. It must mark the correct extent of a name, not just notice a familiar word somewhere inside it. The analogy does not explain the model's uncertainty or contextual computation; those come from the encoder and classification head.

## Before you start

Define the annotation policy **before** fitting a model. Here PER includes the complete human name, ORG includes the complete fictional organization name, and LOC includes the complete place name. Titles and punctuation are excluded. Spans are flat and nonoverlapping: this representation cannot simultaneously label an organization and a nested place inside its name.

For this exercise, “Cedar Labs” is one ORG span, and “New York” is one LOC span. In another domain, products, genes, or legal citations may require different types and boundaries. A model trained under one convention can be “wrong” under another convention even when its prediction looks reasonable.

## Theory: how it works

### BIO labels encode boundaries

**B** means beginning, **I** means inside an entity of the same type, and **O** means outside. The seven labels are O plus B/I for PER, ORG, and LOC.

| Word index | Word | Gold label |
| --- | --- | --- |
| 0 | Ada | B-PER |
| 1 | Lovelace | I-PER |
| 2 | joined | O |
| 3 | Cedar | B-ORG |
| 4 | Labs | I-ORG |
| 5 | in | O |
| 6 | New | B-LOC |
| 7 | York | I-LOC |

An I-ORG following O is an invalid continuation under strict BIO annotation. The example's decoder uses an explicit repair rule: an I tag without a matching active entity begins a new entity. Both the browser and Python metrics apply that same policy. Gold annotations should still be valid BIO; repair is a declared prediction-decoding choice, not permission to ignore malformed training data.

### From contextual vectors to labels

A tokenizer creates `input_ids` and an attention mask with shape `[batch, sequence_length]`. The encoder creates contextual states `[batch, sequence_length, hidden_width]`. A token-classification head maps each state to seven logits, producing `[batch, sequence_length, 7]`. A softmax can convert these logits to per-position label probabilities, but the training loss accepts logits directly.

For every supervised position, cross-entropy penalizes the negative logarithm of the correct label's probability. The batch loss averages over positions whose label is **not −100**. Ignoring special tokens, padding, and selected subtokens prevents meaningless positions from contributing to that objective. An attention mask and a loss mask have different purposes: ignoring a label does not remove that token from contextual computation.

### The important distinction

The annotation unit is a **word**, while the input unit is a **subtoken**. You cannot zip a word-label list directly with a longer model-token list. A fast tokenizer's `word_ids()` maps each subtoken back to its original word index; special tokens and padding map to None.

Two valid supervision policies are common. **First subtoken only** gives each word one loss contribution and ignores its continuation pieces. **All subtokens** propagates labels, changing B-X to I-X for later pieces of a split word. It increases the loss contribution of heavily split words. Neither policy can be silently swapped at evaluation time. This run uses first-subtoken supervision and reads the first subtoken's predicted class back into one word label.

### Truncation is an annotation decision

A 48-token budget can retain only part of a long word or entity. This workflow compares each retained word's piece count with its untruncated count and **rejects any truncated record**. A production extension should split long documents at safe entity boundaries and preserve source offsets; silently converting a partial name into a complete gold entity corrupts the task. The present short fixture passes without truncation. Tests deliberately force partial words and dropped words to verify rejection.

## Implement it

### Score a boundary error by hand

The source below preserves sentence boundaries and compares exact `(type, start, exclusive_end)` tuples. Run `python3 scripts/run-examples.py --id ner-span-scoring`.

{/* example:ner-span-scoring:start */}

```python
"""Word-level BIO alignment and strict, sentence-preserving entity scoring."""

LABELS = ["O", "B-PER", "I-PER", "B-ORG", "I-ORG", "B-LOC", "I-LOC"]


def spans(tags):
    """Return (type, start, exclusive_end). Invalid I starts a new span.

    This explicit repair policy is applied to both displayed predictions and
    metrics. Never join spans across sentence boundaries.
    """
    result, active, start = [], None, 0
    for index, tag in enumerate(list(tags) + ["O"]):
        prefix, kind = ("O", None) if tag == "O" else tag.split("-", 1)
        if prefix not in ["O", "B", "I"]:
            raise ValueError("Expected BIO tags")
        continues = prefix == "I" and kind == active
        if active is not None and not continues:
            result.append((active, start, index))
            active = None
        if prefix != "O" and not continues:
            active, start = kind, index
    return result


def entity_scores(gold, predicted):
    if len(gold) != len(predicted) or any(
        len(a) != len(b) for a, b in zip(gold, predicted)
    ):
        raise ValueError("Sentence and word counts must match")
    expected = {(i, *span) for i, tags in enumerate(gold) for span in spans(tags)}
    actual = {(i, *span) for i, tags in enumerate(predicted) for span in spans(tags)}
    tp = len(expected & actual)
    precision = tp / len(actual) if actual else 0.0
    recall = tp / len(expected) if expected else 0.0
    return {
        "tp": tp,
        "predicted": len(actual),
        "gold": len(expected),
        "precision": precision,
        "recall": recall,
        "f1": 2 * precision * recall / (precision + recall)
        if precision + recall
        else 0.0,
    }


def align_first(word_ids, tags, complete_counts, reject_truncated=True):
    """Only a retained complete word's first piece receives loss supervision.

    Reject rows with any truncated word/entity: no partial entity can silently
    become a shorter gold entity. Interactive inspection can show masks without
    training on such a row.
    """
    from collections import Counter

    retained = Counter(index for index in word_ids if index is not None)
    if reject_truncated and retained != complete_counts:
        raise ValueError("Truncated record: chunk at safe entity boundaries first")
    seen, labels = set(), []
    for index in word_ids:
        if index is None or index in seen or retained[index] != complete_counts[index]:
            labels.append(-100)
        else:
            labels.append(LABELS.index(tags[index]))
            seen.add(index)
    return labels


# region demonstration
def main():
    gold = [["B-PER", "O", "B-ORG", "I-ORG", "O"]]
    boundary_error = [["B-PER", "O", "B-ORG", "O", "O"]]
    result = entity_scores(gold, boundary_error)
    print(
        "token accuracy:", sum(a == b for a, b in zip(gold[0], boundary_error[0])) / 5
    )
    print("strict entity F1:", result["f1"])
    assert result["tp"] == 1 and result["gold"] == 2 and result["f1"] == 0.5


if __name__ == "__main__":
    main()
# endregion demonstration
```

In the five-word fixture, one wrong word label gives token accuracy 4/5 = 0.8. There are two gold entities and two predicted entities, but only the person matches exactly. Precision = 1/2, recall = 1/2, and F1 = 0.5. A boundary error creates both an unmatched prediction and a missed gold entity.

If 95 of 100 word labels are O, an all-O tagger can achieve 95% token accuracy while finding zero of the five entity words. Entity-level precision and recall expose this failure. Our metric returns zero when there are no predictions or no gold entities; it also records the counts so an empty set is not mistaken for a strong result.

{/* example:ner-training:start */}

```python
def encode(row):
    complete = tokenizer(row["tokens"], is_split_into_words=True, truncation=False)
    counts = Counter(i for i in complete.word_ids() if i is not None)
    encoded = tokenizer(
        row["tokens"], is_split_into_words=True, truncation=True, max_length=48
    )
    encoded["labels"] = align_first(encoded.word_ids(), row["tags"], counts)
    assert len(encoded["labels"]) == len(encoded["input_ids"])
    return dict(encoded)
```

There are 26 training, six validation, and eight final test documents. Every person, organization, and place name belongs to one split only. Two entity-free sentences appear in each split. The sentence templates still overlap structurally, so this tests controlled transfer to new names, not robustness across domains. The data manifest records provenance, hash, annotation policy, and split membership.

The run freezes embeddings and trains both transformer layers and the classifier with AdamW, learning rate 0.001, batch size eight, and 90 fixed steps. Validation entity F1 is checked every 30 steps; the first best checkpoint is kept. Only that checkpoint is evaluated on the final test set. The all-O baseline uses the same test documents. These settings are a small CPU demonstration, not recommended hyperparameters for a realistic corpus.

The workflow verifies unchanged frozen embeddings, finite loss, actual model predictions, sentence/word lengths, and checkpoint reload. It saves the tokenizer beside the model. Predictions are decoded into word spans per sentence; an entity never extends into the next document. Reopening the saved checkpoint reproduces the same decoded outputs.

## When to use it

NER supports document indexing, entity-centered search, structured extraction, and candidate redaction. For sensitive redaction, missed entities matter and require broader validation and human procedures. A simple dictionary may be an effective baseline for a fixed catalog; a learned tagger helps when context and previously unseen names matter. A flat tagger is a poor fit for nested or overlapping span requirements unless the representation is changed.

## Limits and common mistakes

Do not label every subpiece B-PER: that creates several beginnings inside one name. Do not score each word as its own sentence: multiword boundaries disappear. Do not include padding in accuracy or assume a high token score means strong extraction. An uncased tokenizer removes capitalization information that can be useful for entity decisions. The small fixture, narrow templates, and repaired BIO predictions limit what this experiment establishes.
