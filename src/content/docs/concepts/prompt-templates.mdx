## Definition and intuition

A prompt template turns named application inputs into a concrete model input. It provides repeatable assembly, while role serialization, input validation, and model output verification remain explicit responsibilities.

A reusable template makes a change reviewable. It also makes a mistake reusable. Inspect the final messages and serialized prompt rather than assuming a framework name guarantees the right input.

## How it works

### Current template API

L11 uses langchain_core.prompts.ChatPromptTemplate and a RunnableLambda adapter around the local GGUF runtime. Templates produce typed messages. The adapter maps their roles into the same explicit ChatML renderer used by the plain-Python path. No hosted provider, hidden API key, or unpinned convenience model is involved.

### Equivalence before abstraction

The workflow renders the same question with a plain message list and the framework template. It asserts equality of the rendered prompt and greedy generated output. This checks adapter behavior for this input; it does not claim every possible framework transformation is equivalent. The runtime also checks the renderer against the actual GGUF Jinja template.

### Contracts at the boundary

Named variables make required inputs visible, but content inside those variables is still task data. Literal role delimiters are rejected in this controlled renderer. Broader untrusted-input handling needs an application-specific policy. After generation, the output still passes the same parser and reference checks; template correctness alone cannot validate the answer.

## Worked example

A template with a system format instruction and user question should produce the same role sequence as its plain-Python equivalent. If an adapter accidentally maps an AI message to user, the visible words may match while the serialized model input differs. L11 displays both forms and checks the complete serialization.

## Implement it

Run this small standard-library mechanism with Python 3. It illustrates the stated contract or calculation. The connected L09–L11 source below performs the actual local-model workflow; this short snippet is not a substitute for those model calls.

{/* example:e5-prompt-templates:start */}

```python
template = "Task: {question}\nReturn one integer."
question = "7 + 8"
rendered = template.format(question=question)
plain = "Task: " + question + "\nReturn one integer."
assert rendered == plain
print(rendered)
```

{/* example:e5-prompt-templates:end */}

```text

```

## When to use it

Use templates when prompts repeat across inputs or need explicit versioning. Keep the variable contract small and test the actual renderer before adding more orchestration.

## Limits and common mistakes

Templates do not fine-tune models, isolate arbitrary malicious content, or guarantee factual output. The snippet demonstrates string assembly; L11 executes typed framework messages and the actual local model.

## Check your understanding

<details>
<summary>What does prompt equivalence check?</summary>

That the concrete serialized input is identical for the declared case. It does not establish semantic correctness of the resulting answer.

</details>

<details>
<summary>Can variable names create model roles?</summary>

No. Roles are typed application messages and serialized delimiters, not labels embedded in arbitrary text.

</details>
