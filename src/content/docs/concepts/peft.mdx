## Definition and intuition

Parameter-efficient fine-tuning (PEFT) adapts a pretrained model by optimizing a limited set of parameters, often newly added modules, while preserving most backbone weights. It is a family of update strategies, not a single loss function or a guarantee of low total memory.

## Theory: how it works

### Adapter modules and task switching

A bottleneck adapter inserts a small down-projection, nonlinearity and up-projection into a network. LoRA instead adds a low-rank linear weight update. Soft prompt tuning learns input embeddings; selective layer freezing trains existing subsets. They differ in expressiveness, inference cost and where gradients flow. Keep these mechanisms separate even when a library exposes them through one interface.

A frozen parameter has no optimizer update. Its forward computation can still be needed, and intermediate activations can still be retained for backpropagation into adapters. Removing backbone gradients and Adam moments therefore does not remove backbone storage or activation memory. The browser memory view separates idealized weights, adapter storage, gradients, moments and a user-supplied activation estimate. Measured process peak is a separate execution-record field.

Each adapter depends on a specific base architecture, checkpoint revision, module names, rank/scaling and tokenizer/template contract. Sharing a base across multiple adapters can save disk space, but loading the wrong base changes the function. An adapter is not an independent miniature model that can recover missing backbone knowledge by itself. Some selective methods save changed embedding/head modules too; a “small adapter file” is not universally just two matrices.

### The important distinction

Parameter efficiency and sample efficiency are different. Learning twelve thousand parameters from thirty-two examples still permits overfitting; creating many epochs does not create new labels. A small trainable percentage also does not establish an equal quality comparison when different models, steps, token budgets or target modules are used. L21 holds the base and data fixed, but uses explicit method-specific learning rates and step budgets, so the comparison is an educational configuration comparison rather than an isolated causal ranking of methods.

## Worked example

The actual fused QKV LoRA configuration has six layers, input width 128, output width 384, rank 4 and alpha 8. Each layer adds `4×128 + 384×4 = 2,048` parameters, totaling 12,288. The original model has 14,067,712 parameters. The trainable fraction is about 0.087%; the entire base still participates in every forward pass.

At float32, one trainable parameter commonly adds four bytes of gradient plus eight bytes for Adam's two moments, besides its own storage. Base-weight storage remains tens of megabytes in this tiny example. A larger activation footprint can dominate the adapter state; sequence length, batch size and checkpointing matter independently.

## Implement it

This standalone Python 3 calculation uses only the standard library. It does not download or train a model. The [complete generation labs](/llm-concept-atlas/labs/generation-adaptation/) provide the pinned environments, actual training entrypoints, staged notebooks, raw results and artifact checks.

```python
layers, d_in, d_out, rank = 6, 128, 384, 4
base_parameters = 14_067_712
trainable = layers * rank * (d_in + d_out)
print("trainable:", trainable)
print("fraction:", round(trainable / (base_parameters + trainable), 6))
print("adapter gradients + Adam bytes:", trainable * (4 + 8))
print("Frozen backbone and activations still occupy memory.")
```

## When to use it

PEFT is useful when serving several domain/style variants on a shared pretrained model, comparing adaptations with limited optimizer memory, or distributing compact task updates. Prefer a fully frozen baseline when adapting does not improve the task. Validate adapter switching and deployment identity before treating shared storage as operational simplicity.

## Limits and common mistakes

The evaluated instruction subset has 32 training,8 validation and 8 test source contexts. Pretraining overlap is unknown. Repeated views of these test outputs are not a new independent benchmark. Preserve failed and length-limited answers, exact base/tokenizer identity and data provenance when transferring the workflow. The book's larger TinyLlama/CUDA settings require their own supported hardware execution; the small profiles do not certify them.

## Check your understanding

<details>
<summary>A frozen backbone has zero optimizer moments. Is its training memory zero?</summary>

No. The weights, forward computations, activations and temporary buffers still exist. Only specified parameter-gradient/optimizer storage is removed.

</details>

<details>
<summary>Can a task adapter be attached to any checkpoint with the same hidden width?</summary>

No. Exact base revision, module layout, tokenizer, serialization and saved configuration are part of the learned function. Matching width alone is insufficient.

</details>
