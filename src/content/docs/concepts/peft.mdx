## Definition and intuition

**PEFT**: Parameter-efficient fine-tuning adapts a pretrained model by training a small subset of parameters or added modules.

Chapter 12 distinguishes pretraining, instruction tuning, and preference optimization. Efficient adapters change a subset of parameters; evaluation still decides whether behavior improved.

## Before you start

Read [Pretraining and SFT](/llm-concept-atlas/concepts/pretraining-and-sft/) first. You should be able to explain what information its output carries. Then return here and ask what extra problem **PEFT** solves. This sequence matters because a plausible output can hide a missing prerequisite or a weak input representation.

## Theory: how it works

1. **Prepare:** Choose a frozen backbone and a compact trainable adaptation
2. **Transform:** Train the adapter on task examples
3. **Inspect:** Compare quality, memory, and portability with a baseline.

### The important distinction

PEFT is a family that includes adapters, LoRA, prompt tuning, and other selective updates. The base checkpoint remains large even when the trainable fraction is small. Report trainable parameter count, total memory during training, and the quality change relative to a frozen baseline.

## Worked example

Instead of changing every weight in a large generator, a team trains adapters for customer-support style. Several adapters may share one base checkpoint. Walk through the three stages above with that input: identify what is prepared, what changes, and which observation would show success. Then change one condition in the example. If the conclusion changes, the method is sensitive to that choice; if it does not, ask whether the example actually tests the mechanism.

## Implement it

**Setup:** Python 3; no packages or API key are needed. Save the following as `example.py` and run `python3 example.py`. It is a small deterministic illustration of the relevant calculation or data flow. It does not download a trained model.

```python
base = [[1.0, 0.0], [0.0, 1.0]]
a = [[0.1], [0.2]]
b = [[0.3, -0.1]]
adapted = [[round(base[i][j] + a[i][0]*b[0][j], 3) for j in range(2)] for i in range(2)]
print(adapted)
```

**Expected output:**

```text
[[1.03, -0.01], [0.06, 0.98]]
```

**What the code shows:** The nested list comprehension adds a rank-one outer product to a frozen 2-by-2 matrix. For wider matrices, the small inner rank is what saves trainable parameters. The [official chapter 12 notebook](https://github.com/HandsOnLLM/Hands-On-Large-Language-Models/tree/main/chapter12) develops the corresponding model-based implementation.

## When to use it

Use it when full fine-tuning is too costly or multiple task variants must be stored. Choose it when the input and output in your application match those assumptions. Compare the simplest useful baseline first, then measure whether the additional complexity improves the metric that matters to readers or users. Record the model, data version, and decision threshold when applicable so results can be reproduced.

## Limits and common mistakes

- Small trainable capacity can limit adaptation and still overfit poor data.
- **Failure to look for:** An adapter fits the training prompts but fails on new phrasing because examples were narrow.

A teaching demo usually holds data and model behavior fixed so one mechanism is visible. Real systems face noisy inputs, changing distributions, and edge cases. Test examples that should fail as well as examples that should succeed, and inspect the intermediate stage that causes the error.
