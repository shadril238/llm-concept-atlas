## Definition and intuition

Embedding evaluation measures whether vector behavior is useful for a declared task on data excluded from fitting and model selection. Correlation, retrieval ranking, classification quality and resource use answer different questions.

Follow the input, objective, update, and evaluation as separate steps. The worked example and experiment below connect the explanation to an inspectable implementation.

## How it works

### Similarity and correlation

Pair MSE measures numeric error against the declared target scale. Pearson correlation measures linear association; Spearman correlation measures rank association with tied values handled explicitly. A monotonic score transformation can preserve ranking without preserving calibration. Correlation is undefined for a constant score or constant target vector, rather than automatically zero or perfect.

### Retrieval and matched evaluators

The retrieval task holds one candidate per service intent and queries it with other unseen test phrasings. MRR averages reciprocal rank, while Recall@1 counts the correct first result. L15 selects regression checkpoints by validation MSE, pair-classifier checkpoints by validation cross entropy, and ranking checkpoints by validation MRR. The final test does not choose among checkpoints or prompts.

### Broader benchmark coverage

MTEB organizes many embedding tasks and datasets; a score depends on benchmark version, task subset, language, data revisions and aggregation. The book’s historical task/language counts are not timeless properties. These labs execute original similarity/retrieval tasks and licensed review classification, not the complete MTEB or STSB benchmark. Runtime and stored artifact size supplement quality but do not measure the same thing.

### STS correlation and MTEB

A report must name its target scale, split, benchmark/task version and selected metric. The executed original binary-relation task is not the human-rated STSB dataset. Complete MTEB/STSB reproduction is not claimed by the E7 execution records. Constant-input correlation remains undefined, and task aggregates should preserve their denominators.

## Worked example

A teacher may rank held-out binary pairs well while giving poorly calibrated probability values for student regression. Conversely, the softmax-trained encoder can obtain a useful pair-classification score but a different cosine retrieval order. Inspect the same held-out query IDs under baseline and adapted encoders instead of choosing the metric that makes one condition look best.

## Implement it

From the repository root, install the foundation environment and run `python3 scripts/run-examples.py --id e7-embedding-evaluation --offline`. The standard-library example below calculates a mechanism or checks the published actual evidence. Recorded-evidence replay is distinct from new optimization: the connected model lab supplies the complete source and fresh-training command.

{/* example:e7-embedding-evaluation:start */}

```python
import json
from pathlib import Path
data = json.loads(Path('src/data/training-results.json').read_text())['embedding']
for row in data['conditions']:
    predictions = row['retrieval']['rows']
    mrr = sum(1 / p['rank'] for p in predictions) / len(predictions)
    assert abs(mrr - row['retrieval']['mrr']) < 1e-12
    print(row['kind'], 'test queries:', len(predictions), 'MRR:', round(mrr, 4))
print('scope: actual recorded task; complete MTEB/STSB not executed')
```

## When to use it

Use task-matched evaluation for choosing retrieval, clustering or classifier representations. Report per-query/per-class failures and resource limits alongside an aggregate.

## Limits and common mistakes

Small repeated templates and only three few-shot selections do not support population-level confidence claims. Our test metrics are a one-time report for fixed protocols; new hyperparameter choices after inspection require fresh evaluation data.

Author execution checks tensor/mask contracts, actual parameter updates, split provenance and artifact reload. It does not constitute independent lesson acceptance. Keep training quality, task quality, runtime and generalization claims separate.
