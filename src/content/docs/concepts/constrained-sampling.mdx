## Definition and intuition

Constrained decoding restricts which tokens may be generated so an output follows a declared grammar. It can improve structural validity while leaving the choice of field values wrong.

A request to “return JSON” is text in a prompt. A decoding grammar is executable runtime control over permitted continuations. The distinction matters when a downstream parser cannot accept free-form text.

## How it works

### Native generation control

The local runtime passes LlamaGrammar.from_json_schema into create_completion. The same instruction-only messages are used in the extraction baseline and native-schema condition. The schema declares item and priority enums, an integer quantity domain one through nine, required fields, and no additional properties. These are general task fields, not the gold answer for each individual case.

### Format is not truth

A grammar can restrict quantity to a valid integer while the model selects the wrong integer. The result must still pass the application validator and be compared with the source order. In the recorded nine-case suite every native-schema response has valid shape, while only two match all reference fields. Those numbers are evidence for this run, not a universal guarantee.

### Finite budgets still matter

The runtime reserves an output cap within the native context and records the finish reason. A one-token probe deliberately stops before a JSON object is complete and fails validation. Grammar construction, supported schema features, termination, and enough output capacity are part of the runtime contract. Post-hoc regex extraction or JSON repair would be a different algorithm and is not used in this native condition.

## Worked example

If the input asks for three pens, a grammar permitting quantities one through nine cannot determine that three is correct. It only rules out values outside the declared domain and invalid syntax. The truncation probe shows another boundary: even an allowed prefix is not necessarily a completed valid object.

allowed = set(range(1, 10))

## When to use it

Use native constraints for bounded interfaces such as labels, extraction objects, or finite action IDs. Keep independent content checks and enough output budget, and verify the actual decoder backend supports the chosen grammar.

## Limits and common mistakes

Constraints do not retrieve facts or correct calculations. JSON-schema support is backend-specific. The browser displays recorded native runs and does not execute a model; changing its validator input is a deterministic contract exercise.

## Check your understanding

<details>
<summary>Is regex cleanup constrained decoding?</summary>

No. Cleanup operates after text generation. Native constraints restrict possible tokens during generation.

</details>

<details>
<summary>Why test an intentionally tiny output cap?</summary>
