## Definition and intuition

Generation evaluation tests whether a model produces useful responses under a declared task, data split, decoding policy and scoring procedure. It combines reference likelihood, reference-based similarity, objective checks and human assessment because none is a universal measure of answer quality.

## Before you start

Read [text generation](/llm-concept-atlas/concepts/generative-model/). Open the [generation training path](/llm-concept-atlas/paths/from-instructions-to-preferences/) if these prerequisites are unfamiliar. Distinguish a token distribution, a trainable parameter, and a task score before tracing this mechanism.

## Theory: how it works

### Generation evaluation metrics

Completion perplexity is exp(total negative completion log likelihood / supervised completion tokens). Prompt and padding targets are excluded in L22, real EOS is included, and the same tokenizer/format is used for the compared policies. Lower perplexity means the reference tokens are less surprising; it does not prove greedy generations are correct. Perplexities across tokenizers or different masking conventions are not directly comparable.

BLEU measures n-gram precision with a brevity penalty; ROUGE-L uses a longest-common-subsequence match, here reported as F1. They are lexical metrics: a paraphrase can have low overlap, and a sentence with one wrong date can have high overlap. BERTScore aligns contextual token embeddings and aggregates precision/recall/F1; it is a semantic-similarity metric, not word overlap and not a factuality oracle. Its encoder, layer, IDF, rescaling and tokenizer settings belong with its score.

L22 actually runs sacrebleu, rouge-score and BERTScore. Its small two-layer pretrained BERT is a demonstration configuration, with no IDF or baseline rescaling, not the usual large BERTScore model. Preserve its full BLEU signature and never compare its semantic numbers with differently configured systems. Exact match uses a declared lowercase word-normalization rule; single-reference mismatch can still be a valid alternative answer.

### Generation benchmarks

A benchmark couples data, tasks and a scoring protocol. Mathematics, commonsense multiple choice, truthfulness and open-ended writing probe different capabilities. Leaderboards aggregate selected evaluations, often with their own prompts and contamination risks. A ranking is conditional on those choices; an eight-case extraction demo is not an MMLU, GSM8K or general instruction benchmark. Do not train or tune on public test prompts merely because their answers are visible.

### Training configuration

Record the base revision, serialization, target modules, LR, optimizer, batch/accumulation, sequence cap, dtype, seeds, evaluation intervals and selection criterion. L21 uses fixed trained-checkpoint validation selection; L23 uses validation pair losses. Hyperparameter tuning on the heldout test would invalidate its role. The compared routes have unequal method-specific budgets; resource and outcome comparisons must say so.

### Instruction training workflow

Freeze source-row/context-disjoint splits, inspect labels and truncation before fitting, train and select with validation only, then generate once under a fixed decoding policy. Preserve every empty, repeated or length-limited output in the denominator. Save and reload the intended deployment artifact. Finally score the same fixed suite and read mistakes by category, rather than reporting only the best metric.

### The important distinction

Read the mechanism and the actual workflow together. A small calculation checks arithmetic; the connected training record checks optimization and artifacts; heldout task results check a separate quality claim.

## Implement it

This standalone Python 3 calculation uses only the standard library. It does not download or train a model. The [complete generation labs](/llm-concept-atlas/labs/generation-adaptation/) provide the pinned environments, actual training entrypoints, staged notebooks, raw results and artifact checks.

```python
from math import exp

negative_log_likelihood, completion_tokens = 12.0, 4
print("completion NLL:", negative_log_likelihood / completion_tokens)
print(
    "completion perplexity:", round(exp(negative_log_likelihood / completion_tokens), 3)
)
reference = "The package arrived on Monday.".lower().split()
wrong = "The package arrived on Tuesday.".lower().split()
print("shared word types:", len(set(reference) & set(wrong)))
print("High lexical overlap does not verify the day.")
```

## When to use it

Use objective checks for extraction formats/known facts, reference metrics for repeatable partial diagnostics, and blinded humans for qualities the reference does not capture. Optional hosted judging remains a documented workflow with an offline importer: no API setup is required. Bind each label to exact output SHA, rubric/judge versions and presentation order; calibrate on adjudicated examples and test AB/BA order sensitivity.

## Limits and common mistakes

The evaluated instruction subset has32 training,8 validation and8 test source contexts. Pretraining overlap is unknown. Repeated views of these test outputs are not a new independent benchmark. Preserve failed and length-limited answers, exact base/tokenizer identity and data provenance when transferring the workflow. The book's larger TinyLlama/CUDA settings require their own supported hardware execution; the small profiles do not certify them.

## Check your understanding

<details>
<summary>Can lower perplexity coexist with worse extraction accuracy?</summary>

Yes. Reference likelihood and the chosen decoding path measure different behavior. A distribution can assign more mass to a reference yet still greedily choose the wrong continuation.

</details>

<details>
<summary>How should absent human ratings be displayed?</summary>

As missing/pending, with their denominator. The importer must not invent scores, silently drop cases or treat automatic mismatch labels as human factuality judgments.

</details>
