## Definition and intuition

A topic representation describes a fixed group with terms, phrases, or a generated name. Refining the representation can change its wording without changing document assignments or model weights.

The same group can be described by speech/recognition/acoustic terms or by the name “Acoustic speech recognition”. That difference concerns the description. It says nothing by itself about whether the documents were grouped well.

## How it works

### Baseline term weights

Default c-TF-IDF ranks candidate terms from aggregated class documents. Its weights express the declared frequency convention. Terms are grounded in the corpus but can include noise, generic words, or redundant variants. Vectorizer preprocessing determines which terms are even available to later refiners.

### KeyBERTInspired representation models

KeyBERTInspired uses c-TF-IDF information to identify representative documents and candidate words, embeds representative content and candidate terms, then reranks by semantic similarity. L08 runs the real BERTopic module with the same pinned embedding backend. Its returned similarity scores have a different meaning from c-TF-IDF weights. Semantic reranking can omit an informative domain abbreviation that the encoder poorly represents.

### Diversity without reassignment

MMR chooses terms that balance topic relevance against redundancy with selected terms. L08 compares diversity 0.2 and 0.8 while keeping assignments fixed. Higher diversity may surface less redundant but less helpful words. The implementation keeps c-TF-IDF weights for selected words; do not interpret the final displayed order as the chronological MMR selection order.

### Generated topic labels

The optional local workflow runs BERTopic TextGeneration with pinned FLAN-T5-small, two representative excerpts capped at 35 whitespace words each, keywords, and a maximum of 24 new tokens. It asserts assignment equality after generation. In this actual run, Summarization broadly describes one group, Filtering is too narrow for a translation group, and the noise-group name invents an unsupported acoustic-language focus. Read full source texts before accepting any generated description.

## Worked example

Topic 1 has representative documents about code-switched translation, constrained translation decoding, and filtering parallel text. A generated name “Filtering” describes only one part of that evidence. The assignment did not change, but the name underrepresents the group. The noise document combines speech recognition, translation, and summaries; its generated name is not accepted as a coherent topic.

## Implement it

This small mechanism uses Python’s standard library and illustrative values; it does not claim to run a pretrained model. Run `python3 scripts/run-examples.py --id discovery-topic-representations`. The connected workflow below supplies the actual model, data, and evaluation.

{/* example:discovery-topic-representations:start */}

```python
assignments_before = [0, 0, 1, -1]
assignments_after = [0, 0, 1, -1]
representatives = [
    "translation of code switched text",
    "constrained translation decoding",
    "parallel corpus filtering",
]
proposed_name = "Filtering"
assert assignments_before == assignments_after
print("unchanged assignments; review name:", proposed_name)
for document in representatives:
    print("evidence:", document)
```

## When to use it

Use representation refinement when initial terms are redundant or hard to read, and preserve the original representation for comparison. Publish the source documents and label-review notes with a collection explorer so users can question a name.

## Limits and common mistakes

This use of “fine-tuning topic representations” does not mean gradient training of the encoder or generator. Generated labels can be fluent, narrow, unsupported, or misleading about mixed/noise groups. A more readable label is not a measured improvement in clustering.
