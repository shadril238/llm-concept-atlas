## Definition and intuition

**RLHF**: Reinforcement learning from human feedback uses preference data, often through a reward model, to guide a policy model.

Chapter 12 distinguishes pretraining, instruction tuning, and preference optimization. Efficient adapters change a subset of parameters; evaluation still decides whether behavior improved.

## Before you start

Read [Reward models](/llm-concept-atlas/concepts/reward-models/) first. You should be able to explain what information its output carries. Then return here and ask what extra problem **RLHF** solves. This sequence matters because a plausible output can hide a missing prerequisite or a weak input representation.

## Theory: how it works

1. **Prepare:** Collect human comparisons under a written rubric
2. **Transform:** Train a preference signal such as a reward model
3. **Inspect:** Optimize the generator while monitoring divergence and human-rated outcomes.

### The important distinction

In a common RLHF pipeline, SFT supplies an initial policy, a reward model learns from comparisons, and policy optimization seeks higher reward while staying near a reference. The reference constraint helps limit drift but does not guarantee alignment. Human evaluation after optimization remains the decisive check.

## Worked example

Reviewers choose response A over B for a safety question. A reward model learns that ranking and the generator is updated toward similar responses, then checked on new questions. Walk through the three stages above with that input: identify what is prepared, what changes, and which observation would show success. Then change one condition in the example. If the conclusion changes, the method is sensitive to that choice; if it does not, ask whether the example actually tests the mechanism.

## Implement it

**Setup:** Python 3; no packages or API key are needed. Save the following as `example.py` and run `python3 example.py`. It is a small deterministic illustration of the relevant calculation or data flow. It does not download a trained model.

```python
from math import log, exp
chosen_logprob, rejected_logprob = -0.4, -1.1
reference_gap = 0.2
beta = 0.5
gap = beta * ((chosen_logprob - rejected_logprob) - reference_gap)
loss = log(1 + exp(-gap))
print(round(loss, 3))
```

**Expected output:**

```text
0.576
```

**What the code shows:** The loss compares the policy preference gap with a reference gap, scales it by beta, and applies a logistic penalty. A lower toy loss does not validate the preference labels. The [official chapter 12 notebook](https://github.com/HandsOnLLM/Hands-On-Large-Language-Models/tree/main/chapter12) develops the corresponding model-based implementation.

## Limits and common mistakes

- Human preferences vary, reward proxies can be exploited, and optimization is costly.
- **Failure to look for:** The policy learns to maximize a scorer's style preference while factual accuracy declines.

A teaching demo usually holds data and model behavior fixed so one mechanism is visible. Real systems face noisy inputs, changing distributions, and edge cases. Test examples that should fail as well as examples that should succeed, and inspect the intermediate stage that causes the error.
