**Deliverable:** a versioned comparison report, an error-analysis notebook, a portable embedding-head artifact, and an inference command that emits a label, score, and review flag.

The concrete task is binary sentiment of a movie-review sentence, with 0 = negative and 1 = positive. This project follows Chapter 4 while using a licensed UCI subset and smaller CPU checkpoints. A sentence can contain mixed opinions; the label policy must say which target and overall judgment are being evaluated. Sentiment does not substitute for a billing/bug/feature-request taxonomy.

## 1. Inspect the inputs

Start with [L07 setup and provenance](/llm-concept-atlas/labs/classification-and-topics/#l07-classification-comparison). The fixture has 200 training, 40 validation, and 80 test UCI movie sentences. It removes canonical exact duplicates and retains IDs. Twelve separately reported original probes stress negation, mixed sentiment, sarcasm, and domain shift. UCI data attribution and its CC BY 4.0 license remain with those rows; repository MIT does not replace that license.

Inspect class counts, text lengths, ambiguous cases, and available source identifiers before fitting. The source lacks reviewer IDs, so exact text deduplication cannot prove reviewer-level separation. Pretrained-model overlap with review sources is unknown. The atlas reports these limits instead of treating a small split as a contamination-free benchmark.

## 2. Fit and compare fairly

```bash
uv sync --locked --project examples/applications/discovery
python3 scripts/run-examples.py --id classification-comparison --allow-network
```

Use `--offline` after the public models are cached. Compare TF-IDF + logistic regression, fixed embeddings + logistic regression, class-average vectors, label-description similarity, a task-specific encoder, NLI zero-shot, and actual FLAN-T5 generation. They use the same test IDs but have different prior training and assumptions.

Fit vocabulary/IDF and local heads on training data only. Select C and the embedding-head review threshold using validation, then report final test results without selecting settings from them. A deliberate wording-sensitivity experiment reports both descriptions rather than silently picking the best test score.

## 3. Turn numbers into an error report

Keep accuracy, macro-F1, each class’s precision/recall/F1/support, invalid-output rate, and the confusion matrix together. Click false-positive and false-negative cells and read the original text. Compare negation, overall versus aspect sentiment, and out-of-domain cases. A high score with a wrong label is especially useful evidence for the limits of a review threshold.

For generative classification, parse exactly the allowed labels. Refusals, timeouts, missing responses, and unfamiliar text must remain visible in evaluation. Do not treat every non-negative output as positive. Report the original challenge probes separately because their sampling and annotation policy differ from the UCI test set.

Create an error log with source ID, gold label, each method’s prediction, raw generated text where applicable, and a short author diagnosis. Distinguish a model error from an ambiguous annotation instead of changing the label just to improve a metric.

## 4. Reload and run inference

The lab writes an embedding-head JSON artifact with exact encoder revision, coefficients, intercept, class IDs, truncation contract, and validation-selected review threshold. It checks reloaded probabilities against the fitted head before using the artifact.

```bash
examples/applications/discovery/.venv/bin/python examples/applications/discovery/src/atlas_discovery/predict.py "The film is not perfect, but I enjoyed it."
```

The original text stays available for inspection. The score describes this head’s output; it does not guarantee correctness or suitability for a new domain. A production version also needs representative fresh evaluation, a measured review process, and a way to detect changing inputs. Editing the model/encoder contract requires a new run and new evidence.

## Transfer questions

<details><summary>What changes for billing versus bug reports?</summary><p>Define those labels and their overlap rules, collect representative labeled examples, choose splits that reflect source/customer independence where possible, and evaluate a matching classifier. Renaming sentiment outputs cannot perform that task.</p></details>

<details><summary>What if a stricter threshold improves accepted accuracy but accepts only ten percent of cases?</summary><p>Report both quantities and the review workload.
