## 1. Choose the task and access route

Read [Language AI](/llm-concept-atlas/concepts/language-ai/), [model access](/llm-concept-atlas/concepts/model-access/), and [generative models](/llm-concept-atlas/concepts/generative-model/). Decide whether your output should be a label, a retrieved document, a vector, or newly generated text. The architecture map distinguishes encoder, decoder, and [encoder-decoder](/llm-concept-atlas/concepts/sequence-to-sequence/) contracts.

**Artifact:** a one-sentence task specification and a local/remote data-path choice. For an account-free CPU exercise, use L01's pinned small decoder. Its repetitive output is an honest learning observation, not a capable-assistant demonstration.

## 2. Inspect actual tokenization

Open the [tokenization reference](/llm-concept-atlas/concepts/tokenization/). Select the same recorded input under BERT and GPT-2; inspect pieces, IDs, special markers, and offsets. The explorer offers fixed real cases, not a text box that pretends to run an arbitrary tokenizer in the browser.

Read [word/subword units](/llm-concept-atlas/concepts/word-and-subword-tokens/) and [vocabulary](/llm-concept-atlas/concepts/vocabulary/). Predict whether the full decoded string must preserve case under BERT uncased.

**Checkpoint:** explain why an ID is an address and why one visible character can occupy several byte-based pieces. If confused, return to the token lesson and compare the full decoded sequence.

## 3. Separate three kinds of vector

Run [L03 representations](/llm-concept-atlas/labs/foundations/#l03-representations), then read [token lookup](/llm-concept-atlas/concepts/token-embedding/), [contextual states](/llm-concept-atlas/concepts/contextualized-embeddings/), and [text embeddings](/llm-concept-atlas/concepts/text-embedding/).

**Artifact:** note the lookup, hidden-state, and pooled-sentence shapes. Compare the same bank ID in loan and river contexts. Explain why its initial row matches but later states differ. Inspect the actual static-word neighbors and the separately labeled PCA view.

**Recovery:** matching coordinate counts do not make different model spaces compatible. Pooling needs a mask and task-appropriate training/evaluation.

## 4. Trace the masked computation

Read [Q/K/V](/llm-concept-atlas/concepts/query-key-value/), [attention](/llm-concept-atlas/concepts/attention/), and the [transformer block](/llm-concept-atlas/concepts/transformer-block/). Run [L05](/llm-concept-atlas/labs/foundations/#l05-transparent-transformer), which uses random weights to expose every stage and checks attention against PyTorch.

**Artifact:** a shape trace from [T,d_model] through heads, masked weights, residual/MLP states, and vocabulary logits. Toggle the browser mask and predict which outputs may change. Then inspect [RoPE rotations](/llm-concept-atlas/concepts/positional-embeddings-and-rope/) and [packing boundaries](/llm-concept-atlas/concepts/sequence-packing/).

**Checkpoint:** future values cannot influence earlier causal outputs; a packed document boundary requires more than an ordinary separator token. Neither a heatmap nor a random forward pass establishes language understanding.

## 5. Generate and compare cache paths

Run [L01 generation](/llm-concept-atlas/labs/foundations/#l01-first-generation), inspect the prompt prefix and newly selected IDs, then read [decoding](/llm-concept-atlas/concepts/decoding/) and [KV cache](/llm-concept-atlas/concepts/kv-cache/). Operate temperature/top-k/top-p controls without confusing them with confidence calibration.

Run [L06](/llm-concept-atlas/labs/foundations/#l06-decoding-and-kv-cache). Compare cached and uncached logits for the same forced tokens before interpreting warmed timings. Note the actual float64 CPU configuration and distinguish cache tensor bytes from total process memory.

**Artifact:** prompt versus continuation IDs, a next-token distribution, and a cache shape/byte calculation. Explain a repeated or truncated output from the real small model.

## 6. Transfer the embedding idea to a new task

Read [Word2vec](/llm-concept-atlas/concepts/word2vec/) and [recommendation embeddings](/llm-concept-atlas/concepts/recommendation-embeddings/). Run [L04](/llm-concept-atlas/labs/foundations/#l04-learned-playlist-recommendations) and inspect one target the model misses. Compare with train-only popularity, excluding observed songs.

**Final task:** explain why song IDs can have learned vectors without representing audio. Propose a cold-start fallback and a leakage-aware split for a larger dataset. Report the denominator of eligible ranking queries and the limits of synthetic themes.

## Test your mental model

<details><summary>A tokenizer splits one word into three pieces. Which shapes change?</summary><p>The token sequence gains positions, so lookup and later state tensors gain positions. Embedding width and vocabulary size do not change merely because this input used more pieces.</p></details>

<details><summary>The model's last state has width 128. Is that already a vocabulary distribution?</summary><p>No. The LM head maps it to one logit per vocabulary item; softmax and decoding are later operations. A classifier or embedding model may use a different head.</p></details>

<details><summary>Cache timings look faster, but logits differ substantially. What is the conclusion?</summary><p>Correctness is unresolved. Inspect masks, positions, cache reuse, dtype, and model state before calling it a valid optimization. Compare the same forced continuation and record tolerances.</p></details>

<details><summary>A recommendation target is an input song. Can it count as a successful unseen-item prediction?</summary><p>No. Repair the target/query construction. Success must follow the declared candidate and held-out interaction contract.</p></details>
