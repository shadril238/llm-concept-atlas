# E3 foundation workflows (L01–L06)

Run from the repository root in the existing locked CPU reference environment:

```bash
uv sync --locked --project examples/training/reference
python3 scripts/run-examples.py --id first-generation --allow-network
python3 scripts/run-examples.py --id tokenizer-comparison --offline
python3 scripts/run-examples.py --id representation-inspection --allow-network
python3 scripts/run-examples.py --id playlist-embeddings
python3 scripts/run-examples.py --id transparent-transformer
python3 scripts/run-examples.py --id cache-equivalence --offline
```

The registry pins model revisions, source/lock/fixture hashes, timeouts, output invariants, and result artifacts. `--record` refreshes actual run evidence; `npm run examples:sync` updates source regions and the published data snapshot. Default site CI runs only standard-library mechanisms. Model and Torch workflows are explicit or opt-in. Records identify the actual CPU/platform; neither GPU nor API configuration is implied.

## L01: real generation and inspection

`atlas_reference/e3/generation.py` uses the pinned pretrained Pythia-14m and its matching tokenizer. It verifies the prompt prefix, records newly generated IDs separately, exposes embedding/final-state/logit shapes, and checks the actual LM head. The fixed prompt produces repetitive text; that observed weakness is retained in the lesson. This is a base model, not an instruction-tuned assistant. No API key is needed.

## L02: reuse the E2 tokenizer comparison

The existing BERT/GPT-2 package remains the canonical eight-case tokenizer exercise. E3's representation package additionally records a numerical/whitespace input. Do not swap tokenizers merely because vocabulary widths look compatible. Model input limits, special markers, and normalization are part of the contract.

## L03: three representation contracts

`atlas_reference/e3/representations.py` loads:

- GloVe wiki/Gigaword-50: 400,000 pretrained 50D word rows, released through the official [Gensim data repository](https://github.com/piskvorky/gensim-data/tree/bd93f51f7536dbf84f194cd8a81c0644b7b95b41). The 69,182,535-byte compressed artifact is SHA-256 `5c55f98957aa9fed8d2ac5fb1dcff57af3b23c5a3ee7af3f7945f8d49198eb24`; metadata lists PDDL. See [GloVe](https://nlp.stanford.edu/projects/glove/) and its [paper](https://nlp.stanford.edu/pubs/glove.pdf). The repository MIT license does not replace model/data licenses.
- The pinned tiny BERT encoder plus compatible BERT vocabulary: initial bank lookup equality and final contextual-state difference.
- The pinned MiniLM sentence model: explicit mask-aware mean pooling, L2 normalization, and a three-sentence cosine matrix.

The compressed GloVe file is cached under `.cache/e3/` and never committed. Its checksum is verified on every run. Offline execution fails if it is missing; use explicit `--allow-network` for the first download. Do not execute remote reader code. PCA uses only eight selected normalized rows and reports retained variance; nearest neighbors use original 50D cosine, excluding the query itself. The plot is not the original geometry, and neighbors can be related without being synonyms.

## L04: learned playlist vectors

`atlas_reference/e3/playlists.py` fits input/context tables on the original fictional fixture. Radius-two center/context pairs and four sampled negatives per pair feed a softplus negative-sampling objective. Adam updates both tables for 180 fixed steps. There are 48/9/12 sessions and 21 warm catalog items plus one cold-start item. Unordered song sets are unique across all sessions. Pair fitting and popularity counts use training sessions only; validation/test hide each session's last item and exclude observed items from candidates.

Report Recall@3 and MRR, not merely a nearest neighbor. Synthetic themes are deliberately easy and not real listening behavior. The default has no cold held-out targets; a larger imported dataset can have ineligible cold queries, whose exclusion/denominator must be reported. The cold catalog row is allocated but not meaningful and is excluded from learned ranking. Saved vectors reload exactly.

### Optional larger Last.fm route

The author's [Last.fm dataset record](https://zenodo.org/records/6090214) provides a roughly 673 MB 1K archive (MD5 `a79a6808f54f73354789a9fb02cb1e41`) and makes its non-commercial-use/attribution conditions explicit. Download and inspect its terms yourself; the atlas does not redistribute listening events or profiles. This option is not a verified full-scale training result.

```bash
python3 examples/training/reference/import_lastfm.py /path/to/userid-timestamp-artid-artname-traid-traname.tsv examples/artifacts/lastfm-sessions.json --max-events 200000
examples/training/reference/.venv/bin/python examples/training/reference/src/atlas_reference/e3/playlists.py --data examples/artifacts/lastfm-sessions.json
```

The importer reads the six-column event file, ignores profiles, orders each user's timestamps, creates sessions with a 30-minute gap, deduplicates repeated songs within a session, and uses a stable user-group hash for 80/10/10 splits. Its bounded event sample and warm-query eligibility can change representativeness; report those choices and the source file hash with your own run. An importer smoke test verifies parsing/session boundaries; no large-data performance badge is awarded.

## L05: transparent transformer and architectural distinctions

The NumPy mechanism uses random parameters and states every shape: lookup [3,4], two Q/K/V heads [2,3,2], attention [2,3,3], MLP expansion [3,8], final logits [3,7]. It implements pre-norm, causal masking, value mixing, output projection, residuals, and ReLU feedforward. PyTorch scaled-dot-product attention provides an independent reference for the attention result. Future-value perturbation cannot alter earlier causal outputs.

The ReLU toy is not falsely labeled SwiGLU. The lessons separately explain pre/post normalization, RMSNorm, SiLU/SwiGLU, GQA/MQA, local attention, FlashAttention, rotary Q/K pairs, and packed-document masks. Standard-library tests and matching browser calculations cover norm preservation, relative rotations, and visibility. These mechanisms verify quantities, not learned language quality.

## L06: decoding and cache correctness

The shared standard-library source implements stable softmax, temperature > 0, top-k then top-p, crossing-token retention, renormalization, and seeded sampling. Invalid parameters fail explicitly. Greedy is an argmax operation, not temperature-zero division.

The real cache check uses fixed teacher-forced tokens for both paths. Float32 comparisons initially showed differences amplified through layers; the retained failure led to a clearly declared CPU float64 reference check. Maximum logit difference must be < 1e-9, and actual layer cache shapes/bytes must match the theoretical tensor count. Three warmed timings include prefill. They describe float64 CPU behavior, not production precision or a GPU-kernel benchmark; short sequences can have unfavorable caching overhead.
